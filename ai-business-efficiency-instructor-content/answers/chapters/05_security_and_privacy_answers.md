# 05 セキュリティとプライバシー 講師用成果物例

- 元教材：[05 セキュリティとプライバシー](../../05_security_and_privacy.md)
- 対応演習：紙上で行う入力判断と誤入力対応

## 1. 利用上の注意

- 演習は紙上を基本とし、実在する個人情報、機密情報、認証情報をAIへ入力しません。
- ChatGPTを使う場合は、教材に明記された完全な架空ケースだけを入力します。実データを伏せ字にしたものは演習用の架空データではありません。
- 入力可否は製品名だけで決まりません。組織承認、アカウント、目的、データ分類、契約、設定、保存、最小化、出力管理を確認します。
- 法人向け製品であっても、自社の許可なく入力できるとは限りません。不明な場合は入力を止めます。
- 個人情報の該当性、通知・同意、国外移転、事故通知等は地域・契約・状況で異なります。最新の法令・公式情報・社内規程を確認し、担当部署または専門家へ相談します。
- 企業研修では個人アカウントの登録を求めず、未承認の場合はすべて紙上で実施します。

## 2. 利用環境の準備確認：記入例

| 項目 | 模範例 |
|---|---|
| 基本方法 | 紙のケースカードとワークシートを使用 |
| ChatGPT | 組織の承認済み研修用アカウントがある場合だけ任意使用 |
| AIへ入力できる内容 | 「青空企画」「研修サンプルA」等、一から作った架空情報だけ |
| AIへ入力しない内容 | 実在メール、画面画像、会議音声、名簿、価格、APIキー、未公開文書 |
| 参照する社内資料 | 情報分類表、AI利用ルール、事故連絡先 |
| 未承認時 | AI画面を開かず、講師配布の出力例を使用 |

### 準備確認の発言例

```text
この演習は入力可否をAIに決めさせる演習ではありません。
まず紙上で人が判断し、ChatGPTを使う場合も架空ケースから確認質問を出す用途だけにします。
実在データを見つけたら入力せず、講師または社内窓口へ伝えます。
```

## 3. ガイド付き練習：模範成果物

### 3.1 紙上分類

| ケース | 暫定判断 | 理由 | 次の行動 |
|---|---|---|---|
| 架空会社の公開済み一般説明文 | 条件付きで利用候補 | 公開済みでも、権利、目的、最新性、承認環境を確認する | 必要な部分へ減らし、出典と確認日を記録 |
| 一から作った架空問い合わせ | 利用候補 | 実在者・実案件を元にせず、禁止情報も含まない | 送信せず、研修内だけで使用 |
| 氏名・電話番号・購入履歴を含む実在顧客の苦情 | 入力停止・相談 | 個人情報と顧客情報を含み、目的に対し過剰 | 完全な架空ケースへ置換し、実処理は担当部署へ相談 |
| `DEMO-ONLY-NOT-A-KEY` | 教材内だけで利用候補 | 明確な教材用文字列であり、実システムを認証できない | 本物と誤認しない表示を維持 |

### 3.2 ChatGPTが返す確認質問の例

完全な架空ケースだけを入力した場合の望ましい出力例です。

| 観点 | 確認質問の例 |
|---|---|
| 組織承認 | 利用するアカウントと用途は組織に承認されていますか |
| データ分類 | 入力には個人情報、機密情報、認証情報が含まれていませんか |
| 目的 | 要約の目的に、全文入力が本当に必要ですか |
| 契約・設定 | 学習利用、保存、削除、共有、処理先の条件を確認しましたか |
| 最小化 | 架空データや必要項目だけで目的を達成できますか |
| 出力管理 | 誰が確認し、どこへ保存し、誰へ共有しますか |
| 不明時 | どの担当者へ相談し、確認まで入力を止めますか |

AIが「架空なので必ず安全」と結論づけた場合は、その出力を採用せず、アカウント、設定、共有、目的の確認を追加します。

## 4. 実務演習：模範成果物

### 4.1 入力判断表

| ケース | 暫定判断 | 主な理由 | 安全な代替 | 承認・相談先 |
|---|---|---|---|---|
| 公開済みの一般情報 | 条件付きで利用候補 | 公開済みでも権利、最新性、用途、承認環境が未確認の場合がある | 必要な段落だけ使い、URL・公開日・確認日を残す | 業務責任者、必要に応じ広報・法務 |
| 氏名・電話番号を含む顧客苦情メール | 入力停止・相談 | 個人情報、顧客情報、再識別可能な具体事情を含む | 実在者を元にしない架空ケースへ置換 | 個人情報、情報セキュリティ、業務責任者、必要に応じ法務 |
| 完全に架空のメールテンプレート | 条件付きで利用候補 | 架空でも利用環境、保存、共有の条件は残る | 承認済み環境で必要最小限を使う | 研修責任者 |
| 未公開の価格改定表 | 入力停止・相談 | 未公開機密で、事業・契約へ影響し得る | 架空商品と架空価格へ置換 | 業務責任者、情報セキュリティ、法務・契約担当 |
| 本物の可能性があるAPIキーを含む画面 | 入力停止 | 認証情報は不正利用へ直結し、会話削除では秘密性が戻らない | 画像を使わず、エラーコードと架空画面で再現 | システム管理者、情報セキュリティ、事故窓口 |
| 事前通知していない会議音声 | 入力停止・相談 | 発言者の個人情報・機密、通知・同意、保存・閲覧条件が未確認 | 架空の会議メモを使う | 会議責任者、個人情報、情報セキュリティ、必要に応じ法務・労務 |

「条件付き」は利用者が独断で入力してよい意味ではありません。必要条件を権限のある担当者が確認するまで入力を止めます。

### 4.2 APIキー誤入力時の紙上フロー

| 順序 | 行動 | 主担当例 | 記録すること |
|---:|---|---|---|
| 1 | 追加入力、共有、自動処理を止める | 発見者 | 発見時刻、止めた操作 |
| 2 | 秘密値を増やさず事実を記録する | 発見者 | 利用サービス、アカウント、入力時刻、画像の範囲 |
| 3 | 正式な事故窓口へ報告する | 発見者・上司 | 分かっている事実と未確認事項 |
| 4 | 旧キーを失効し、安全に交換する | 権限を持つシステム管理者 | 対象キー、失効・交換の実施記録 |
| 5 | アクセスログと影響を確認する | 情報セキュリティ・システム管理者 | 不審利用、接続元、操作範囲 |
| 6 | 保存・削除・通知の扱いを判断する | 事故責任者、法務、個人情報担当等 | 契約、社内手順、必要な対応 |
| 7 | 画面、手順、教育を改善する | 業務・システム・研修担当 | 再発防止策と担当 |

状況により報告と失効は並行します。利用者が独断で会話やログを消さず、組織の証跡保全手順に従います。APIキーの完全な値をメールやチャットへ再掲しません。

### 4.3 再発防止の例

| 面 | 改善例 |
|---|---|
| 画面 | 秘密値を通常画面へ表示しない、教材用の架空画面を使う、アップロード前に表示範囲を確認する |
| 手順 | 画像入力前チェック、認証情報を含む画面の入力禁止、事故連絡先、失効・影響確認の手順を明文化する |
| 教育 | 認証情報の見分け方、会話削除の限界、報告経路をロールプレイする |

## 5. 人間レビュー：対話例

| レビュー担当者の問い | 利用者役の修正例 |
|---|---|
| 氏名を消せば安全ですか | 部署、日時、購入内容等から再識別できるため、完全な架空ケースへ置き換える |
| 法人向けAIなら入力できますか | 製品名だけでなく、用途、契約、設定、データ分類、承認を確認する |
| 会話を削除すれば終わりですか | キーを失効・交換し、ログと影響を確認し、正式記録を残す |
| なぜ紙上で行うのですか | 判断練習に実データ送信は不要で、入力事故を起こさず同じ手順を学べるため |
| 法的通知は誰が決めますか | 利用者ではなく、責任者、法務、個人情報担当、必要な専門家が個別事情で判断する |

## 6. 振り返り：記入例

- 迷ったケース：公開済み文章。公開済みでも権利、最新性、用途、承認環境の確認が残る。
- 不足していた情報：利用するプランの保存・学習利用設定と、正式なデータ分類。
- 安全な代替：架空メールで分類方法だけを試し、実メールは入力しない。
- 自組織で確認すること：事故窓口、緊急連絡手段、APIキー失効担当、証跡保全手順。

## 7. 観察ポイントと改善例

| 観察ポイント | 望ましい様子 | 改善例 |
|---|---|---|
| 立ち止まる | 不明時に入力せず相談する | 即断した場合は、不足情報と確認先を書かせる |
| 根拠 | データ、目的、契約・設定、最小化、出力管理を使う | 製品名だけなら判断軸を一つずつ当て直す |
| 代替行動 | 架空化、最小化、紙上処理等を提案する | 全面禁止だけなら目的を安全に達成する別案を考える |
| 誤入力初動 | 停止・記録・報告・失効・影響確認へ進む | 会話削除だけなら、秘密性が回復しない点から再検討する |
| 役割分担 | 利用者、管理者、事故責任者、専門担当を分ける | 利用者一人で判断している場合は権限ごとに割り振る |

## 8. 別解・ツール利用不可時の紙上例

### 許容できる別解

- 公開済み文章を利用候補とする場合でも、承認環境、目的、権利、最新性、出力確認を明示する。
- 未公開価格を将来の条件付き利用とする場合は、明示承認、限定環境、権限、保存、ログを具体化する。
- 会議音声は通知・同意等が整えば再検討できる場合があるが、提示された状況では入力を止める。
- 証跡保全は組織ごとに異なるため、秘密値を増殖させず正式窓口の指示へ従う。

### 紙上例

1. ケースカードを「利用候補」「条件付き」「入力停止・相談」の三つの台紙へ置きます。
2. 裏面へ、理由、不足情報、安全な代替、相談先を書きます。
3. 誤入力カードを、停止、記録、報告、失効、影響確認、再発防止の順へ並べます。
4. 役割カードを割り当て、口頭で引継ぎます。
5. 別の受講者が、秘密値の再掲や独断削除がないか確認します。

## 9. 講師向け補足

分類名を当てることより、「何が不明だから止めるか」「何を確認できれば再判断できるか」「入力しない代替は何か」を説明できるよう支援します。実際の事故対応は自社手順を優先し、法令・契約・本人通知等は担当部署や専門家へつなぎます。
