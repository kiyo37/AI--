# 00 コース概要：講師用解答集

[元教材「00 コース概要：AI業務効率化講師へのロードマップ」へ戻る](../../00_course_overview.md)

## 利用上の注意

- 本書の模範解答は一例です。受講者の経験、対象業種、生活条件、組織ルールに応じた別解を認めます。
- 自己確認では、状態の名称よりも、根拠と次の行動が具体的かを見ます。
- 演習には架空の企業・部署だけを使います。実在する顧客名、個人情報、機密情報は入力させません。
- AIで作成した計画、教材、レビュー案は必ず人が確認します。法務、著作権、個人情報、医療、金融などの判断は、組織の担当者や専門家に確認してください。
- AIツールの機能、料金、契約、データ利用条件は変わります。研修実施時点の最新の公式情報を確認してください。

## 演習：自分の30日計画を作る

### 利用環境の準備確認

- 基本演習でChatGPTを使う場合は、[対話AIアカウント準備ガイド](../../setup/chat_ai_account_setup.md)を確認します。
- 企業研修では個人登録を強制せず、管理者が発行・招待した業務用アカウントを使います。利用できない受講者には紙の計画表と講師作成の架空出力を用意します。
- 個人学習では、本人が利用条件と費用を確認した個人アカウントを使えます。
- どの方法でも、この教材の架空情報以外は入力しません。

### ガイド付き練習

講師の例を見ながら、知識マップの各領域を次のいずれかで自己確認します。

| 状態 | 意味 | 次に行うことの例 |
|---|---|---|
| まだ説明が難しい | 用語を知っていても、自分の言葉で説明できない | 本文と図を使い、定義・例・注意点を書き直す |
| 例があれば説明できる | 見本を参照すれば説明できる | 別の業務例へ置き換えて説明する |
| 演習を進行できる | 説明、問いかけ、人間レビューを案内できる | 第三者の観察を受け、誤解される箇所を直す |

ChatGPTには言い換えや整理の案を出させても構いませんが、自分の理解状態や学習優先度を決めさせません。

### 実務演習

1. 改善したい領域と、講師として扱いたい架空の業種を選びます。
2. 30日表へ、実行日、成果物、利用する教材、相談相手を追記します。
3. 最終成果物を組み替え可能なモジュールへ分け、それぞれの完成条件を記載します。
4. 30日後に模擬講義を依頼する相手と、観察してほしい行動を決めます。

### 模範解答

以下は、架空の受講者「研修企画担当A」が9月1日から学ぶ例です。

#### 1. 知識マップを自己確認する

| 領域 | 現在の状態 | 根拠 | 次の行動 |
|---|---|---|---|
| AI基礎 | 例があれば説明できる | 基本用語は読めるが、比喩だけでは限界を説明できない | 主要用語を「定義・例・注意点」で説明する |
| ツール | まだ説明が難しい | 製品名は知っているが、契約・統制を含めて比較していない | 同じ架空課題を同条件で比較する |
| プロンプト | 演習を進行できる | 目的、制約、出力形式を指定し、元資料との照合を案内できる | 完成条件と改善手順を追加する |
| 業務分析 | 例があれば説明できる | 業務名の列挙で止まり、判断と例外を分けていない | 1業務を1動作ずつ分解する |
| セキュリティ | まだ説明が難しい | 入力禁止情報と停止・相談条件を体系的に説明できない | データ分類と入力可否の演習を行う |
| 正確性 | 例があれば説明できる | 誤りがあることは知っているが、確認手順が曖昧 | 一次情報との照合表を作る |
| 法務・統治 | まだ説明が難しい | 権利、利用規約、責任者の整理が不足している | 架空のAI利用ルール案をレビューする |
| RAG | 例があれば説明できる | 概要は説明できるが、検索漏れや版管理を扱えない | 紙上で検索・引用確認を設計する |
| 自動化・AIエージェント | 例があれば説明できる | 連携例は分かるが、承認と停止条件が不足している | 人間承認付きフローを作る |
| 研修設計 | 演習を進行できる | 研修の流れと演習を作った経験がある | 実務指標と定着支援を追加する |
| 講師実践 | 例があれば説明できる | 説明経験はあるが、質疑やデモ障害への対応が不安 | 1モジュールを模擬実施し、観察結果から改善する |

#### 2. 優先領域と対象業種を選ぶ

| 項目 | 選択 | 理由 |
|---|---|---|
| 優先領域1 | セキュリティ | 誤った入力判断は情報漏えいにつながり、研修効果より大きな損害を生むため |
| 優先領域2 | 法務・統治 | AI生成物の利用条件、責任者、人間レビューの説明が不足しているため |
| 扱いたい業種 | 架空の法人向け教育サービス業 | 教材、問い合わせ、会議、事務など複数の業務例を、安全な架空データで作りやすいため |

#### 3. 30日表へ成果物を割り当てる

学習時間は固定しません。本人が継続できる時間帯を予定表へ登録し、都合が変わった場合は成果物を保ったまま日を調整します。

| 日 | 学習テーマ | 観察できる成果物 | 利用教材・相談相手 |
|---:|---|---|---|
| 1 | 全体像 | 自己確認表、対象業種、利用環境の確認記録 | 00章、学習仲間 |
| 2〜3 | 生成AI基礎 | 主要用語の初心者向け説明、誤解されやすい点のメモ | 01章 |
| 4〜5 | ツール概論 | 同じ架空課題の比較表、公式情報の確認日と参照先 | 02章、情報システム担当者役 |
| 6〜8 | 業務分解 | 問い合わせ業務の作業・判断・例外・責任者一覧 | 04章 |
| 9〜11 | プロンプト | メール、議事録、報告書のプロンプトと元資料照合表 | 03章 |
| 12 | 効果測定 | 時間、品質、重大誤り、確認工数の測定方法 | 04章 |
| 13〜15 | セキュリティ | 入力可否分類表、入力禁止時の安全な代替手順 | 05章、セキュリティ担当者役 |
| 16〜17 | ハルシネーション | 架空の主張と一次情報による検証記録 | 06章 |
| 18〜19 | 著作権・統治 | AI利用ルール案、専門家へ確認する論点一覧 | 07章、法務担当者役 |
| 20〜22 | RAG | 文書一覧、版、権限、検索・引用確認の紙上設計 | 08章 |
| 23〜25 | 自動化・AIエージェント | 承認、停止、ログ、手動代替を含むフロー | 09章 |
| 26 | 研修ニーズ分析 | 対象者、課題、制約、受講前提の一覧 | 10章、研修企画担当者役 |
| 27 | モジュール設計 | 対象者に応じて選べるモジュール一覧と到達目標 | 10章 |
| 28 | 教材・演習 | スライド案、架空データ、演習手順、完成条件 | テンプレート集 |
| 29 | 登壇実践 | 1モジュールの模擬講義記録、観察者のコメント | 同僚または学習仲間 |
| 30 | 改善・提出 | 指摘反映表、最終研修パッケージ、残課題一覧 | レビュー担当者 |

#### 4. 最終成果物をモジュールで設計する

| モジュール | 主な成果物 | 完成条件 |
|---|---|---|
| 導入・AI基礎 | 用語説明、得意・不得意の事例 | 初心者が例を使って説明し直せる |
| 業務分解 | 業務マップ、AIと人の役割表 | 判断、例外、責任者が分かれている |
| 安全利用 | 入力可否ケース、停止・相談手順 | 入力禁止情報と相談先を判断できる |
| 実務ハンズオン | 架空データ、プロンプト、照合表 | AI出力を人が元資料と照合できる |
| 定着支援 | 実務目標、相談先、振り返り方法 | 研修後の利用状況と問題を確認できる |

これらを対象者と目的に応じて組み替えます。特定の研修時間を前提にせず、使うモジュールごとに到達目標と完成条件を決めます。

#### 5. 模擬講義と第三者観察を決める

| 項目 | 模範例 |
|---|---|
| 依頼相手 | 同僚2名に受講者役と観察者役を依頼する |
| 実施範囲 | 「AIへ任せる作業と、人が判断する作業の分け方」モジュール |
| 観察してほしい行動 | 平易な説明、受講者への問いかけ、入力禁止情報の案内、人間レビューの実演、質問へ断定せず答えること |
| 必須確認 | AI出力を人が確認すること、利用を止める条件、担当者・専門家へ相談する条件を説明できたか |
| 改善記録 | 観察した事実、改善案、修正内容、再確認者を残す |

**最終成果物の仮テーマ**：架空の「青葉ラーニング社」管理部門向けに、メール・議事録の効率化と安全な入力判断を扱う研修モジュール一式を作る。

### 完成条件・観察ポイント・改善が必要な状態

| 完成条件 | 観察ポイント | 改善が必要な状態 |
|---|---|---|
| 現在の状態に根拠がある | 経験や成果物を基に説明しているか | 根拠のない自己判断だけになっている |
| 実行日と成果物が具体的である | 第三者が実施と完成を確認できるか | 「勉強する」「理解する」だけで終わっている |
| 優先領域と計画がつながる | 弱い領域へ成果物と相談機会を割り当てているか | 全領域を同じ扱いにしている |
| 成果物がモジュール化されている | 対象者や目的に応じて組み替えられるか | 固定時間の進行表だけで、到達目標が不明である |
| 安全な利用条件がある | アカウント、入力可否、人間確認、停止・相談、代替方法があるか | 未承認環境や実在情報を使う計画なら、利用を止めて修正する |
| 第三者レビューがある | 誰が何を観察し、どう改善するかが明確か | 本人またはAIの確認だけで完了している |

### 人間レビュー

同僚または学習仲間が、次を確認します。

- 本人の予定で実行できるか。
- 各日の成果物が最終モジュールへつながっているか。
- 実在情報を使わず、承認済み環境または紙上代替を選んでいるか。
- AIの提案をそのまま採用せず、本人が優先度、責任、相談先を決めているか。
- 模擬講義で、便利さだけでなく限界、停止条件、人間の責任を説明できるか。

### 振り返り例

> ChatGPTは学習テーマの整理に役立った。一方、勤務予定に合わせた実行日、安全上の優先順位、相談相手は自分とレビュー者が決めた。業務用アカウントを使えない日は、紙上ワークと講師配布の架空出力で続ける。

### 許容できる別解

- 学習開始日、実施頻度、対象業種は異なって構いません。
- 優先領域がRAGや自動化などでも、現在の状態の根拠と計画がつながっていれば認めます。
- 模擬講義の相手は同僚、上司、学習仲間でも構いません。本人だけの自己確認ではなく、第三者の観察を入れてください。
- 連続して学べない場合は、成果物とレビュー機会を保った週末中心の計画も認めます。
- 最終パッケージの構成は対象者に合わせて変更できます。ただし、安全利用と人間レビューのモジュールは省略しません。

### よくある誤り

- 全領域を同じ扱いにし、改善したい領域へ学習を重点配分していない。
- 「理解する」「復習する」だけで、確認できる成果物がない。
- 製品操作の練習だけで、業務分解、安全性、人間レビューを扱っていない。
- 研修を固定の長さだけで設計し、対象者と到達目標に応じて組み替えられない。
- 模擬講義の観察者や、見てほしい行動が決まっていない。
- 実在企業の資料や個人情報を演習へ持ち込む。

### 講師向け解説

この演習の目的は、理想的な計画表を作ることではなく、受講者が自分の弱点を証拠付きで認識し、行動と成果物へ変換することです。状態の呼び方を判定するのではなく、根拠のない過大評価を問い直してください。安全性が弱い受講者には、便利なデモより先に入力可否、人間確認、利用停止と相談の判断を割り当てます。最終成果物は、対象者や研修目的に合わせて組み替えられるモジュールとして扱います。
