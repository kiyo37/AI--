## この演習の目的

架空の問い合わせ30行をAIの候補だけで処理せず、人が全件を分類基準へ照合し、Excelで数値を再計算して、安全な月次報告を完成させます。

## 準備：3つの経路から選ぶ

この演習は一人で完了できます。ペアで相互確認する方法は任意です。次のうち、利用できる経路を一つ選びます。

| 経路 | 準備とルール |
|---|---|
| 個人学習（AIあり） | 公式URL、利用規約、プライバシー設定、料金を最新の公式情報で確認し、教材の架空データだけを使う |
| 組織利用（AIあり） | 組織が承認したAI、業務用アカウント、指定保存先、正式な相談先だけを使う |
| AIなし | [保存済みAI分類案（問題例）](../sample-outputs/inquiry_monthly_ai_output_problem.md)を使い、同じ照合と修正を行う |

## 演習の共通手順

1. **目的と成果物**を確認する。
2. **準備**として、使用経路と収録ファイルを確認する。
3. **手順付き例**だけを、説明を読みながら試す。
4. **自力課題**は、自己点検ガイドを開かずに作る。
5. **人による元資料照合**として、AI出力と元資料を自分で1項目ずつ比べる。
6. 詰まった場合だけ、末尾の**段階ヒント**を一つずつ開く。
7. 自力課題の後に**自己点検**ガイドと比べる。
8. 誤りまたは改善点を**最低1点修正**し、修正理由を残す。
9. **完了条件**と安全な終了を確認し、**次へ**進む。

## 1. 学習ゴールと背景

30行の問い合わせを、AIで一括分類して終わりにせず、重複・空欄・複数論点・優先確認候補を人が全件確認し、Excelで数値を再計算して月次報告を完成させます。

### 学習ゴール

- AIの分類を「候補」として扱い、30行すべてを原文と分類基準へ戻って確認できる
- 主分類と副論点を分け、同じ問い合わせを二重計上しない
- 重複ID、ID空欄、本文空欄を別々に扱える
- `COUNTIF`と`COUNTIFS`を使って、確認済みデータだけを集計できる
- 集計だけでは分からない原因、責任、障害、返金可否を断定せず報告できる
- 外部送信をせず、最終成果物だけを指定場所へ残せる

### 用語補足

| 用語 | この演習での意味 |
|---|---|
| CSV | 項目をコンマで区切った表形式のテキストファイル。Excelへ読み込むと行と列で扱える |
| 主分類 | 1件を集計するときに一度だけ数える中心の分類 |
| 副論点 | 同じ問い合わせに含まれる、主分類以外の話題。主分類の件数へ二重計上しない |
| `COUNTIF`／`COUNTIFS` | 条件に合うセルや行の件数をExcelで数える関数（決められた計算） |
| フィルター | 条件に合う行だけを一時的に表示するExcelの機能。非表示の行が削除されたわけではない |

この演習は採点しません。速さより、件数の一致と、判断できないときに止まることを重視します。

## 2. 実務での使いどころ

| 業務 | AIが補助できること | Excel・通常処理が行うこと | 人が判断すること |
|---|---|---|---|
| 問い合わせ整理 | 主分類、副論点、根拠語句の候補 | 行数、重複候補、分類別件数を再計算 | 最終分類、例外、優先確認 |
| 月次報告 | 読みやすい文章の草案 | 確認済み数値の表と比率 | 数値照合、表現、承認、共有可否 |
| 改善検討 | 観察事項・確認質問の候補 | 月ごとの同じ定義での集計 | 原因調査、施策、責任、費用対効果 |

AIには数えさせても、Excelの確認済み集計と突き合わせます。1か月分の少数データだけで「顧客全体の傾向」や「原因」を断定しません。

| 利用環境 | 選ぶ経路 |

| AIを利用できない、未承認、ログインできない | [保存済みAI分類案（問題例）](../sample-outputs/inquiry_monthly_ai_output_problem.md)＋Excel経路 |

Excelのデスクトップ版・Web版の開き方と、タブ区切りが1列に入った場合の違いは、[クイックスタート「Excelでタスク一覧を作る」](../setup/participant_quickstart.md#8-excelでタスク一覧を作る)を参照してください。画面名が異なる場合は設定を変えず、自分で事前確認した方法へ切り替えます。

### 操作2：教材を開く

次の3ファイルを別々のタブで開きます。

1. [架空問い合わせ明細30行](../sample-data/monthly_inquiry_cases.csv)
2. [月次問い合わせ分類基準](../sample-data/monthly_inquiry_classification_rules.md)
3. [学習用レビューシート](../workbooks/inquiry_monthly_review_sheet.md)

AIを使えない場合だけ、4つ目として[保存済み問題例](../sample-outputs/inquiry_monthly_ai_output_problem.md)を開きます。

### 操作3：開始前チェックを行う

- [ ] 入力するのは上記の完全な架空データだけである
- [ ] 組織が承認した対話AIとExcel、または指定された代替経路を使う
- [ ] ファイル添付、Web検索、外部アプリ連携は使わない
- [ ] 実在情報を追加しない
- [ ] メール送信、顧客返信、チケット更新、共有リンク作成を行わない
- [ ] 最終成果物の保存先が決まっている

一つでも確認できなければ作業を始めず、利用環境の管理者または組織の正式な窓口へ相談します。

### 操作4：CSVをExcelへ読み込む

#### Excelデスクトップ版

1. Excelで「空白のブック」を開きます。
2. 「データ」から「テキストまたはCSVから」を選びます。
3. `monthly_inquiry_cases.csv`を選びます。
4. 文字コードが選べる場合は`UTF-8`、区切り文字は`コンマ`を選びます。
5. プレビューで`連番`から`問い合わせ本文`まで6列に分かれ、日本語が読めることを確認します。
6. 「読み込み」を選びます。

#### Excel Web版

1. 自分で案内した組織のポータルからExcelを開きます。
2. 自分で事前確認した「アップロードして開く」または組織指定のブックへの貼り付けを使います。
3. `連番`から`問い合わせ本文`まで6列に分かれ、30行あることを確認します。
4. CSVがExcelブック形式（`.xlsx`）へ変換されたこと、会社指定の保存先、ファイル名を確認します。変換や保存先を確認できない場合は、収録済みの読み込み済みブックまたはMarkdown経路へ切り替えます。

日本語が文字化けする、全てA列へ入る、列数が違う場合は上書き保存しません。個人用サービスで変換せず、収録済みの読み込み済みブックまたはMarkdown経路へ切り替えます。

### 操作5：作業用ブックを作る

1. CSVのままでは複数シートや数式を保持できないため、自分で決めた保存先（組織利用では指定保存先）へExcelブック形式で保存します。デスクトップ版では「名前を付けて保存」で`Excelブック（.xlsx）`を選び、Web版では変換後の形式・保存先・名前を確認します。
2. ファイル名を最初から`架空問い合わせ月次報告_最終版.xlsx`とし、別の作業中ファイルや初回AI出力ファイルは作りません。
3. 元データのシート名を`明細`へ変更します。
4. `作業用AI候補`、`集計`、`月次報告`の3シートを追加します。
5. `明細`シートで見出しを含め31行、データ部分が30行であることを確認します。

Web版で自動保存される場合は、自分または組織が決めた限定保存先で作業します。版履歴や監査ログを自己判断で削除しません。

この読み込み方は、Microsoft公式の[UTF-8 CSVをExcelで開く方法](https://support.microsoft.com/en-US/Excel/opening-csv-utf-8-files-correctly-in-excel)と[ブラウザー版とデスクトップ版の違い](https://support.microsoft.com/en-US/Excel/differences-between-using-a-workbook-in-the-browser-and-in-excel)を2026年8月9日に確認した内容です。画面名や対応形式は変わるため、自習では実施直前に公式情報と組織の実画面を再確認します。

## 段階3：30行を分類・集計・報告する

### 操作1：AIへ分類候補を作らせる

AI経路だけで行います。新しい空のチャットを開き、次のプロンプトをコピーします。続けて、`{ここへCSVの見出しと30行を貼る}`の1行だけを削除し、[CSV](../sample-data/monthly_inquiry_cases.csv)の見出しから30行目までを同じ位置へ貼り付けます。

```text
あなたは、架空の月次問い合わせを整理する補助者です。

目的：入力された30行について、分類、複数論点、優先確認、根拠語句の候補を作る。
これは候補であり、最終判断や顧客対応ではない。

主分類は次のどれか一つ：
アカウント・ログイン、申込・契約、請求・支払、操作方法、不具合、解約、保留（情報不足）

分類ルール：
- 中心となる依頼または最後に求めている対応を主分類にする。
- 残る話題は副論点へ書き、なければ空欄にする。
- 材料不足や本文空欄は推測せず「保留（情報不足）」にする。
- 直近期限と利用不能、金銭の重複・解約後請求、複数端末の同現象は
  優先確認候補を「要確認」とし、それ以外は「通常」とする。
- 原因、責任、障害範囲、返金可否、契約上の結論を断定しない。
- 入力の連番、問い合わせID、行数、順序を変更しない。重複行も統合・削除しない。
- 空欄の問い合わせIDを作り足さない。
- 入力にない個人、会社、製品、日付、金額を追加しない。

出力：
- 見出しと30行をTSV（タブ区切り）で出す。Markdown表にしない。
- 列は「連番、問い合わせID、主分類候補、副論点候補、優先確認候補、分類根拠」の6列。
- 分類根拠は元の件名・本文の短い語句だけにし、タブや改行を含めない。
- 最後に説明文や集計を追加しない。

入力CSV：
---
{ここへCSVの見出しと30行を貼る}
---
```

送信前に、教材の30行以外が混ざっていないことを目で確認します。AI回答を受け取ったら、次を確認します。

- 見出し1行＋データ30行である
- 連番が1から30まで順番どおりである
- 問い合わせIDは空欄を含め元データと同じである
- 6列である
- 原因、返金、障害を断定する文がない

一つでも満たさなければ、出力をそのまま貼り付けません。同じチャットで`連番とIDを変更せず、欠けた行を戻してください`と1回だけ修正を求めます。直らなければAIなし経路へ切り替えます。

### AIなし経路：保存済み問題例を使う

[保存済みAI分類案（問題例）](../sample-outputs/inquiry_monthly_ai_output_problem.md)をAIの初回回答として扱います。問題例は正解ではありません。30行の元データと分類基準へ戻り、作り足し、誤分類、原因断定、優先確認漏れを直します。

### 操作2：AI候補を作業シートへ置く

1. AI出力または保存済み問題例のTSV部分だけをコピーします。
2. `作業用AI候補`シートのA1を選び、貼り付けます。
3. A列からF列の6列、見出しを含む31行に分かれたことを確認します。
4. 全てA列へ入った場合は、[クイックスタートのデスクトップ版・Web版の違い](../setup/participant_quickstart.md#8-excelでタスク一覧を作る)に従います。
5. A列の連番とB列のIDを、`明細`シートのA列・B列と上から30行すべて照合します。

連番またはIDが一つでも違う場合は一括コピーをしません。元データを正として、次の操作で1行ずつ判断します。

### 操作3：最終判定用の列を作る

`明細`シートのG1からM1へ、次の見出しを入力します。

| 列 | 見出し | 入れる内容 |
|---|---|---|
| G | 最終主分類 | 人が確定した主分類 |
| H | 副論点 | 人が確認した副論点。なければ空欄 |
| I | 優先確認候補 | `要確認`または`通常` |
| J | データ品質 | 数式で`正常`、`重複候補`、`ID空欄`、`本文空欄`を表示 |
| K | 分類根拠 | 元の件名・本文にある短い語句 |
| L | 人間確認 | 全項目を元資料と照合した後だけ`確認済み` |
| M | 集計対象 | 数式で`対象`または除外理由を表示 |

AI候補の行数・連番・IDが完全に一致した場合だけ、`作業用AI候補`のC2:E31を`明細`のG2:I31へ、F2:F31をK2:K31へコピーできます。これは候補の転記であり、確定ではありません。

### 操作4：データ品質を数式で確認する

`明細`シートのJ2へ次の数式を入力します。

```excel
=IF(B2="","ID空欄",IF(COUNTIF($B$2:B2,B2)>1,"重複候補",IF(F2="","本文空欄","正常")))
```

1. J2を選びます。
2. セル右下の小さな四角をJ31までドラッグするか、自分で案内した方法で数式をコピーします。
3. J2:J31を確認します。
4. `重複候補`では、同じIDの前の行と受付日・件名・本文まで一致するか、人が確認します。

次にM2へ入力し、M31までコピーします。L列が`確認済み`になるまでは、集計対象を確定しません。

```excel
=IF(L2<>"確認済み","未確認",IF(J2="重複候補","除外（重複）",IF(J2="ID空欄","除外（ID空欄）","対象")))
```

数式は候補を見つける補助です。この教材では、連番18が連番7とID・日付・件名・本文まで完全一致することを人が確認してから、L列へ`確認済み`と書きます。同じIDでも内容が異なるデータでは、この数式だけで除外せず、作業を止めて正式な重複処理ルールと業務責任者へ確認します。

### 操作5：30行を人が全件照合する

フィルターで例外だけを見て終わりにせず、連番1から30まで順番に行います。

1. `明細`のA列からF列を読みます。
2. [分類基準](../sample-data/monthly_inquiry_classification_rules.md)で主分類、複数論点、優先確認、データ品質の条件を確認します。
3. G、H、I、Kを採用・修正します。
4. 原因や対応結論がK列へ混ざっていれば、元文の短い根拠語句へ直します。
5. AからMまでをもう一度確認した後、L列へ`確認済み`と入力します。
6. [レビューシートの30行照合欄](../workbooks/inquiry_monthly_review_sheet.md#3-30行の全件照合)へ結果を記録します。

AIが同じ分類を出していても、照合を省略しません。判断できないものは`保留（情報不足）`とし、集計のために無理に通常分類へ入れません。

### 操作6：集計表を作る

`集計`シートへ次の項目と数式を入力します。

| セル | 入力する内容 | 期待する意味 |
|---|---|---|
| A1 | 指標 | 見出し |
| B1 | 値 | 見出し |
| A2 | 元データ行数 | CSVの30行 |
| B2 | `=COUNTA(明細!A2:A31)` | 空欄でない連番を数える |
| A3 | 集計対象件数 | 重複後発行・ID空欄を除く |
| B3 | `=COUNTIF(明細!M2:M31,"対象")` | 対象行を数える |
| A4 | 重複除外 | 後から出た重複候補 |
| B4 | `=COUNTIF(明細!M2:M31,"除外（重複）")` | 重複除外を数える |
| A5 | ID空欄除外 | ID空欄 |
| B5 | `=COUNTIF(明細!M2:M31,"除外（ID空欄）")` | ID空欄除外を数える |
| A6 | 本文空欄 | 元30行中の本文空欄 |
| B6 | `=COUNTIF(明細!J2:J31,"本文空欄")` | 本文空欄を数える |
| A7 | 保留 | 対象のうち情報不足 |
| B7 | `=COUNTIFS(明細!M2:M31,"対象",明細!G2:G31,"保留（情報不足）")` | 保留を数える |
| A8 | 優先確認候補 | 対象かつ要確認 |
| B8 | `=COUNTIFS(明細!M2:M31,"対象",明細!I2:I31,"要確認")` | 優先確認候補を数える |
| A9 | 複数論点 | 対象かつ副論点あり |
| B9 | `=COUNTIFS(明細!M2:M31,"対象",明細!H2:H31,"<>")` | 副論点のある行を数える |
| A10 | 未確認件数 | 人による元資料照合が終わっていない行 |
| B10 | `=COUNTIF(明細!M2:M31,"未確認")` | `0`でなければ報告へ進まない |

A11へ`主分類`、B11へ`件数`、C11へ`構成比`と入力します。A12:A18へ次の7分類を1行ずつ入力します。

```text
アカウント・ログイン
申込・契約
請求・支払
操作方法
不具合
解約
保留（情報不足）
```

B12へ次の数式を入力し、B18までコピーします。

```excel
=COUNTIFS(明細!$M$2:$M$31,"対象",明細!$G$2:$G$31,A12)
```

C12へ次の数式を入力し、C18までコピーします。C12:C18の表示形式をパーセント、小数1桁にします。

```excel
=B12/$B$3
```

A19へ`合計`、B19へ`=SUM(B12:B18)`、C19へ`=SUM(C12:C18)`と入力します。A20へ`差分確認`、B20へ次の数式を入力します。

```excel
=B3-B19
```

差分が`0`でない、または未確認件数が`0`でなければ報告へ進みません。L列の確認状態、数式範囲、除外、空欄、最終主分類を確認します。

### 操作7：月次報告を作る

`月次報告`シートへ次を配置します。

1. A1へ`架空問い合わせ 月次報告（2026年7月）`と入力します。
2. 対象期間を`2026-07-01～2026-07-31`とします。
3. 元データ行数、集計対象件数、重複除外、ID空欄除外、本文空欄、保留、優先確認候補、複数論点、未確認件数を`集計`シートから参照します。例：集計対象件数の値は`=集計!B3`です。未確認件数は`0`であることを表示します。
4. `集計`のA11:C19をコピーし、主分類別の件数と構成比を載せます。
5. 次の枠を作り、確認済み数値だけで文章を記入します。

| 見出し | 書く内容 |
|---|---|
| 観察できたこと | 最多の主分類と件数、保留、優先確認候補 |
| 追加確認 | 保留の不足情報、優先確認候補で担当者が見る事実 |
| 改善候補 | どの案内・手順を点検するかという候補。効果や原因は未確定とする |
| 限界 | 1か月の架空30行だけで、増減、原因、全体傾向は判断できない |
| 承認状態 | `研修用草案・外部送信禁止` |

`請求が多いのは画面が悪いから`のような因果表現は書きません。`請求・支払が最多のため、内訳と案内ページを追加確認する`のように、数値と次の確認を分けます。

### 操作8：作業用候補を残さず最終保存する

1. この教材では、レビューが終わったら`作業用AI候補`シートを削除します。実務で候補・修正履歴を保持すべきかは、組織の監査・記録・保存ルールで決め、自己判断で削除しません。
2. `明細`、`集計`、`月次報告`の3シートだけであることを確認します。
3. 同じ`架空問い合わせ月次報告_最終版.xlsx`へ上書き保存します。別名の中間ファイルは作りません。
4. メール送信、共有リンク作成、顧客システムへの登録は行いません。

AIのチャット画面や問題例を別ファイルとして保存しません。組織が保持する監査ログ、チャット履歴、版履歴は自己判断で削除せず、正式な保持・削除ルールに従います。

## 段階4：人による元資料照合を行う

[学習用レビューシート](../workbooks/inquiry_monthly_review_sheet.md)を使い、次の順で確認します。

### 1. 全件照合

- [ ] 連番1～30を飛ばさず確認した
- [ ] `明細`A～F列の元データとG～M列の最終判定・数式を、元CSVと分類基準へ全行照合した
- [ ] 主分類は1行につき一つである
- [ ] 複数論点を副論点へ分け、主分類へ二重計上していない
- [ ] 原因、責任、障害、返金・契約判断を作り足していない
- [ ] 全30行のL列が`確認済み`である

### 2. 数値照合

- [ ] 元データ行数＝集計対象＋重複除外＋ID空欄除外
- [ ] 主分類別合計＝集計対象件数
- [ ] 未確認件数が0である
- [ ] 差分確認が0である
- [ ] 比率の合計が丸め前で100%である
- [ ] 月次報告の数値が集計シートと一致する

### 3. 報告表現

- [ ] 「多い」と「増えた」を区別した
- [ ] 集計から原因や責任を断定していない
- [ ] 保留と優先確認候補を隠していない
- [ ] 研修用草案・外部送信禁止と明記した

### 停止条件

次のどれかが起きたら、共有・提出を止めて利用環境の管理者または組織の正式窓口へ知らせます。

- 実在情報を入力、貼り付け、画面共有した
- 元データが30行でない、または文字化け・列ずれがある
- AIが行やIDを変更し、元データへ戻しても対応関係を確認できない
- 集計対象件数と分類別合計の差が0にならない
- 未確認件数が0にならない
- 原因、責任、返金、契約、障害の専門判断が必要である
- 意図しない外部共有、自動送信、顧客システム更新が起きた

誤入力や誤共有の疑いがある場合は、証拠となる画面やログを自己判断で削除・転載せず、組織のインシデント手順と正式窓口に従います。

## Excelを利用できない場合

### Markdown経路

1. [レビューシートの30行照合欄](../workbooks/inquiry_monthly_review_sheet.md#3-30行の全件照合)へ最終主分類等を記入します。
2. 分類ごとに1件ずつ正の字またはチェックを付けて数えます。
3. 電卓を使える場合は、`分類件数 ÷ 集計対象件数 × 100`で構成比を小数1桁まで計算します。
4. レビューシートのMarkdownひな形へ、明細、集計、月次報告をまとめます。
5. `架空問い合わせ月次報告_最終版.md`として指定場所へ保存します。

### 紙上経路

自分でCSV、分類基準、レビューシート、問題例を印刷します。30行へ分類を書き、分類ごとに正の字で数え、元30行から除外2行を引いた件数と一致するか確認します。撮影して個人クラウドやSNSへ投稿しません。

## 完成条件

- [ ] 最終成果物に、確認済み明細、集計、月次報告がある
- [ ] 30行を全件照合した記録がある
- [ ] 元データ、除外、分類別合計の関係が一致している
- [ ] 未確認件数が0で、全行の人間確認が完了している
- [ ] 優先確認候補と保留を人が確認した
- [ ] 原因・責任・専門判断を断定していない
- [ ] 初回AI候補を別成果物として保存していない
- [ ] 外部送信、共有リンク、顧客システム更新をしていない

## 安全な終了処理

1. 最終成果物だけが自分または組織が決めた保存先にあることを確認します。
2. 誤って作った共有リンクや外部送信がないことを確認します。疑いがあれば削除だけで終えず正式窓口へ報告します。
3. ダウンロードしたCSV、コピー、一時ファイルは、自分または組織が定めたルールに従って保持または削除します。
4. 共有PCでは、指定された手順でExcelと業務用AIからサインアウトします。
5. 履歴・監査ログ・ごみ箱を自己判断で消去しません。

## 自習のポイント

- 最初から確認例の件数を見ず、段階4で自分の式と元CSVを照合します。
- AIの精度より、`30行を維持したか`、`元文へ戻ったか`、`保留できたか`を確認します。
- 分類の理由は、推測ではなく元の短い語句を引用して記録します。
- 数式エラーは、式を自分で打ち直す前に、シート名、行範囲、全角記号、引用符を順に確認します。
- デスクトップ版・Web版の画面は利用前に最新の公式情報で確認し、手順と異なる場合はMarkdownまたは紙上経路へ切り替えます。
- 実務への適用、外部送信、自動振り分けはこの演習に含めません。個人情報、契約、返金、障害対応が関係する場合は、担当部署または専門家の確認が必要です。
