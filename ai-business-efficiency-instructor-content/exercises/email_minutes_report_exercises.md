## この演習の目的

架空の会議メモや業務数値から、メール、議事録、タスク一覧、報告書、上司向け要約を作り、AI出力を元資料へ戻って確認する一連の作業を練習します。

## 準備：3つの経路から選ぶ

この演習は一人で完了できます。ペアで相互確認する方法は任意です。次のうち、利用できる経路を一つ選びます。

| 経路 | 準備とルール |
|---|---|
| 個人学習（AIあり） | 公式URL、利用規約、プライバシー設定、料金を最新の公式情報で確認し、教材の架空データだけを使う |
| 組織利用（AIあり） | 組織が承認したAI、業務用アカウント、指定保存先、正式な相談先だけを使う |
| AIなし | [保存済みの議事録・タスク一覧（問題例）](../sample-outputs/beginner_minutes_saved_output.md)と各演習内の架空データを使い、同じ照合と修正を行う |

## 演習の共通手順

1. **目的と成果物**を確認する。
2. **準備**として、使用経路と収録ファイルを確認する。
3. **手順付き例**だけを、説明を読みながら試す。
4. **自力課題**は、自己点検ガイドを開かずに作る。
5. **人による元資料照合**として、AI出力と元資料を自分で1項目ずつ比べる。
6. 詰まった場合だけ、末尾の**段階ヒント**を一つずつ開く。
7. 自力課題の後に**自己点検**ガイドと比べる。
8. 誤りまたは改善点を**最低1点修正**し、修正理由を残す。
9. **完了条件**と安全な終了を確認し、**次へ**進む。

## 共通ルール

- すべて架空の組織・人物・データです。実在情報へ置き換えてAIへ入力しないでください。
- 組織が承認したAIツールだけを使います。利用できない場合は紙上で行います。
- AI出力を元資料と1項目ずつ照合し、修正者・確認日を記録します。
- 外部送信は行いません。

## 使用ツールと開始前準備

基本ツールは、組織が指定した承認済み対話AIです。ChatGPTは選択肢の一例です。開始前に[クイックスタート](../setup/participant_quickstart.md)、[AIツール共通準備](../setup/common_preparation.md)、[対話AIのアカウント準備](../setup/chat_ai_account_setup.md)を確認します。

| 利用場面 | 準備 |
|---|---|
| 個人学習 | 公式サイトから登録した本人管理のアカウントと、教材の架空データを使う |
| 組織内学習 | 管理者が発行・承認した業務用アカウントを使い、個人登録を行わない |
| 指定された対話AIを利用できない | 教材に収録された架空の初回出力または紙上草案を使う |

開始前に、ログイン状態、履歴・共有設定、画面共有の有無、入力データ、外部送信を行わないことを確認します。

## この演習集の進め方

最初に**演習1の会議メモ整理**を行います。これは、AIに文章を書かせるだけでなく、実務で使える二つの成果物を完成させるガイド付き演習です。

> [クイックスタート](../setup/participant_quickstart.md)で同じ会議メモを使い、完成した議事録とタスク一覧まで保存済みの人は、演習1を繰り返す必要はありません。成果物が下記の完了条件を満たすことだけ確認し、[演習2](#演習2メール返信作成)へ進んでください。演習1は、このファイルから始める場合や、クイックスタートを未実施の場合に使う手順付き例です。

```text
完全な架空会議メモ
  ↓
完成プロンプトをコピーしてAIへ送る
  ↓
Word用議事録＋Excel用タスク一覧の草案
  ↓
元メモと全項目を照合
  ↓
同じチャットで修正
  ↓
条件を1点だけ改善して再出力
  ↓
もう一度事実を照合
  ↓
完成した議事録とタスク一覧だけを保存
```

初回草案を別のメモ帳へ転記するだけの作業は行いません。初回草案はAIの同じチャットに残したまま照合し、最終的に業務で使う形へ整えた成果物を保存します。AIの履歴保存を業務記録の代わりにはしません。

演習1の後は、必要に応じて演習2〜5へ進みます。どの演習でも、次の順序は同じです。

| 段階 | 自分が行うこと | 人として確認すること |
|---|---|---|
| 準備 | 承認済みAI、架空データ、保存先を確認 | 入力禁止情報や実在情報がないか |
| 草案作成 | 完成プロンプトをコピーして送信 | 指定した形式で出力されたか |
| 事実照合 | 元資料とAI出力を1項目ずつ比較 | 数値、決定、担当、期限、未決事項 |
| 修正 | 同じチャットで具体的な修正を依頼 | 修正によって別の誤りが増えていないか |
| 1点改善 | 読み手、要約、並び順などを一つ変更 | 改善後も事実が一致しているか |
| 完成 | Word・Excel等へ貼り付けて体裁を整える | 外部送信前の承認が必要か |

## 手順付き例（演習1）：会議メモからWord用議事録とExcel用タスク一覧を作成

### 目的

少し乱れた会議メモから、会議参加者が確認する議事録と、実行管理に使うタスク一覧を作ります。AIが入力にない決定・担当・期限を補っていないか、人が元メモへ戻って確認します。

照合時の正式な元資料は、[初回演習用の架空会議メモ](../sample-data/beginner_meeting_notes.md)です。AI出力と食い違う場合は、この元資料を正とします。

### 完成させる成果物

| 成果物 | 使用するアプリ | 完成した状態 |
|---|---|---|
| 会議議事録 | Word | 会議情報、3件の決定事項、3件の未決事項が読みやすく整理されている |
| タスク一覧 | Excel | タスク・担当・期限の3列に、元メモで確定した3件だけが入っている |

**タブ区切り（TSV）**とは、項目と項目の間をタブという区切り文字で分けた形式です。Excelへ貼り付けると、`タスク`、`担当`、`期限`を別々の列に分けやすくなります。

Word・Excelは、組織が指定したデスクトップ版またはWeb版を使用します。Web版を使う場合も、個人アカウントを新規登録したり、アプリや拡張機能を自己判断でインストールしたりしません。

WordまたはExcelを利用できない場合は、[Officeを利用できない場合](#officeを利用できない場合)の方法で同じ内容を完成させます。

### 操作1：入力前に確認する

- [ ] 組織が指定した承認済み対話AIを開いている
- [ ] 新しい空のチャットを開いている
- [ ] 次のコードブロックを実在する会議情報へ書き換えていない
- [ ] Word・Excelまたは代替用紙の保存先を確認した

### 操作2：完成プロンプトを一度だけ送る

次のコードブロック内をすべてコピーし、対話AIの入力欄へ貼り付けて送信します。元メモだけを先に送る必要はありません。

```text
あなたは、社内会議の記録を整理するアシスタントです。

目的：架空の会議メモから、Wordに貼り付ける議事録と、Excelに貼り付けるタスク一覧を作る。
読者：会議の参加者と研修運営の関係者。
入力：以下の区切り線内だけを材料にする。
---
- 2026-07-08、架空AI研修運営改善会議。参加：研修責任者、研修運営担当、情報システム担当、情報セキュリティ担当（すべて役割名）。
- 入力禁止情報一覧のレビュー：情報セキュリティ担当、2026-07-10まで。
- 録画をどう扱うかは法務確認が必要。録画の可否、確認する担当、期限は未決。
- 終了時チェックリストへのリンクを学習案内へ追加する。決定。
- 来月にフォローアップ会を行う案が出た。実施するかどうかも日程も未決。
- 学習案内の改訂：研修運営担当、2026-07-12まで。
- 次回の初心者研修は、教材の完全な架空データだけを使う。決定。
- 次回会議日は未決。時刻と会場も決まっていない。
- 業務用アカウントのログインテスト：情報システム担当、2026-07-11まで。
- 会議終了時チェックリストを共有フォルダーへ置く。決定。
---
制約：
- 入力にない決定、担当、期限、日時、参加者を補わない。
- 未決の担当と期限は「未決」と書く。
- 走り書きを決定事項、担当と期限が確定したタスク、未決事項に分類し、混同しない。
- 法的な結論を作らず、「法務確認が必要」という状態を保つ。
- 実在する人物、企業、URLを追加しない。
出力形式：
1. 最初に「Word貼り付け用議事録」と書く。
2. 会議名、開催日、参加者の役割、決定事項、未決事項の順で整理する。
3. 次に「Excel貼り付け用タスク一覧」と書く。
4. タスク一覧は「タスク」「担当」「期限」の3列とし、列の間をタブで区切る。Markdownの表にはしない。
5. タスク一覧には、担当と期限が両方決まっている3件だけを含める。
```

### 操作3：AIの画面上で初回草案を確認する

AIの回答はまだ完成品ではありません。別のメモ帳へ保存せず、AI画面と次の元メモ確認表を並べて確認します。

| 確認対象 | 元メモの正しい内容 | AI出力の判定 |
|---|---|---|
| 会議名 | 架空AI研修運営改善会議 |  |
| 開催日 | 2026-07-08 |  |
| 参加役割 | 指定された4役割 |  |
| 決定事項 | 指定された3件 |  |
| タスク | 指定された3件だけ |  |
| タスクの担当・期限 | 3件すべて元メモどおり |  |
| 録画 | 録画可否・確認担当・期限は未決。法務確認が必要 |  |
| 来月のフォローアップ会 | 実施可否・日程とも未決 |  |
| 次回会議 | 日付・時刻・会場は未決 |  |
| 入力外の情報 | 追加されていない |  |

判定欄には`一致`、`不足`、`入力外の追加`のいずれかを書きます。言い換えは、意味と決定状態が同じなら一致です。

### 操作4：同じチャットで修正する

不足または入力外の追加が一つでもあれば、同じチャットへ次の形式で送ります。`{}`内を見つけた問題へ置き換えます。

```text
元メモとの照合で、次の問題を見つけました。
- {AI出力の問題}
- {元メモの正しい内容}

入力にない情報は補わず、Word貼り付け用議事録とExcel貼り付け用タスク一覧を両方とも修正してください。
修正後も、決定事項、担当、期限、未決事項が元メモと一致しているか自己確認してください。
```

修正版が出たら、操作3の全項目をもう一度確認します。最初から誤りがなかった場合も、`初回草案の事実修正なし`と手元の照合表へ記録して次へ進みます。

### 操作5：自分で条件を1点だけ改善する

このガイドでは、**タスクを期限の早い順に並べる**という1点だけを改善します。同じチャットへ次の全文を送ります。

```text
内容、担当、期限は変えず、Excel貼り付け用タスク一覧だけを期限の早い順に並べ替えてください。
Word貼り付け用議事録も含め、最終版の全文を再出力してください。
元の会議メモにない情報は追加しないでください。
```

タスクが`2026-07-10`、`2026-07-11`、`2026-07-12`の順になったことを確認します。再出力後も、操作3の表を使って**全項目を再確認**します。読みやすくなっていても、担当や期限が変わった場合は完成にしません。

自分で別の観点を指定した場合は、読み手の変更、100字以内の要約追加、議事録の並び順変更などから一つだけ選んでも構いません。一度に複数の条件を変えず、何を変えたかを記録し、再出力の全事実を照合します。

### 操作6：Word用議事録を完成させる

1. Wordで新しい空の文書を開きます。
2. AIの最終出力から「Word貼り付け用議事録」だけをコピーして貼り付けます。「Excel貼り付け用タスク一覧」は含めません。
3. タイトルと見出しを整えます。内容そのものを推測で追加しません。
4. `完成議事録.docx`という名前、または自分または組織が決めた名前で指定場所へ保存します。
5. 外部送信、共同編集、共有リンク作成は行いません。

### 操作7：Excel用タスク一覧を完成させる

1. AIの最終出力にあるタブ区切りの見出し行と3件のタスクをコピーします。
2. Excelで新しい空のブックを開き、A1セルへ貼り付けます。
3. `タスク`、`担当`、`期限`が別々の列へ入ったことを確認します。
4. デスクトップ版で1列に入った場合は、組織の規程に従って「データ」→「区切り位置」でタブを区切り文字に指定します。Web版で1列に入った場合は`Ctrl+Z`で貼り付けを取り消し、自分で事前確認した貼り付け方法、組織指定のExcel様式、またはMarkdown・紙上代替へ切り替えます。
5. `タスク一覧.xlsx`という名前、または自分または組織が決めた名前で指定場所へ保存します。
6. 自動送信、カレンダー登録、担当者への通知は行いません。

### Officeを利用できない場合

| 利用できるもの | 代替方法 |
|---|---|
| Markdown対応エディター | 議事録を見出しと箇条書き、タスクを3列のMarkdown表にして保存する |
| テキストエディター | 議事録をプレーンテキスト、タスクをタブ区切りのまま保存する |
| 紙だけ | [初回演習ワークシート](../workbooks/beginner_minutes_worksheet.md)の印刷版へ議事録と3列のタスク表を書き、元メモ照合欄にチェックする |

紙上演習では、[保存済みの議事録・タスク一覧（問題例）](../sample-outputs/beginner_minutes_saved_output.md)を開き、照合・修正します。個人アカウントを新しく作る必要はありません。この問題例を正解として保存しないでください。

### 演習1の完了条件

- [ ] 完全な架空データだけを使用した
- [ ] 元メモの全項目を人が照合した
- [ ] 必要な修正を同じチャットで行い、修正版も再確認した
- [ ] タスクを期限の早い順にするなど、指定された1点だけを改善した
- [ ] 改善後の出力も全項目を再確認した
- [ ] 完成した議事録とタスク一覧を指定場所へ保存した
- [ ] メール送信、公開、共有、自動登録を行っていない

## 完成条件と自己点検ポイント

| 観点 | 完成した状態 | 改善が必要な状態 |
|---|---|---|
| 入力安全 | 架空・最小限の情報と承認済み環境を確認 | 実情報、禁止情報、未承認環境を使う |
| 指示設計 | 目的・読者・制約・形式・確認方法を指定 | 曖昧な依頼だけで生成する |
| 事実忠実性 | 入力外を断定せず、不明を明示 | 日時、担当、原因、補償などを創作する |
| 実務品質 | 読者が状況と次の行動を理解できる | 結論、依頼、要確認事項が分からない |
| 人間確認 | 全主張を照合し、修正者・確認日・承認点を残す | AI出力を無確認で採用する |

### 演習2〜5で実際に行う共通操作

1. 各演習の「自力課題」にある完成プロンプト全体を、承認済み対話AIの新しいチャットへ貼り付けて送信します。
2. 初回草案を別ファイルへ保存せず、AI画面上で架空データと照合します。日付・数値だけでなく、決定・候補・未決・確約禁止の状態も確認します。
3. 誤りがあれば同じチャットで、`元資料では〇〇です。△△という記載を〇〇へ修正し、全文を再出力してください。入力外の情報は追加しないでください。`と具体的に伝えます。
4. 修正版を元資料と再照合します。
5. 読み手、文字数、要約、並び順などから1点だけ条件を変え、再出力します。
6. 最終出力の全事実をもう一度照合し、自分で指定した場合だけ完成成果物を指定場所へ保存します。メール送信や公開は行いません。

一度に多くの条件を変えず、「何を1点変えたか」と「変えた後も同じだった事実」を説明できるようにします。

## 演習2：メール返信作成

### 目的

日程変更への返信を、入力にない約束を追加せず作成します。

### 架空データ

```text
相手：青葉商事の研修担当役
受信内容：7月8日14:00の打合せを変更したい。7月9日午前または7月10日午後を希望。
自社の空き：7月9日10:00〜11:00のみ。オンライン会議を予定。
目的：7月9日10:00で確認を取り、会議URLは確定後に送る。
禁止：契約・費用・研修日程を確約しない。
```

### 自力課題

まず、次の完成プロンプトをコピーして試します。

```text
目的：架空の取引先へ、打合せ日程の変更候補を返信する。
読者：青葉商事の研修担当役。
入力：以下の区切り線内だけを材料にする。
---
相手：青葉商事の研修担当役
受信内容：7月8日14:00の打合せを変更したい。7月9日午前または7月10日午後を希望。
自社の空き：7月9日10:00〜11:00のみ。オンライン会議を予定。
目的：7月9日10:00で確認を取り、会議URLは確定後に送る。
禁止：契約・費用・研修日程を確約しない。
---
制約：7月9日10:00〜11:00だけを候補として提示する。会議URL、契約、費用、研修日程を確約しない。不明事項を補わない。200〜300字。
出力形式：件名、本文、送信前チェックの順。
評価基準：日時と利用可能時間が元資料に一致し、相手が返信すべき内容が分かる。
```

1. 件名、本文、送信前チェックを出力させるプロンプトを作ります。
2. 200〜300字、丁寧で簡潔な草案を作ります。
3. 日時、タイムゾーン、URL、確約表現を確認します。

> 自力で作成した後、対応する自己点検ガイドで根拠と修正点を確認します。

## 演習3：クレーム返信作成

### 目的

感情へ配慮しつつ、原因や補償を勝手に断定しない一次返信を作ります。

### 架空データ

```text
顧客からの連絡：オンライン研修で10分ほど音声が聞こえず、途中の説明を受けられなかった。
確認済み事実：運営側でも一部時間帯の音声不具合を確認。原因は調査中。
対応：資料と該当部分の代替説明文を翌営業日17時までに案内予定。
補償：未決。返信で約束しない。
窓口：研修運営窓口（架空）。
```

### 自力課題

```text
目的：架空の音声不具合に対する一次返信を作る。
読者：不具合を連絡した研修参加者。
入力：以下の区切り線内だけを材料にする。
---

窓口：研修運営窓口（架空）。
---

評価基準：感情へ配慮しつつ、調査中と未決事項が明確である。
```

1. 「受け止め、確認済み事実、現在の対応、次回連絡、窓口」の順で作ります。
2. 顧客の過失を示唆する表現、原因断定、補償確約を禁止します。
3. 共感表現が過剰な責任認定になっていないか確認します。

> 自力で作成した後、対応する自己点検ガイドで根拠と修正点を確認します。
