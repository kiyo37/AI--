# AI業務効率化講師のための用語集

## 使い方

用語を暗記するためではなく、**専門知識のない受講者へ短く説明するため**の用語集です。各用語は「一言説明→業務例→注意点」の順で説明してください。製品仕様や法的な定義は変わる場合があるため、最新の公式情報・社内規程・専門家の見解を優先します。

## AI・生成AIの基礎

| 用語 | 初心者向けの意味 | 講師が添える注意点 |
|---|---|---|
| AI（人工知能） | 人が行う認識、予測、文章作成などの一部をコンピューターで支援する広い概念 | 人間と同じ理解・責任を持つとは限らない |
| 機械学習 | データの例から傾向や規則を学ぶ方法 | 学習データの偏りが結果へ影響する |
| 深層学習 | 多数の層を持つニューラルネットワークを使う機械学習 | 「深い」は人間の深い理解を意味しない |
| ニューラルネットワーク | 入力を複数段階で変換し、特徴や関係を学ぶ計算の仕組み | 人間の脳そのものではなく、脳から着想を得た数理モデル |
| 生成AI | 文章、画像、音声などの新しい内容を作るAI | 生成物の正しさ、権利、安全性は人が確認する |
| LLM（Large Language Model／大規模言語モデル） | 大量の文章などから言葉のパターンを学び、文脈に続く文章を生成するモデル | 流暢さは事実の保証ではない |
| 確率的生成 | 前後の文脈から次に続きやすい言葉を選び、内容を順に組み立てること | 同じ指示でも出力が変わる場合があり、正しさは保証されない |
| モデル | 入力から出力を作るために学習された仕組み | 製品とモデルは別。1製品が複数モデルを使う場合がある |
| 推論 | 学習済みモデルへ入力し、出力を作る処理 | 人間の論理的推論と同じ正確さを保証しない |
| ルールベース | 人があらかじめ決めた「もし〜なら〜する」という規則で動く方式 | 曖昧な文章には弱いが、固定条件の判定には向く場合がある |
| 自然言語 | 日本語や英語など、人が日常の会話や文章で使う言葉 | プログラム言語とは区別して使う |
| トークン | AIが文章を処理する小さな単位 | 文字数と一致せず、上限・料金の数え方はモデルごとに異なる |
| コンテキストウィンドウ | 1回の処理でAIが参照できる情報の範囲 | 広くても全情報を正しく使える保証はない |
| マルチモーダル | 文章に加え、画像、音声、動画など複数種類を扱うこと | 入力の種類が増えるほど映り込みや誤認のリスクも増える |
| プロンプト | AIへ渡す目的、入力、制約、出力形式などの指示 | 呪文ではなく、小さな業務仕様書として扱う |
| プロンプトエンジニアリング | 目的に合うAIへの指示を設計し、出力を評価・改善する考え方 | 指示だけで解決しない問題は、データ・業務・仕組みを見直す |
| ハルシネーション | AIがもっともらしい誤情報や存在しない出典を生成すること | AIへ再質問するだけでなく、一次情報で確認する |

## 業務分析・評価

| 用語 | 初心者向けの意味 | 講師が添える注意点 |
|---|---|---|
| 業務プロセス | 仕事の開始から完了までの作業、判断、受渡しの流れ | 業務名のままAI化せず、1動作ずつ分ける |
| Before / After | 改善前と改善後を同じ指標で比べること | 生成時間だけでなく確認・修正時間も含める |
| 統制 | リスクを抑えるために、権限、承認、記録、監視、停止などを組み合わせて管理すること | 注意喚起だけでなく、実際に守れる仕組みにする |
| リスクベース | すべてを一律に扱わず、起こりやすさと影響の大きさに応じて対策を変える考え方 | 高影響用途や検出しにくい誤りほど確認を厚くする |
| KPI（Key Performance Indicator／重要業績評価指標） | 目標への進み具合を測る重要な指標 | 利用回数ではなく、時間・品質・重大誤りを測る |
| PoC（Proof of Concept／概念実証） | 本格導入前に、対象と期間を限定して実現性・効果・安全性を確かめる検証 | 成功基準だけでなく停止条件も先に決め、人が結果を評価する |
| ルーブリック | 成果物や実演を段階別の基準で採点する表 | 好みではなく観察できる行動で評価する |
| CRM（Customer Relationship Management／顧客関係管理） | 顧客情報、商談、対応履歴などを管理する仕組み | 顧客情報の入力・連携には権限と契約確認が必要 |
| CS（Customer Support／カスタマーサポート） | 顧客からの質問、相談、苦情などへ対応する業務・部門 | 対応履歴には個人情報や機密情報が含まれ得る |
| FAQ（Frequently Asked Questions／よくある質問） | よく寄せられる質問と回答をまとめたもの | 内容の版、根拠、更新責任者を管理する |
| ID（Identifier／識別子） | 文書やデータを他と区別するための番号・記号 | 氏名などの個人情報をそのままIDにしない |
| URL | ウェブページやファイルの場所を示すインターネット上のアドレス | URLが開けるだけでは内容の正しさを証明しない |
| SNS（Social Networking Service） | 利用者同士が情報を投稿・共有するオンラインサービス | 投稿を一次情報と決めつけず、元情報を確認する |
| API（Application Programming Interface） | ソフトウェア同士が決められた形式で情報や機能をやり取りする窓口 | APIキーは秘密情報であり、AIへ入力しない |
| JSON（JavaScript Object Notation） | 項目名と値を組にして、システムが読みやすく表すデータ形式 | 形式が正しくても内容が正しいとは限らない |
| SaaS（Software as a Service） | インターネット経由で利用するソフトウェアサービス | 保存場所、契約、管理機能、提供終了時の対応を確認する |
| ワークスペース | 組織やチーム単位で利用者、設定、データをまとめて管理する領域 | 個人用と組織用を混同しない |
| 権限継承 | 元のシステムで設定した閲覧・編集の許可を連携先でも引き継ぐこと | 実際の継承範囲を設定とテストで確認する |
| コネクタ | 自動化ツールとメール、表計算、チャットなどを接続する連携部品 | 接続先ごとに権限、送信先、保存、費用を確認する |
| 業務スイート | 文書、表計算、メール、会議など複数の業務機能をまとめた製品群 | 製品名が同じでも契約プランで機能が異なる場合がある |
| 出口計画 | 契約終了やサービス停止時に、データと業務を別の手段へ安全に移す計画 | データ出力、削除確認、手動代替、責任者を決める |
| 工数 | 作業に必要な人の時間や労力 | AIの生成時間だけでなく確認・修正時間も含める |
| 中央値 | 値を小さい順に並べたとき中央に位置する値 | 極端に大きい・小さい値の影響を平均より受けにくい |
| 要件定義 | 目的、必要な機能、制約、安全条件、合格基準を実施前に明確にすること | ツール選定より先に業務要件を決める |
| 仕様書 | 何を、どの条件で、どの形式に仕上げるかを定めた文書 | AIへの指示も小さな仕様書として整理できる |
| ボトルネック | 業務全体の速度や成果を最も妨げている工程 | AI化の前に手順変更で解消できないか確認する |
| データフロー | 情報がどこから入り、どこで処理・保存され、どこへ渡るかという流れ | 外部送信、再委託、削除まで確認する |
| 与信 | 支払能力などを審査し、後払いや融資などの信用を与える判断 | 高影響判断であり、AIだけで確定しない |
| 足切り条件 | 他の効果が高くても、満たさなければ不採用とする最低条件 | 重大誤り、権限違反、情報漏えいなどを対象にする |
| 責任分界 | AI、作成者、確認者、承認者、管理者がどこまで判断・対応するかを区切ること | 最終責任をAIへ置かない |
| 読者適合 | 言葉、詳しさ、構成が対象読者の知識と目的に合っていること | 対象者による試読や演習で確認する |
| 構造化形式 | 項目名や順序などの規則を決めたデータ形式 | 表やJSONなど、後工程が扱いやすい形を選ぶ |
| 形式検証 | 出力が決めた項目、型、順序などの規則どおりか確かめること | 形式が合格でも内容の正しさは別に確認する |
| 機密性 | 権限のない人へ情報を見せない性質 | 情報分類、アクセス権、保存、送信先で守る |
| 完全性 | この教材の文章評価では、必要な項目に抜けがないこと | 正確性とは別に確認する。セキュリティ分野では改ざん防止の意味でも使われる |
| 明確性 | 読み手が複数の意味に取り違えにくいこと | 主語、対象、期限、条件を具体化する |
| 網羅性 | 必要な範囲をどの程度漏れなく含んでいるか | 情報を増やすだけでなく、対象範囲を先に定める |
| 検出可能性 | 誤りや異常を人や仕組みが見つけられる度合い | 影響が大きく見つけにくい処理は自動化を避ける |
| 粒度 | 作業や情報をどの細かさに分けるかという単位 | 業務分解では原則として1行1動作にする |
| しきい値 | 処理、承認、判定を分ける境界となる値 | 金額や件数など、誰が変更できるかを管理する |
| 妥当性 | 目的や条件に照らして適切であること | 「動いた」だけでなく、学習・業務目的に合うか確認する |
| 形骸化 | ルールや確認が形式だけになり、実質的に機能しない状態 | 承認者へ根拠・差分・影響を見せる |
| 是正 | 見つかった問題の原因を直し、再発しにくくする対応 | 修正後に同じ基準で再確認する |

## セキュリティ・プライバシー

| 用語 | 初心者向けの意味 | 講師が添える注意点 |
|---|---|---|
| 機密情報 | 公開されると組織や関係者に損害を与え得る非公開情報 | 自社だけでなく顧客・取引先情報も含む |
| 個人情報 | 個人を識別できる情報など、法令・規程で保護される情報 | 氏名を消しても組合せで再識別できる場合がある |
| データ分類 | 公開、社内限定、機密、厳秘など、情報の重要度に応じて扱い方を分けること | 組織の正式な分類と取扱規程を優先する |
| 匿名化 | 一般に、個人を識別できない状態へ加工する考え方 | 法的要件は厳密。自己判断せず担当者・専門家へ確認する |
| 仮名化 | 氏名などを別の記号へ置き換え、対応情報を別管理する考え方 | 元へ戻せる情報があれば、無条件に安全とは言えない |
| 再識別 | 氏名を消した情報を、部署、日時、役職などと組み合わせて本人へ結び付け直すこと | 伏せ字や仮名だけで安全とは判断しない |
| 認証情報 | パスワード、APIキー、秘密鍵など本人・システムを確認する秘密 | 誤入力時は削除だけでなく失効・交換・報告を行う |
| APIキー | プログラムがサービスを利用するときの秘密の鍵 | コード、ログ、画像、チャットへ載せない |
| 秘密鍵 | 暗号化や本人確認などに使う、外部へ公開してはいけない秘密の値 | 漏えいの疑いがあれば担当者が失効・交換する |
| セッショントークン | ログイン済みであることをサービスへ示す一時的な認証情報 | 取得されると本人になりすまされる場合がある |
| SSO（Single Sign-On／シングルサインオン） | 1回の共通認証で複数サービスへのログインを管理する仕組み | 退職・異動時の停止と権限連携を確認する |
| 最小権限 | 仕事に必要な最小限の閲覧・操作だけを許す原則 | エージェントや連携ツールにも適用する |
| アクセス権 | 誰がどの情報・機能を閲覧、編集、実行できるかを示す許可 | 必要以上の権限を与えない |
| アクセス制御 | アクセス権を設定・確認し、権限外の利用を防ぐ仕組み | 元文書と検索・連携先の権限を一致させる |
| シャドーAI | 組織が把握・承認していないAIの業務利用 | 禁止だけでなく承認済み代替手段と相談先を用意する |
| プロンプト注入 | 文書や外部データに隠れた指示でAIの動作を変えようとする攻撃 | 外部データを命令として信用せず、権限と出力を制限する |
| インシデント | 情報漏えい、誤送信、不正アクセスなど対応が必要な事故・事象 | 隠さず、停止・記録・報告・影響確認を行う |
| DPA（Data Processing Agreement／データ処理契約） | 個人データの処理条件を定める契約 | 契約名称や内容はサービス・地域で異なる |
| SLA（Service Level Agreement／サービス水準合意） | 稼働率やサポートなどサービス水準に関する合意 | 障害ゼロを保証するものではなく、代替手順も必要 |
| 第三者提供 | 情報を本人・自組織以外の別の者や組織へ渡すことに関する法務上の扱い | 該当性や必要な手続は個人情報担当・専門家へ確認する |
| 処理地域 | データが保存・処理される国や地域 | 契約、法令、再委託先と併せて確認する |
| 国外移転・データ越境 | データが国境を越えて保存、処理、提供されることに関する確認事項 | 適用法令や必要手続は担当者・専門家へ確認する |
| 再委託 | サービス提供者や受託者が、処理・業務の一部をさらに別の事業者へ任せること | 再委託先、処理内容、地域、事故通知を契約で確認する |
| データ主体 | 個人情報の対象となっている本人 | 問い合わせ、開示、訂正、削除等への対応は法令・規程で確認する |
| 暗号化 | データを権限のない人に読まれにくい形へ変えること | 保存時・通信時の適用範囲と鍵管理を確認する |
| 脆弱性 | 攻撃や誤操作に悪用される可能性があるシステム上の弱点 | 詳細を未承認AIや公開場所へ入力しない |
| 証拠保全 | 事故調査に必要な時刻、操作、ログなどを正式な手順で残すこと | 秘密情報をむやみに複製せず、窓口の指示に従う |
| CSIRT（Computer Security Incident Response Team） | 情報セキュリティ事故へ対応する組織内外の専門チーム | 組織により名称・連絡方法が異なる |
| ベンダーロックイン | 特定サービスへ依存し、別の手段へ移りにくくなる状態 | 出口計画と手動代替を用意する |

## 正確性・ガバナンス・権利

| 用語 | 初心者向けの意味 | 講師が添える注意点 |
|---|---|---|
| 一次情報 | 当事者、法令原文、公的統計、公式発表など元に近い情報 | 一次情報でも版、日付、対象、例外を確認する |
| 原著論文・原典 | 研究結果を最初に報告した論文や、引用・解説の元になった文書 | 要約だけでなく該当箇所と条件を確認する |
| ファクトチェック | 主張を分け、信頼できる根拠と照合する作業 | URLの実在だけでなく、本文が主張を支えるかを見る |
| 反証 | 仮説が誤りである可能性を示す証拠や条件 | AIに賛成材料だけでなく反対材料も探させる |
| エスカレーション | 自分だけで判断せず、責任者や専門家へ判断を引き継ぐこと | 引継ぎ条件と相談先を事前に決める |
| 母集団 | 調査や統計の結論を当てはめようとしている対象全体 | 標本との違い、対象期間、除外条件を確認する |
| AIガバナンス | AIを目的に沿って安全に使うための責任、ルール、監視、改善の仕組み | 規程を作って終わらず、運用指標と事故から更新する |
| バイアス | データや設計などにより、結果が特定方向へ偏ること | すべての差が不当とは限らないが、影響と公平性を評価する |
| 公平性 | 属性や立場によって不当な不利益が生じないよう確認する考え方 | 何を公平とするかは業務・法令・関係者で定義する |
| 透明性 | AIをどこでどう使ったかを関係者が理解・確認できる状態 | 必要な開示範囲は用途・契約・規程で決める |
| 説明責任 | 判断や運用の理由・根拠・責任者を説明できること | AIが出したから、では説明にならない |
| 人間レビュー | AI出力を目的別チェックリストと元資料で確認すること | 時間、専門性、修正・停止権限が必要 |
| 依拠 | 既存作品に接して、それを基に表現を作ったと評価されること | 法的評価は個別事情によるため専門家へ確認する |
| パブリシティ | 氏名や肖像などが持つ顧客吸引力に関する利益の考え方 | 著作権とは別の論点。地域・事情により専門家確認が必要 |
| 著作権 | 文章、画像、音楽などの創作的な表現について、権利者が利用を管理できる権利の総称 | 保護範囲や例外は地域・事情で異なるため専門家へ確認する |
| 商用利用 | 販売、広告、企業活動など、事業や収益に関係する利用 | 範囲はサービス規約・ライセンスごとに確認する |
| ライセンス | 素材・生成物・ソフトウェアを利用できる条件を定めた許諾や契約上の権利 | 製品利用の契約と著作物利用の許諾を区別する |
| 帰属・クレジット | 権利を誰が持つか、または作者名・出典等をどのように表示するかという事項 | ライセンスや契約で必要な表示を確認する |
| 商標 | 商品・サービスの出所を示す名称、ロゴなどを保護する仕組み | 著作権とは別に確認する |
| 肖像 | 人の顔や姿の利用に関する権利・利益の論点 | 同意、用途、地域、誤認の可能性を確認する |
| 不正競争 | 他者の商品表示との混同など、公正な競争を害する行為に関する法的論点 | 個別事案は法務・専門家へ確認する |
| リスク許容度 | 組織がどの程度のリスクまで受け入れるかという基準 | 経営・業務責任者が用途別に決める |
| 残余リスク（残存リスク） | 対策を行った後にも残るリスク | 本教材では「残余リスク」に表記を統一し、受容者と見直し日を記録する |
| 代表性 | テスト例やデータが実際の利用者・状況を偏りなく含む度合い | 全体平均だけでなく属性・状況別に確認する |
| 異議申立て | 影響を受けた人が訂正や人間による再判断を求められる仕組み | 連絡先、期限、再審査者を定める |
| 証跡 | 誰が、いつ、何を確認・承認・変更したかを後から確かめられる記録 | ログ自体の機密性と保存期間も管理する |

## RAG・自動化・エージェント

| 用語 | 初心者向けの意味 | 講師が添える注意点 |
|---|---|---|
| RAG（Retrieval-Augmented Generation／検索拡張生成） | 質問に関係する資料を検索し、その抜粋をAIへ渡して回答する仕組み | 根拠検索が加わっても正解は保証されない |
| ナレッジマネジメント | 組織の知識を集め、整理・共有・更新し、仕事で再利用できる状態を保つ活動 | 文書の所有者、版、期限、権限を決める |
| ナレッジベース | 組織の知識を検索・更新・再利用できる形で管理した情報群 | 所有者、版、権限、失効を管理する |
| メタデータ | 文書名、版、所有者、日付など文書を説明する情報 | 検索と版管理に使う |
| チャンク | 検索しやすい意味のまとまりへ分けた文書断片 | 小さすぎると原則と例外が切れる |
| 埋め込み | 文章の意味的特徴を比較しやすい数値へ変える処理 | 数値が近いことは正解を意味しない |
| ベクトル検索 | 埋め込みが近い文章を候補として探す検索 | 数字、否定、版、対象条件を別途確認する |
| ハイブリッド検索 | キーワード検索とベクトル検索など、複数の検索方法を組み合わせること | 組み合わせても検索漏れは残るため評価する |
| クエリ | 検索やデータ取得のためにシステムへ渡す質問・検索条件 | 初心者向けには「検索する質問」と言い換える |
| ベクトルデータベース（ベクトルDB） | 埋め込みを保存し、意味の近いデータを探せるようにしたデータベース | 保存権限、更新、削除、版を管理する |
| top-k | 検索結果などから上位k件を選ぶ指定。kには件数が入る | 件数を増やせば必ず正解が含まれるわけではない |
| グラウンデッドな回答 | 指定資料など確認できる根拠に基づいて作られた回答 | 根拠付きでも読み違いや引用誤りを人が確認する |
| 再順位付け | 検索候補を質問との関連度で並べ直す処理 | 候補に正解がなければ並べ直しても解決しない |
| 検索索引（インデックス） | 必要な情報を素早く探せるよう事前に作る検索用の一覧・構造 | 文書の更新や失効に合わせて作り直す |
| ベクトル索引 | 文章の意味的な近さから候補を探すための検索索引 | 数値、否定、版などは別の条件でも確認する |
| キーワード索引 | 文書内の語句から候補を探すための検索索引 | 言い換えや表記揺れで漏れる場合がある |
| 版フィルター | 版番号、施行日、失効状態などで検索対象を絞り込む条件 | 現行版だけが残るかテストする |
| RPA（Robotic Process Automation） | 人が行う定型的な画面操作を規則どおり再現する自動化 | 画面変更や例外に弱い場合がある |
| ワークフロー | 条件、順序、承認を決めて処理を流す仕組み | 失敗、再試行、重複防止を設計する |
| AIエージェント | 目標に応じて手順を選び、許可されたツールを使って処理する仕組み | 製品により定義が異なり、権限・上限・監査が重要 |
| Human-in-the-loop | 処理の途中に人の確認や承認を入れる設計 | 承認画面に元情報・根拠・差分を示す |
| ログ | 誰が、いつ、何を入力・実行・承認したかの記録 | ログ自体の機密性・保存期間も管理する |
| 監査 | 記録と実態から、ルールどおり運用されているか確かめる活動 | 指摘だけでなく是正と再確認まで行う |
| ロールバック | 変更や実行結果を以前の安全な状態へ戻すこと | 戻せない操作では事前承認を厚くする |
| 許可リスト | 実行してよい操作や接続先だけを登録し、一覧にない操作を拒否する仕組み | AIが自由な宛先・操作を作れないようにする |
| トリガー | メール受信や指定時刻など、自動処理を開始するきっかけ | 重複発火や誤作動を想定する |
| テナント管理 | 企業・組織単位で利用者、権限、設定、データ範囲をまとめて管理すること | 個人アカウントとの違いを確認する |
| オフライン評価 | 本番業務へ反映せず、保存済みの検証データで品質と安全性を採点する事前テスト | ここでの「オフライン」はインターネット未接続とは限らない |
| 例外処理 | 通常手順で扱えない入力やエラー時に、停止・通知・人手対応へ切り替える仕組み | 想定外を無理に自動処理しない |
| データベース | 情報を検索・更新しやすい形で整理して保存する仕組み | 読取・書込・削除の権限を分ける |
| 権限棚卸し | 利用者や連携ツールの権限を定期確認し、不要・過剰な権限を削除する作業 | 異動・退職・接続終了時にも行う |
| タイムアウト | 処理が決めた時間内に終わらないとき、待ち続けず失敗として止める仕組み | 再試行回数と人への通知を決める |
| テストセット | 品質と安全性を同じ条件で繰り返し評価するための質問・入力例の集まり | 通常例だけでなく、例外・権限違い・攻撃的入力も含める |

## 研修・講師実践

| 用語 | 初心者向けの意味 | 講師が添える注意点 |
|---|---|---|
| 行動目標 | 研修後に受講者が実演・判断できる具体的な行動 | 「理解する」では採点しにくい |
| ハンズオン | 受講者が実際に手を動かして学ぶ演習 | 操作だけでなく、確認・修正・停止を含める |
| Mermaid | Markdown内の文字コードからフロー図などを描く記法 | 閲覧環境によっては図ではなくコード表示になるため、文章による説明も付ける |
| ファシリテーション | 参加者の発言と作業を促し、目的へ沿って学習を進めること | 講師が全て話すことではない |
| ティーチバック | 受講者が学んだ内容を他者へ短く説明する練習 | 説明の正確さと分かりやすさを確認する |
| アクセシビリティ | 障害、年齢、端末などにかかわらず参加・理解しやすくする配慮 | 色だけに頼らない、字幕、読み上げ、代替手段を用意する |
| レッドチーム | 攻撃者・誤用者の視点で弱点を試す活動 | 許可された範囲とデータで実施する |
| アーキテクチャ | モデル、データ、検索、外部連携などをどう組み合わせるかというシステム全体の構成 | 構成図だけでなく責任とデータの流れも示す |
| アイデンティティ | IT上で、利用者が誰でどの組織・役割・権限を持つかを示す情報 | 認証と権限管理を区別する |
| 供給者評価 | サービス提供会社の安全対策、契約、障害対応、再委託先などを確認すること | 導入時だけでなく定期的に見直す |
| 自己効力感 | 「自分ならその行動を実行できる」と本人が感じる度合い | 実際の技能・業務成果とは分けて測る |
| オフィスアワー | 研修後に、決めた時間帯へ質問や相談を持ち込める場 | 相談内容と回答を次の教材改善へつなげる |
| ヒヤリハット | 事故には至らなかったが、一歩間違えば事故になり得た事例 | 責任追及ではなく予防とルール改善に使う |
| 架空化 | 実在する氏名、組織、数値などを使わず、一から架空情報を作ること | 氏名だけを隠す匿名化・仮名化とは異なる |
| ロールプレイ | 参加者が利用者、承認者、担当者などの役割を演じて判断・対応を練習する方法 | 正解発表だけでなく、判断理由と引継ぎを振り返る |

## 30秒説明の型

```text
{用語}とは、簡単に言うと{一言説明}です。
業務では{身近な例}に使います。
ただし、{限界・リスク}があるため、{人が行う確認}が必要です。
```

例：「RAGとは、簡単に言うとAIが指定資料を探してから回答する仕組みです。社内規程の質問対応などに使います。ただし、検索漏れや読み違いがあるため、人が引用と原文を確認します。」
