# 00 コース概要：AI業務効率化講師へのロードマップ

## 1. この章の目的

コース全体を俯瞰し、30日間の学習計画と最終成果物を決めます。AI業務効率化講師の仕事は、製品操作の説明ではなく、業務成果、安全性、定着までを設計することです。

**AI（Artificial Intelligence、人工知能）**とは、人が行う認識、予測、文章作成などの一部をコンピューターで支援する広い概念です。

## 2. 学習ゴール

- AI業務効率化講師に必要な知識領域を説明できる
- 自分の現在地と不足領域を把握できる
- 30日間の学習時間と成果物を具体化できる
- 各モジュールの完成条件と改善方法を理解できる

## 3. 本編解説

専門用語の短い説明は[用語集](glossary.md)でも確認できます。この章では全体像を先に示すため、後の章で詳しく扱う用語には初出時に短い説明を添えます。

### 3.1 コース全体像

**プロンプト**とは、目的、材料、条件、出力形式などをAIへ伝える指示です。プロンプトが上手でも、対象業務が不適切なら改善にはなりません。逆に、業務を分解できれば、AIを使わず手順変更だけで改善できる箇所も見つかります。

### 3.2 必要な知識マップ

この知識マップで使う中心語を先に押さえます。

- **確率的生成**：前後の文脈から次に続きやすい言葉などを確率に基づいて選び、内容を順に組み立てること
- **統制**：利用者、権限、承認、記録などを組織のルールに沿って管理すること
- **データ分類**：情報を公開、社内限定、機密などの重要度に分け、扱い方を決めること
- **RAG（Retrieval-Augmented Generation、検索拡張生成）**：関係する資料を検索し、その抜粋をAIへ渡して回答させる仕組み
- **AIエージェント**：目標に応じて手順を選び、許可されたツールを使って処理する仕組み

| 領域 | 主要な問い | 講師に必要な説明力 |
|---|---|---|
| AI基礎 | 何ができ、なぜ間違うか | 擬人化せず確率的生成として説明する |
| ツール | どれを選ぶか | 目的、データ、統制、連携、費用で比較する |
| プロンプト | どう指示するか | 良い例と悪い例を比較し、改善理由を示す |
| 業務分析 | どこに使うか | 作業、判断、例外、責任に分解する |
| セキュリティ | 何を入れてよいか | データ分類と契約・設定確認を教える |
| 正確性 | 何を信じるか | 根拠確認と高リスク時の停止条件を教える |
| 法務・統治（責任とルールで運用を管理すること） | 誰が責任を持つか | 権利、利用規約、承認、記録を整理する |
| RAG | 社内知識をどう使うか | 検索と生成の違い、限界を説明する |
| 自動化・AIエージェント | どこまで動かすか | 権限、承認、ログ（誰がいつ何をしたかの記録）、失敗時対応を設計する |
| 研修設計 | どう定着させるか | 対象者別に実務演習と観察方法を設計する |
| 講師実践 | どう安全に進行するか | 質疑、反対意見、デモ失敗に対応し、模擬登壇を改善する |

### 3.3 学習ロードマップ

**責任分界**とは、AI、自動化、人間がそれぞれどこまで担当し、誰が最終判断するかを区切ることです。**概念設計**とは、実装を始める前に必要な構成、流れ、条件を整理することです。

| フェーズ | 章 | 成果物 | 完成条件 |
|---|---|---|---|
| 基礎 | 01〜02 | 用語説明、ツール比較 | 初心者の質問に例を使って答えられる |
| 分析 | 04 | 業務分析シート | AI、人、自動化の責任分界が明確 |
| 指示設計 | 03 | 業務要件に基づくプロンプト集 | 出力を基準で評価・改善できる |
| 安全 | 05〜07 | リスク評価、利用ルール | 禁止・条件付き・可を理由付きで分類できる |
| 発展 | 08〜09 | RAG／自動化の概念設計 | 根拠、権限、承認、ログを含む |
| 講師 | 10〜11 | 組み替え可能な研修モジュール、模擬登壇の改善記録 | 目的、演習、観察、定着、進行が一貫している |

講師育成では `04→03` を推奨します。先に業務目的、判断、例外、責任を決め、その要件をプロンプトへ落とすためです。初心者向け研修の導入では、短い操作体験を先に置く `03→04` も選べます。

### 3.4 30日間の学習計画

各日の学習量は仕事や生活に合わせて調整します。AIツールの利用が社内で許可されていない場合、演習は紙上または講師が用意した架空出力で行います。

| 日 | テーマ | 手を動かす課題 |
|---:|---|---|
| 1 | 全体像 | 自己評価と研修対象者を決める |
| 2〜3 | 生成AI基礎 | 5つの専門用語を各100字で言い換える |
| 4〜5 | ツール概論 | 3つの業務を選定マトリクス（候補と評価軸を並べた比較表）で比較する |
| 6〜8 | 業務分解 | 1業務を開始から完了まで分解する |
| 9〜11 | プロンプト | 分解した業務のメール、議事録、報告書を改善する |
| 12 | 効果測定 | 時間、品質、リスクの指標を決める |
| 13〜15 | セキュリティ | 入力可否を分類し、安全な代替データを作る |
| 16〜17 | ハルシネーション（AIが作るもっともらしい誤情報） | 3つの主張を一次情報（公式発表や原資料など、発信元に近い情報）で検証する |
| 18〜19 | 著作権・統治 | AI利用ルール案をレビューする |
| 20〜22 | RAG | 文書準備、検索、引用評価を紙上設計する |
| 23〜25 | 自動化・AIエージェント | 承認付きフローと例外処理を書く |
| 26 | 研修ニーズ分析 | 対象者、課題、制約を整理する |
| 27 | 研修構成 | 導入・基礎・安全・実務演習を独立したモジュールとして作る |
| 28 | 教材・演習 | スライド案、架空データ、完成条件、観察ポイントを作る |
| 29 | 登壇実践 | 1つのモジュールで模擬講義、質疑対応、デモ障害の代替進行を実施する |
| 30 | 改善・提出 | フィードバックを反映し最終版にする |

### 3.5 最終成果物

「架空の企業・部署」を対象に、次の7点を一式で作ります。各成果物は、研修目的や利用可能な時間に応じて組み替えられるモジュールとして設計します。

| 成果物 | 必須要素 |
|---|---|
| 研修企画書 | 対象者、課題、到達目標、実施条件、前提 |
| 業務分析シート | 現行手順、AI候補、人の判断、リスク、効果指標 |
| モジュール型スライド構成 | 導入、基礎、安全、実演、演習、振り返りを独立して差し替え可能にする |
| ハンズオン（受講者が手を動かす演習） | 架空データ、手順、期待結果、失敗例、完成条件、観察ポイント |
| AI利用ルール案 | 禁止情報、承認、レビュー、ログ、相談先 |
| 定着計画 | 30・60・90日後の指標、相談会、事例共有 |
| 模擬登壇の改善記録 | 説明、問いかけ、安全性、進行、質疑、次回の改善 |

### 3.6 成果物レビューガイド

成果物は点数で順位付けせず、「完成条件を満たすか」「何を観察したか」「次に何を直すか」でレビューします。

| 観点 | 完成条件 | 観察ポイント | 改善ポイント |
|---|---|---|---|
| 説明 | 定義、身近な例、限界、人間確認を説明できる | 初心者が自分の言葉で言い換えられるか | 誤解しやすい言葉を図・例・対比例で補う |
| 業務設計 | 作業、判断、例外、責任、効果指標がつながる | 製品名より先に業務目的を説明しているか | AI以外の簡素化・通常自動化も比較する |
| 安全性 | 入力禁止、停止、相談、承認、記録が具体的である | 不明なケースで作業を止められるか | 契約・権限・監査の確認先を追記する |
| 演習 | 架空データで判断・生成・照合・修正を体験できる | 操作だけで終わらず判断理由を記録しているか | 失敗例と人間レビューを追加する |
| 定着 | 研修後の試行、相談、事例共有、指標確認がある | 現場と管理職の役割が決まっているか | 仕事へ戻った後の支援経路を明確にする |
| 登壇 | 問いかけ、演習、質疑、障害時代替を安全に進行できる | 受講者の迷いと誤解を拾えているか | 説明順、問い、代替教材を改善記録へ残す |

## 4. 実務での使いどころ

- 研修依頼を受けたときの要件確認
- 自分の知識不足を特定するチェックリスト
- 顧客に「研修後に何が残るか」を説明する提案資料
- 模擬登壇の観察・改善シート

## 5. 講師メモ

- 初回に「AIで何ができるか」より「誰が最終責任を持つか」を問いかけます。
- 成功例だけでなく、誤答、情報漏えい、過度な自動化の失敗例も扱います。
- 受講者が製品名に集中したら、業務目的とデータ分類へ話を戻します。
- 「正解を教える講師」ではなく「安全に判断できる枠組みを渡す講師」を目指します。

## 6. 演習

### 演習：自分の30日計画を作る

#### 利用環境の準備確認

- 企業研修では、受講者に個人登録を強制しません。管理者が発行・招待した業務用アカウントを使い、利用できない人には紙上ワークを配布します。
- 個人学習では、自分の判断と費用負担で個人アカウントを使えます。登録前に利用規約、年齢・地域条件、データ設定を公式情報で確認します。
- 基本演習はChatGPTを使います。準備は[対話AIアカウント準備ガイド](setup/chat_ai_account_setup.md)を参照してください。
- どちらの場合も、入力はこの教材の架空情報だけにします。

#### ガイド付き練習

講師の例を見ながら、知識マップの各領域を「まだ説明が難しい／例があれば説明できる／演習を進行できる」のいずれかで自己確認します。ChatGPTには、各領域を初心者向けに言い換える案だけを出させ、自己判断の代行はさせません。

#### 実務演習

1. 改善したい領域と、講師として扱いたい架空の業種を選びます。
2. 30日表へ実行日、成果物、利用する教材、相談相手を追記します。
3. 最終成果物をモジュール単位へ分け、完成条件を記載します。
4. 30日後に模擬講義を依頼する相手と、観察してほしい行動を決めます。

#### 人間レビュー

同僚または学習仲間が、実行可能性、安全性、成果物同士のつながりを確認します。AIが提案した計画はそのまま採用せず、本人が予定と責任を確定します。

#### 振り返り

- ChatGPTが整理を助けた部分はどこですか。
- 自分またはレビュー者が決める必要があった部分はどこですか。
- アカウントや組織ルールが未確認の場合、どの代替方法で学習を続けますか。

**完成条件**：実行日と成果物が具体的で、安全な利用環境、相談先、レビュー方法、代替方法が記載されていること。

## 7. 実務チェックリストと振り返り

この節は採点に使いません。実務へ移す前の自己確認と対話に使います。

- [ ] プロンプト以外に、業務分解、安全性、人間の責任、定着を学ぶ理由を説明できる
- [ ] 30日計画の各日に、作るものまたは試す行動がある
- [ ] 研修成果物を、目的に応じて組み替えられるモジュールとして設計した
- [ ] 企業研修では個人登録を強制せず、管理者発行アカウントまたは代替教材を用意した
- [ ] AI出力を人が確認し、不明な情報は担当者へ相談する前提がある

**振り返り**：今の自分が最初に強化する領域はどこですか。その領域を選んだ根拠と、最初に作る成果物を書いてください。

## 8. まとめ

講師に必要なのは、AI知識、業務分析、安全設計、研修設計の組み合わせです。30日間で各章の成果物を積み上げ、最後に「安全に実務へ移せる研修パッケージ」として統合します。
