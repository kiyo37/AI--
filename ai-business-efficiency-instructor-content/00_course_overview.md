# 00 コース概要：AI業務効率化講師へのロードマップ

## 1. この章の目的

コース全体を俯瞰し、30日間の学習計画と最終成果物を決めます。AI業務効率化講師の仕事は、製品操作の説明ではなく、業務成果、安全性、定着までを設計することです。

**AI（Artificial Intelligence、人工知能）**とは、人が行う認識、予測、文章作成などの一部をコンピューターで支援する広い概念です。

## 2. 学習ゴール

- AI業務効率化講師に必要な知識領域を説明できる
- 自分の現在地と不足領域を把握できる
- 30日間の学習時間と成果物を具体化できる
- 修了判定に使う評価基準を理解できる

## 3. 本編解説

専門用語の短い説明は[用語集](glossary.md)でも確認できます。この章では全体像を先に示すため、後の章で詳しく扱う用語には初出時に短い説明を添えます。

### 3.1 コース全体像

**プロンプト**とは、目的、材料、条件、出力形式などをAIへ伝える指示です。プロンプトが上手でも、対象業務が不適切なら改善にはなりません。逆に、業務を分解できれば、AIを使わず手順変更だけで改善できる箇所も見つかります。

### 3.2 必要な知識マップ

この知識マップで使う中心語を先に押さえます。

- **確率的生成**：前後の文脈から次に続きやすい言葉などを確率に基づいて選び、内容を順に組み立てること
- **統制**：利用者、権限、承認、記録などを組織のルールに沿って管理すること
- **データ分類**：情報を公開、社内限定、機密などの重要度に分け、扱い方を決めること
- **RAG（Retrieval-Augmented Generation、検索拡張生成）**：関係する資料を検索し、その抜粋をAIへ渡して回答させる仕組み
- **AIエージェント**：目標に応じて手順を選び、許可されたツールを使って処理する仕組み

| 領域 | 主要な問い | 講師に必要な説明力 |
|---|---|---|
| AI基礎 | 何ができ、なぜ間違うか | 擬人化せず確率的生成として説明する |
| ツール | どれを選ぶか | 目的、データ、統制、連携、費用で比較する |
| プロンプト | どう指示するか | 良い例と悪い例を比較し、改善理由を示す |
| 業務分析 | どこに使うか | 作業、判断、例外、責任に分解する |
| セキュリティ | 何を入れてよいか | データ分類と契約・設定確認を教える |
| 正確性 | 何を信じるか | 根拠確認と高リスク時の停止条件を教える |
| 法務・統治（責任とルールで運用を管理すること） | 誰が責任を持つか | 権利、利用規約、承認、記録を整理する |
| RAG | 社内知識をどう使うか | 検索と生成の違い、限界を説明する |
| 自動化・AIエージェント | どこまで動かすか | 権限、承認、ログ（誰がいつ何をしたかの記録）、失敗時対応を設計する |
| 研修設計 | どう定着させるか | 対象者別に演習と評価を設計する |
| 講師実践 | どう安全に進行するか | 質疑、反対意見、デモ失敗に対応し、模擬登壇を改善する |

### 3.3 学習ロードマップ

**責任分界**とは、AI、自動化、人間がそれぞれどこまで担当し、誰が最終判断するかを区切ることです。**概念設計**とは、実装を始める前に必要な構成、流れ、条件を整理することです。

| フェーズ | 章 | 成果物 | 合格の目安 |
|---|---|---|---|
| 基礎 | 01〜02 | 用語説明、ツール比較 | 初心者の質問に例を使って答えられる |
| 分析 | 04 | 業務分析シート | AI、人、自動化の責任分界が明確 |
| 指示設計 | 03 | 業務要件に基づくプロンプト集 | 出力を基準で評価・改善できる |
| 安全 | 05〜07 | リスク評価、利用ルール | 禁止・条件付き・可を理由付きで分類できる |
| 発展 | 08〜09 | RAG／自動化の概念設計 | 根拠、権限、承認、ログを含む |
| 講師 | 10〜11 | 3時間研修パッケージ、模擬登壇評価 | 目的、演習、評価、定着、進行が一貫している |

講師育成では `04→03` を推奨します。先に業務目的、判断、例外、責任を決め、その要件をプロンプトへ落とすためです。初心者向け研修の導入では、短い操作体験を先に置く `03→04` も選べます。

### 3.4 30日間の学習計画

1日45〜90分を目安にします。AIツールの利用が社内で許可されていない場合、演習は紙上または架空データで行います。

| 日 | テーマ | 手を動かす課題 |
|---:|---|---|
| 1 | 全体像 | 自己評価と研修対象者を決める |
| 2〜3 | 生成AI基礎 | 5つの専門用語を各100字で言い換える |
| 4〜5 | ツール概論 | 3つの業務を選定マトリクス（候補と評価軸を並べた比較表）で比較する |
| 6〜8 | 業務分解 | 1業務を開始から完了まで分解する |
| 9〜11 | プロンプト | 分解した業務のメール、議事録、報告書を改善する |
| 12 | 効果測定 | 時間、品質、リスクの指標を決める |
| 13〜15 | セキュリティ | 入力可否を分類し、安全な代替データを作る |
| 16〜17 | ハルシネーション（AIが作るもっともらしい誤情報） | 3つの主張を一次情報（公式発表や原資料など、発信元に近い情報）で検証する |
| 18〜19 | 著作権・統治 | AI利用ルール案をレビューする |
| 20〜22 | RAG | 文書準備、検索、引用評価を紙上設計する |
| 23〜25 | 自動化・AIエージェント | 承認付きフローと例外処理を書く |
| 26 | 研修ニーズ分析 | 対象者、課題、制約を整理する |
| 27 | 研修構成 | 3時間研修の流れを作る |
| 28 | 教材・演習 | スライド案、架空データ、採点基準を作る |
| 29 | 登壇実践 | 20分の模擬講義、質疑対応、デモ障害の代替進行を実施する |
| 30 | 改善・提出 | フィードバックを反映し最終版にする |

### 3.5 最終成果物

「架空の企業・部署」を対象に、次の7点を一式で作ります。

| 成果物 | 必須要素 |
|---|---|
| 研修企画書 | 対象者、課題、到達目標、時間、前提 |
| 業務分析シート | 現行手順、AI候補、人の判断、リスク、効果指標 |
| 3時間スライド構成 | 導入、基礎、安全、実演、演習、振り返り |
| ハンズオン（受講者が手を動かす演習） | 架空データ、手順、期待結果、失敗例、採点基準 |
| AI利用ルール案 | 禁止情報、承認、レビュー、ログ、相談先 |
| 定着計画 | 30・60・90日後の指標、相談会、事例共有 |
| 模擬登壇評価 | 説明、問いかけ、安全性、時間、質疑、改善記録 |

### 3.6 修了ルーブリック（段階別評価表）

**ルーブリック**とは、成果物や実演を段階別の基準で採点する表です。

| 評価軸 | 1：不足 | 2：基礎 | 3：実務 | 4：講師レベル |
|---|---|---|---|---|
| 説明 | 用語を列挙 | 定義を説明 | 例と限界を説明 | 誤解を予測し質問に対応 |
| 業務設計 | ツール起点 | 作業を抽出 | 責任と例外を分離 | KPI（Key Performance Indicator、重要業績評価指標）と導入順序まで提案 |
| 安全性 | 注意喚起のみ | 禁止情報を理解 | リスク別の対策を設計 | 契約・権限・監査（記録と実態を照合してルールどおりか確かめる活動）まで扱う |
| 演習 | 操作の模倣 | 指示どおり実施 | 判断理由を記録 | 評価基準と改善ループを設計 |
| 定着 | 研修で終了 | アンケート | 実務指標を追跡 | 管理職・相談窓口を巻き込む |
| 登壇 | 読み上げ中心 | 時間内に説明 | 問いかけと演習を進行 | 質疑・反対意見・障害へ安全に対応 |

目安は全項目3以上、かつ安全性は3以上です。

## 4. 実務での使いどころ

- 研修依頼を受けたときの要件確認
- 自分の知識不足を特定するチェックリスト
- 顧客に「研修後に何が残るか」を説明する提案資料
- 模擬登壇の評価表

## 5. 講師メモ

- 初回に「AIで何ができるか」より「誰が最終責任を持つか」を問いかけます。
- 成功例だけでなく、誤答、情報漏えい、過度な自動化の失敗例も扱います。
- 受講者が製品名に集中したら、業務目的とデータ分類へ話を戻します。
- 「正解を教える講師」ではなく「安全に判断できる枠組みを渡す講師」を目指します。

## 6. 演習

### 演習：自分の30日計画を作る（30分）

1. 上の知識マップを1〜4で自己評価します。
2. 最も弱い2領域と、講師として扱いたい業種を1つ選びます。
3. 30日表に具体的な学習時間と提出物を追記します。
4. 30日後に20分の模擬講義を依頼する相手と評価方法を決めます。

**提出物**：自己評価表、日程表、最終成果物の仮テーマ。評価基準は「実行日が決まっている」「成果物が観察可能」「安全性を含む」の3点です。

## 7. 確認問題

1. AI業務効率化講師が、プロンプト技術だけを教えてはいけないのはなぜですか。
2. 業務分解で最低限分けるべき3つの要素を挙げてください。
3. 最終成果物に定着計画を含める理由は何ですか。
4. 修了ルーブリックで安全性の最低基準を高くする理由は何ですか。

<details><summary>解答例</summary>

1. 対象業務、入力データ、誤りの影響、人の責任を整理しないと、速く誤る・漏えいする仕組みを作る恐れがあるためです。
2. 定型作業、人が行う判断、例外時の処理（責任者を含む）などです。
3. 研修中にできても、実務で使われ品質が改善しなければ業務成果にならないためです。
4. 情報漏えいや高リスク判断は、効率化効果より大きな損害につながり得るためです。

</details>

## 8. まとめ

講師に必要なのは、AI知識、業務分析、安全設計、研修設計の組み合わせです。30日間で各章の成果物を積み上げ、最後に「安全に実務へ移せる研修パッケージ」として統合します。
