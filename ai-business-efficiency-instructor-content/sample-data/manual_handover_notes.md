# 業務マニュアル作成演習用：未整理の引継ぎメモ

> この資料は演習のために一から作成した架空データです。実在する企業、人物、備品、申請、システムとは関係ありません。

## 1. この資料の位置付け

架空の「青葉サービス社 研修運営室」で、研修備品の貸出申請を台帳へ転記する担当者から受け取った、順不同の引継ぎメモです。メモには、古い記憶、未確認の表現、矛盾、不足があります。

このメモだけで台帳更新を始めてはいけません。まず、何を確認しなければ手順を確定できないか質問を作ってください。

| 表記 | 意味 |
|---|---|
| `M01`など | メモの識別番号。確認質問で根拠位置を示すために使う |
| `たぶん`、`らしい` | 未確認情報。業務ルールとして採用しない |
| 貸出台帳 | 貸出予定を記録する、組織指定の共有台帳 |
| 申請票 | 台帳更新の材料となる申請記録 |

## 2. 順不同のメモ

AIを使う経路では、次の`【AI入力ここから】`から`【AI入力ここまで】`までを、見出し・表を含めて選択します。

【AI入力ここから：未整理メモM01〜M20】

| ID | 引継ぎメモの断片 |
|---|---|
| M01 | 承認された研修備品の申請を見て、貸出台帳に1行追加する仕事。誰が承認するのかは聞き忘れた。 |
| M02 | 台帳には、申請番号、申請部署、備品コード、備品名、数量、貸出予定日、返却予定日、状態を入れていたと思う。 |
| M03 | 返却予定日が空でも、いったん入れて後で直せばよいと前任者から聞いた気がする。 |
| M04 | 別のメモには「空欄が1つでもあれば登録しない」とある。どの項目が必須かは書いていない。 |
| M05 | 新しい行の状態は「予約」だったか「貸出予定」だったか、確認が必要。 |
| M06 | 備品名は備品コードから調べる。以前は記憶で入力したこともある。どの一覧を正とするか不明。 |
| M07 | 同じ申請番号があったら、既存行を上書きしたことがある。ただし、二重登録を防ぐため何も変更しないという話もあった。 |
| M08 | 同じ申請番号でも内容が違う場合がある。そのとき誰へ相談するか書かれていない。 |
| M09 | 編集できないときは、自分のパソコンへ台帳をコピーして、後で戻せばよいという非公式なメモがある。実際に許されるかは不明。 |
| M10 | 台帳を開ける人と編集できる人は同じとは限らない。必要な権限名や申請先は不明。 |
| M11 | 申請番号で検索してから入力していた。部分一致でよいか、完全一致が必要かは書かれていない。 |
| M12 | 数量は数字ならよいのか、0や小数を認めるのか不明。返却予定日が貸出予定日より前の例も想定されていない。 |
| M13 | 入力後は保存して終わり。保存されたことを何で確認するか、完了記録をどこへ残すかは不明。 |
| M14 | 空欄、重複、権限不足のときに、処理を止めるのか、保留として記録するのか、相談先はどこか不明。 |
| M15 | 画面の製品名、メニュー名、ボタン名、シート名はこのメモにない。前任者は口頭で画面を見せていた。 |
| M16 | 「登録」という言葉が、新しい行を作る意味なのか、特定の画面操作名なのか分からない。 |
| M17 | 手順書の版番号、作成者、確認者、見直し日をどこへ書くか決まっていない。 |

【AI入力ここまで：未整理メモM01〜M20】

## 3. この段階で行ってよいこと

- メモを、目的、入力、操作、期待結果、例外、権限、完了条件に分類する
- 矛盾するメモを並べる
- 確認質問と、その質問が必要な理由を作る
- 不足情報を`要確認`と記録する

## 4. この段階で行ってはいけないこと

- `たぶん`、`らしい`という記述を確定ルールへ変える
- 空欄や日付を推測で補う
- この資料にない製品名、画面名、メニュー名、ボタン名、セル位置を作る
- 個人用コピーへの保存、権限回避、既存行の上書きを安全な手順として採用する
- 実在する申請票や台帳を演習へ持ち込む
