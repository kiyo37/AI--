# 業務マニュアル作成演習用：人間確認カードと紙上テストケース

> [!TIP]
> 紙上テストの8〜10列表はGitHubでは横へスクロールします。`ケース`または`申請番号`を共通キーに、`申請内容`、`日付・承認`、`既存行・権限`のまとまりを順に確認してください。

> この資料は演習のために一から作成した架空データです。実在する企業、人物、備品、申請、システムとは関係ありません。

## 1. 開くタイミング

[未整理の引継ぎメモ](manual_handover_notes.md)を読んで確認質問を作り、[レビューシート](../workbooks/manual_usability_review_sheet.md)へ記入した後に開きます。これは、架空の業務責任者、台帳管理担当、申請確認窓口から人が確認した回答をまとめた教材です。

実務では、このカードをそのまま使いません。実際の業務責任者、規程、承認済みの最新資料へ確認します。

AI草案を作成するときは、次の`【AI入力ここから】`から`【AI入力ここまで】`までを、見出し・表を含めて選択します。AI実操作は必須です。紙上テストケースは人間レビュー用のため、この入力範囲に含めません。

## 2. 確認カード

### カードA：目的、範囲、役割

| 項目 | 確認済みの回答 |
|---|---|
| 目的 | 承認済みの研修備品貸出申請を、指定された貸出台帳へ正確に1件ずつ記録する |
| 対象 | 研修備品の新規貸出申請だけ。返却、取消、在庫数変更、申請の承認は対象外 |
| 実行者 | 台帳の編集権限を付与された台帳更新担当 |
| 申請の承認者 | 研修運営責任者。台帳更新担当は承認を代行しない |
| 手順書の確認者 | 研修運営責任者と台帳管理担当 |

### カードB：使用する情報と正しい参照先

| 情報 | 正しい参照先 | 注意点 |
|---|---|---|
| 申請内容 | 承認状態が`承認済み`の貸出申請票 | 承認待ち、差戻し、取消は更新しない |
| 備品名 | 台帳管理担当が指定した最新版の備品マスター | 記憶や過去の台帳行から補わない |
| 既存登録 | 台帳管理担当が指定した貸出台帳 | 個人用コピーを正としない |
| 相談記録 | 指定された例外記録欄 | 実際の保存場所は組織の指定に従う |

この演習には、実製品の名称、画面名、メニュー名、ボタン名、シート名、セル位置は設定されていません。手順書には、`指定台帳を開く`、`申請番号を完全一致で照合する`などの行動と期待結果を書き、架空の画面ラベルを作りません。

### カードC：開始できる条件

次の条件をすべて満たす場合だけ、通常の新規行作成へ進みます。

1. 申請状態が`承認済み`である。
2. 次の7項目がすべて記載されている。
   - 申請番号
   - 申請部署
   - 備品コード
   - 数量
   - 貸出予定日
   - 返却予定日
   - 承認状態
3. 数量が1以上の整数である。
4. 返却予定日が貸出予定日と同日または後である。
5. 備品コードが最新版の備品マスターにある。
6. 申請番号が貸出台帳に存在しない。
7. 台帳更新担当に指定台帳の編集権限がある。

### カードD：新規行へ記録する内容

| 列 | 記録する内容 | 根拠 |
|---|---|---|
| 申請番号 | 申請票の申請番号 | 承認済み申請票 |
| 申請部署 | 申請票の申請部署 | 承認済み申請票 |
| 備品コード | 申請票の備品コード | 承認済み申請票 |
| 備品名 | 備品コードと完全一致する名称 | 最新版の備品マスター |
| 数量 | 申請票の数量 | 承認済み申請票 |
| 貸出予定日 | 申請票の貸出予定日 | 承認済み申請票 |
| 返却予定日 | 申請票の返却予定日 | 承認済み申請票 |
| 状態 | `貸出予定` | この確認カード |

入力後は8項目を根拠資料と一つずつ照合します。指定された通常の保存方法で保存した後、対象の申請番号が完全一致で1行だけ存在し、8項目が一致することを再確認します。

### カードE：空欄・不正値の分岐

必須項目の空欄、数量0・小数・数字以外、返却予定日が貸出予定日より前、備品マスターにないコードのいずれかがあれば、台帳を変更しません。推測で補わず、問題項目と申請番号を指定された例外記録欄へ記録し、`申請確認窓口`へ相談します。

申請確認窓口から修正済みの承認済み申請票が示された場合は、その最新版を使って最初から確認し直します。台帳更新担当が申請票を書き換えたり、承認したりしません。

### カードF：重複の分岐

申請番号は完全一致で検索します。

| 状況 | 行うこと | 完了状態 |
|---|---|---|
| 同じ申請番号の既存行が1行あり、8項目が今回の根拠資料とすべて一致 | 新しい行を追加せず、既存行も変更しない。例外記録欄へ`同一内容の重複確認・更新なし`と記録 | 台帳は変更なし。二重登録していない |
| 同じ申請番号の既存行が1行あり、1項目でも異なる | 追加も上書きもせず、相違項目を例外記録欄へ記録して`台帳管理担当`へ相談 | 台帳は変更なし。相談中 |
| 同じ申請番号の既存行が2行以上ある | 内容が同じでも追加・上書き・削除をせず、件数を例外記録欄へ記録して`台帳管理担当`へ相談 | 台帳は変更なし。相談中 |

### カードG：権限不足の分岐

指定台帳が閲覧専用である、編集が拒否される、または権限が不明な場合は台帳を変更しません。個人フォルダーへのコピー、別台帳の作成、他人の認証情報の利用、権限設定の自己変更を行わず、申請番号と発生状況を例外記録欄へ記録して`台帳管理担当`へ相談します。

権限を持つ別担当者へ処理を引き継ぐ場合は、組織が指定した方法で行います。演習では実際の共有や引継ぎを行いません。

### カードH：完了、停止、記録

| 場面 | 完了と判断できる状態 |
|---|---|
| 通常登録 | 保存後の台帳に申請番号が1行だけあり、8項目が根拠資料と一致する |
| 同一内容の重複 | 台帳を変更せず、重複確認と更新なしを例外記録欄へ残した |
| 空欄・不正値・内容が異なる重複・権限不足 | 台帳を変更せず、問題と相談先を例外記録欄へ残した。相談結果が出るまでは処理未完了 |

次の場合は、その場で変更を止めます。

- 参照している申請票、備品マスター、台帳が最新版か分からない
- 入力根拠が一致しない、または必要項目を確認できない
- 既存行を上書き・削除しなければ進めない
- 権限、保存先、共有範囲、相談先が分からない
- 意図しない変更や情報漏えいの疑いがある

誤変更や情報漏えいの疑いがある場合は、自己判断で履歴や証拠を削除せず、台帳管理担当と組織の事故連絡窓口へ連絡します。

### カードI：版管理

手順書には、文書名、版番号、作成日、作成者の役割、確認者の役割、対象範囲、改訂履歴を記載します。

- AIまたは手作業で作った未確認版：`草案 v0.1`
- 確認カードと照合した紙上テスト用：`テスト版 v1.0`
- 紙上テストの指摘を反映した版：`完成版 v1.1`

版番号が上がっても、実務利用の承認を自動的に得たことにはなりません。この演習の`完成版`は研修成果物であり、実在業務で利用できる正式文書ではありません。
