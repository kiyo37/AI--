# Zoom会議の文字起こし・議事録作成 準備ガイド

最終確認日：2026年8月9日

このガイドは、Zoom会議の発言を文字にし、その文字起こしから安全に議事録を作る方法を学ぶためのものです。Zoomの機能、画面名、対象プラン、管理者設定は変わるため、利用前に末尾の公式情報と組織の契約・規程を確認してください。

> **基本演習ではZoomへ登録しません。** 教材内の保存済み架空文字起こしを、条件を確認した承認済み対話AIへ入力して議事録を生成・改善します。Zoom実機は任意ですが、AIの実操作は必須です。実際のZoom会議で文字起こしや録画を行うのは、組織承認、管理者設定、ホスト権限、参加者への事前説明、法令・社内規程上必要な同意、保存・削除方法がすべて確認できた場合だけの任意発展です。実在の参加者を予告なく録音・録画・文字起こししません。

## 1. このガイドでできるようになること

- 字幕、文字起こし、録画、AI要約の違いを説明できる
- Zoomを使わなくても、架空の文字起こしから議事録を作れる
- 承認済み環境では、会議前・会議中・会議後に必要な確認ができる
- 文字起こしの誤認識を見つけ、「決定」「依頼」「未決」を分けられる
- 録画、文字起こし、議事録の保存先・閲覧者・保持期間を分けて管理できる

| 読む人 | 先に読む範囲 | 次に行うこと |
|---|---|---|

| 承認済み任意実機のホスト・管理者 | 1〜13、16 | 組織の実環境で開始・停止・権限・終了処理まで事前検証する |
| 組織で任意実機を承認・管理する担当者 | 1〜5、14〜16 | 任意実機を行うかを担当部門と判断する |

基本演習では、Zoomのライセンスや管理者画面を理解する必要はありません。保存済み文字起こしを対話AIで処理し、誤変換の検証、修正指示、人間レビューへ集中します。任意実機は、個人学習では本人が条件を確認し、組織利用では担当部門が承認した場合だけ行います。

## 2. 最初に学習ルートを選ぶ

| ルート | 対象 | アカウント | 扱うデータ |
|---|---|---|---|
| 基本演習（個人学習・組織利用、必須） | すべての人 | Zoomアカウントは不要。承認済み対話AIは必要 | [保存済み架空文字起こし](../sample-data/video_meeting_transcript.md)と[照合メモ](../sample-data/video_meeting_verification_notes.md) |
| 任意の実機確認 | 承認済み企業環境の指定ホスト・指定参加者 | 組織が発行・承認したZoomアカウント | 教材の架空台本を読み上げる。ただし、取得される声、表示名、顔、接続情報は実在参加者のデータとして扱う |

個人アカウントを組織利用の代替にしません。Zoomの無料登録や試用開始は学習の完了条件ではありません。Zoomを使えない場合は保存済み架空文字起こしを承認済み対話AIで処理する基本演習を行います。対話AIを使えない場合は、環境準備が整うまで基本演習を停止します。

任意実機は、教材の会話内容が架空であっても「完全な架空データだけを使う基本演習」には含めません。実在参加者の声や表示名等を取得するため、[第02章 セキュリティとプライバシー](../02_security_and_privacy.md)の学習後、担当部門が別途承認した環境で、指定された人だけが実施します。

## 3. 似ている機能を区別する

| 用語 | 初心者向けの意味 | 会議後に残るか | この教材での位置づけ |
|---|---|---|---|
| 自動字幕（captions） | 発言を会議中に読みやすく画面へ表示する機能 | 字幕自体の保存・ダウンロード機能は2026年5月18日に廃止。録画の再生画面で字幕が表示される場合はあるが、保持するMeeting transcriptとは別 | 聞き取り支援。議事録の保存素材とは扱わない |
| Meeting transcript | 会議中の音声を文字にし、保持・保存できる「会議文字起こし」 | 管理者・ホストの設定、権限、保持期間による | Zoom任意実機で使う主な文字起こし機能 |
| 録画 | 映像、音声、画面共有などを記録すること | クラウドまたは端末に残る。設定によって記録対象が異なる | 必要性とリスクを別に審査。文字起こしのためだけに自動で録画しない |
| クラウド録画の音声文字起こし | クラウド録画の音声から作られる時刻付きテキスト | 録画とともにZoom上へ残り、VTTとして扱える | 録画が承認された場合だけの任意発展 |
| Meeting Summary（AI会議要約） | 音声からAIが会議の要点をまとめる機能 | 設定した共有先、保持・削除設定による | ライセンス・管理者設定がある場合だけの任意発展。完成議事録ではない |
| 議事録 | 人が確認し、決定事項、タスク、未決事項を整理した業務文書 | 組織の文書管理ルールで保存 | 最終成果物。責任者が承認する |

Zoom公式は、保存する音声テキストには字幕ではなくMeeting transcriptを使うよう案内しています。詳細は[字幕の保存に関するZoom公式案内](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0063899)と[Meeting transcriptの有効化](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0085675)で確認します。

## 4. 操作前に組織で決めること

表示された通知へ参加者が応答したことだけで、すべての地域・契約・利用目的における法的同意が満たされるとは断定できません。対象国・地域、参加者との関係、社内規程、契約に応じて、法務、個人情報保護、情報セキュリティ、労務などの専門部署へ確認してください。

| 決める項目 | 記入・確認する内容 |
|---|---|
| 目的 | 例：決定事項と担当タスクを確認するため |
| 取得するもの | 文字起こしだけか、音声・映像・画面共有・チャットも含むか |
| 対象区間 | 会議全体か、特定議題だけか。休憩・機密議題では止めるか |
| 参加者への説明 | 取得目的、記録対象、利用先、閲覧者、保存場所、保持期間、削除方法、AI利用の有無 |
| 必要な同意 | 誰から、いつ、どの方法で得て、どこへ記録するか |
| 参加しない選択肢 | 記録なしの別会議、書面回答など、組織が決めた代替方法 |
| 閲覧・共有 | ホスト、議事録担当、承認者など必要最小限の人だけにする方法 |
| 保持・削除 | 録画、文字起こし、AI要約、議事録、ダウンロードの各期限と削除責任者 |
| 誤りの訂正 | 話者、固有名詞、数字、否定表現等を誰が確認・訂正するか |
| 事故時の連絡 | 誤共有、無断記録、過剰保存が起きた際の正式窓口 |

### 外部参加者・電話参加者がいる場合

- 招待状と会議冒頭の両方で説明し、画面上の表示だけに頼らない
- 電話参加者は画面通知を読めないため、音声で目的、記録対象、停止・退出方法を伝える
- 通訳、委託先、顧客、海外拠点を含む場合は、契約や対象地域の追加確認を行う
- 録画を使う場合、Zoomは参加者へ録画通知を表示または音声で通知します。ただし、通知と組織に必要な同意手続は同じ意味ではありません。詳細は[Zoom公式の録画通知](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0068228)と[録画への同意画面](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0059819)を確認します

### 機密情報・個人情報を含む会議

表示名、声、顔、所属、発言内容、文字起こしは、内容や対象地域によって個人情報・機密情報として扱う必要があります。文字になると検索・コピー・転送しやすくなるため、音声より安全になるわけではありません。

- 基本演習では、実在する顧客、従業員、患者、取引、障害、契約などの情報を扱わない
- 人事評価、健康、金融、法務相談、認証情報などを含む議題では、取得の必要性を専門部署と個別に判断する
- パスワード、APIキー、認証コードを会議で読み上げたり、画面共有したり、文字起こしへ残したりしない
- 議題の一部だけが取得対象外なら、開始・停止の担当と切替時刻を事前に決める
- 録画、未確認文字起こし、AI要約、確定議事録は内容とリスクが異なるため、同じ共有設定を自動適用しない

## 5. 任意実機の環境確認

### 5.1 必要条件

- [ ] 組織がZoom、対象機能、アカウント、利用目的を承認している
- [ ] 管理者が契約プラン、提供地域、対応言語、アプリ版を確認している
- [ ] 指定されたホストだけが操作する
- [ ] デスクトップアプリは組織が承認した配布元・方法で導入済みである
- [ ] アカウントへ組織指定のSSO・MFAでサインインできる
- [ ] 教材の架空台本と、Zoomを使えない場合の保存済み架空文字起こしがある。声、表示名等は実在参加者データとして扱う
- [ ] 文字起こし、録画、AI要約ごとの保存先、閲覧者、保持期間、削除方法を確認した
- [ ] 参加者への事前説明と、必要な同意の取得・記録方法を確認した

Meeting transcriptは初期状態で有効とは限らず、ホストまたは管理者による明示的な有効化が必要です。契約・権限等の現在条件は[Zoom公式のMeeting transcript設定](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0085675)で確認してください。

### 5.2 デスクトップ、Web App、Webポータルの違い

| 場所 | 主な用途 | 本教材での扱い |
|---|---|---|
| デスクトップアプリ | 会議を開始し、文字起こしを開始・表示・停止・許可時に保存 | 任意実機の標準手順 |
| Zoom Web App | ブラウザ内で会議へ参加 | 機能提供や表示位置がアカウント・版・段階的提供で異なり得る。同じ環境で開始から終了まで確認できた場合だけ使用 |
| Zoom Webポータル | Meeting transcriptの設定、保持・権限、会議後の文字起こし等の管理 | 管理者・ホストが事前・事後に使用 |

ZoomのリリースノートにはWeb Appの文字起こし操作に関する更新も掲載されていますが、画面は変わる可能性があります。[Zoom Meetingsリリースノート](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0080363)と組織の実画面を利用前に照合します。メニューが見つからない場合、個人アカウントや未承認アプリへ切り替えず、基本演習へ戻ります。

## 6. 管理者・ホストの事前設定

操作名は2026年8月9日時点の公式案内に基づく例です。日本語表示、管理者画面の更新、段階的提供により名称や場所が異なる場合があります。

1. Zoom Webポータルへ、組織指定の管理者またはホストアカウントでサインインします。
2. 管理者は `Admin Center → Settings → Meeting → In Meeting (Advanced)`、個人設定を許可されたホストは `My account → Settings → Meeting → In Meeting (Advanced)` を確認します。
3. `Meeting transcript` が承認された方針どおりになっているか確認します。灰色で変更できない場合は、上位の管理者設定が固定しています。自分で回避しません。
4. 次を管理者と確認します。
   - 自動生成する会議の範囲
   - 文字起こし開始時のカスタム説明文
   - 指定日数後の自動削除
   - ホストが会議後に閲覧・削除・ダウンロードできるか
   - 会議中に文字起こしを見られる人
   - 端末へ保存できる人（ホストだけ、共同ホストまで、内部参加者等）
5. 演習では閲覧・保存権限を必要最小限にし、外部参加者や全参加者への保存許可を安易に選びません。
6. 設定値、確認者、確認日を個人の学習メモまたは組織の承認記録へ残します。設定変更そのものは管理者の変更手順・承認記録に従います。

設定項目の意味と現在の画面は[Zoom公式のMeeting transcript設定](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0085675)を参照してください。

Zoom上のカスタム説明文や確認ボタンは、製品上の通知・応答を記録する機能です。それだけで、法令、契約、就業規則等で必要な説明や同意をすべて満たしたとは扱いません。組織が定めた説明文、同意方法、記録方法、代替参加方法を優先します。

## 7. 会議前チェックリスト

### 主催者

- [ ] 会議の目的、議題、参加者、議事録承認者を決めた
- [ ] 文字起こし担当と、人が取る補助メモの担当を分けた
- [ ] 決定、担当、期限を会議中に復唱する進行ルールを伝えた
- [ ] 人名、部署名、略語、製品名の用語表を用意した
- [ ] 参加者全員へ、取得目的、対象、AI利用、閲覧者、保存、保持、削除を事前案内した
- [ ] 必要な同意と、記録を希望しない人への組織指定の代替方法を確認した
- [ ] 外部・電話・途中参加者へ説明を届ける方法を決めた
- [ ] 休憩、機密議題、個人相談など、停止する区間を決めた
- [ ] 誤作動時に文字起こしを止め、紙上メモへ切り替える人を決めた

### 参加者への案内例

```text
この会議では、決定事項と担当タスクを確認する目的で、発言の文字起こしを行います。
映像・音声の録画は行いません。文字起こしは議事録担当者と会議責任者が確認し、
組織指定の保存場所で○日間保持した後、規程に従って削除します。
AI要約は使用しません。発言者名、数字、期限、決定事項は会議後に人が確認します。

```

この例をそのまま法的同意文として使用しません。実際の取得対象、保存、参加者、対象地域、契約に合わせて専門部署が確認します。

## 8. 会議中の操作（デスクトップアプリ）

### 8.1 開始する

1. ホストが承認済みアカウントで会議を開始します。
2. 会議冒頭で、文字起こしの目的、記録対象、利用先、停止区間、問い合わせ先を口頭で説明します。
3. 必要な同意が確認できない参加者がいる場合は開始せず、組織指定の代替へ切り替えます。
4. 会議コントロールの `More（詳細）→ Transcript（文字起こし）` を選びます。
5. 文字起こしが開始されたことを示す表示と、参加者側への案内を確認します。表示が不明なら、発言を続けず停止して確認します。
6. `Transcript` パネルを開き、最初の台本発言で文字の更新、言語、話者候補、数字を確認します。時刻情報が画面や出力にある場合は確認位置として使い、ない場合は重要発言のおおよその経過時刻を人の補助メモへ残します。

ホストによる開始・停止、参加者からの開始依頼、パネル表示、許可された端末保存の現行手順は[Zoom公式「Using Meeting transcripts」](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0085682)で確認します。

### 8.2 会議中に人が行うこと

| 確認対象 | 進行例 | なぜ必要か |
|---|---|---|
| 決定と提案 | 「これは決定です／まだ提案です」と復唱する | AIが両者を混同しやすい |
| 担当と期限 | 「担当は業務管理担当、期限は8月12日です」と復唱する | 担当なし・期限なしのタスクを防ぐ |
| 数字と否定 | 「10件です」「自動送信**しません**」と明確に言う | 誤認識時の影響が大きい |
| 話者 | 一人ずつ発言し、表示名を確認する | 同時発話や同じ部屋の集音では話者を誤りやすい |
| 根拠位置 | 重要発言の時刻を補助メモへ残す | 会議後に録音・文字起こしを探す手掛かりになる |
| 不明点 | 「聞き取れないため要確認」と記録する | 推測で埋めないため |

時刻は確認箇所を探す手掛かりであり、発言内容が正しいことの証明ではありません。権限のある記録、人の補助メモ、発言者確認と組み合わせます。

### 8.3 一時停止・終了する

- 対象外の議題へ入る前に、ホストが文字起こしを停止します
- 画面右上のTranscript表示にある停止操作を選び、確認画面を確認します
- その場で削除する選択肢が表示された場合も、独断で選ばず組織の保持・事故対応手順に従います
- 再開前に参加者へ再度知らせ、必要な確認を行います
- 会議終了前に、決定、タスク、未決事項を人が読み上げて確認します

## 9. Web Appから参加する場合

Web Appのボタン位置や利用可否を推測しません。実際に使う契約・ブラウザ・権限で次を事前確認できた場合だけ使います。

1. ホストとして文字起こしを開始・停止できるか
2. 参加者側へ文字起こし中であることが明確に表示されるか
3. 外部・未サインイン・電話参加者の扱いが組織方針どおりか
4. 誰が表示・保存できるか
5. 会議後にどこへ残り、誰が削除できるか

一つでも確認できない場合は、承認済みデスクトップアプリをホストが使用するか、保存済み架空文字起こしへ切り替えます。ブラウザ拡張機能や外部の文字起こしボットを代替として無断追加しません。

## 10. 会議後の取得・確認・削除

### 10.1 文字起こしを取得する

| 状況 | 取得方法 | 注意 |
|---|---|---|
| 会議中の端末保存を許可 | Transcriptパネル下部の `Save transcript` からTXTを保存 | 保存できる人は管理者設定次第。端末上の別コピーとして管理する |
| 会議後の保持を許可 | Webポータルの `Recordings and Transcripts → Transcripts` 等から権限のあるホストが確認 | 表示対象やVTTの取得可否は生成方法・設定により異なる |
| 保存権限なし | ダウンロードしない | スクリーンショット、コピー＆ペースト、外部ツールで回避しない |

Meeting Summary用に保持した文字起こしの検索、ダウンロード、削除については[Zoom公式の会議文字起こし管理](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0076632)も確認してください。リンク先には旧「AI Companion」表記が残る場合があります。

### 10.2 AIへ渡す前に人が直す

1. 原文ファイルは上書きせず、「未確認」と明記してアクセス制限する。
2. 次の箇所を優先して確認する。
   - 話者名・部署
   - 人名、製品名、社内略語
   - 数量、金額、日付、期限
   - 「する／しない」「可能／不可能」などの否定
   - 決定、提案、依頼、保留の区別
   - 担当者と期限の組合せ
3. 権限のある録音・録画、会議中の補助メモ、議題、発言者への確認で訂正する。
4. 確認できない内容は消したり推測したりせず、「要確認」と時刻を残す。
5. 組織が承認したAIだけへ、許可されたデータ分類の範囲で渡す。外部AIへ貼り付ける前に、文字起こし全体を入力してよいか確認する。
6. AIが作った議事録を元文字起こしと訂正記録へ照合し、会議責任者が承認する。

### 10.3 共有・保持・削除を終える

- [ ] 録画、文字起こし、AI要約、完成議事録を別の情報として管理した
- [ ] 閲覧者と共有先を必要最小限にした
- [ ] 自動共有、招待者へのメール送信、外部共有が意図せず有効でないか確認した
- [ ] パソコンのダウンロード、同期フォルダ、ごみ箱、メール添付等のローカルコピーを確認した
- [ ] 組織の保持期間に従い、削除または正式保管した
- [ ] 削除が必要な場合、原本と複製の両方について実施者・確認者・日時を記録した
- [ ] 共用・貸与端末とWebポータルからサインアウトした
- [ ] 誤共有、無断取得、削除漏れの疑いがあれば、追加コピーを作らず正式窓口へ報告した

「共有リンクを無効にすること」と「元データを削除すること」は別の操作です。どちらが必要かを組織の手順で確認します。

## 11. 任意発展A：クラウド録画の音声文字起こし

この方法は、会議自体をクラウド録画し、その音声から時刻付きのVTTを作るものです。Meeting transcriptだけを使う方法より取得情報と影響範囲が大きくなるため、単に議事録を作りやすくする目的だけで選びません。

| 確認 | 内容 |
|---|---|
| 契約・設定 | 対象となる有料アカウント、クラウド録画、音声文字起こしが必要。現在条件は公式情報で確認 |
| 記録対象 | 映像、音声、チャット、画面共有等が設定により含まれ得る |
| 参加者通知 | 録画開始時に画面・音声の通知がある。組織に必要な説明・同意は別途確認 |
| 出力 | 処理後、時刻付きVTTが録画一覧に表示される。話者や文言を人が編集可能 |
| 共有 | 録画共有時に文字起こし表示を許可するか確認 |
| 保持 | クラウド録画、VTT、ダウンロードをそれぞれ管理・削除 |

現在の対象条件、対応言語、編集方法は[Zoom公式「Using audio transcription for cloud recordings」](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064927)で確認します。VTT等の形式は[録画ファイル形式の公式説明](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064394)を参照してください。

## 12. 任意発展B：Meeting Summary（AI会議要約）

Meeting Summaryは、音声から文字情報を作り、AIで会議要約を生成する機能です。Zoomの2026年6月22日付リリースノートでは「AI Companion」のブランド名を段階的に終了し、設定ページを「AI」へ変更すると案内されていますが、機能自体は継続します。公式ヘルプの記事名や本文には旧表記が残る場合があります。旧名称や固定メニュー名は暗記せず、利用時点の「AI」「Meeting Summary」等の表示を公式情報と管理画面で確認します。対象ライセンス、管理者設定、提供地域等に依存し、機能が表示されない場合は個人契約や試用で回避しません。

### 使用前に追加確認すること

- Meeting Summaryと関連するAI機能が組織で承認・有効化されているか
- 自動開始が有効か。意図しない会議で動き始めない設定か
- 要約の自動共有先がホストだけか、共同ホスト・内部招待者・外部招待者までか
- メール本文へ要約を載せるか、認証が必要なリンクだけにするか
- 外部共有制限、IP制限、自動削除が方針どおりか
- 画面共有のOCR（画面上の文字を読み取る機能）や会議チャットを要約材料に含めるか
- 第三者モデル、処理地域、契約、データ取扱いを専門部署が確認したか

AI要約には、抜け、話者の取り違え、決定と提案の混同、存在しない担当・期限の追加があり得ます。必ず文字起こしと人のメモへ戻り、完成議事録とは別に扱います。公式の利用条件と操作は[Meeting Summaryの利用方法](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058013)、共有・保持・データ利用の設定は[Meeting Summaryの有効化](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0057960)、名称変更は[Zoom Meetingsリリースノート](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0080363)で確認してください。

## 13. トラブル時の分岐

| 状況 | まず確認すること | 対応 |
|---|---|---|
| Transcriptが表示されない | 契約、管理者設定、ロック、ホスト権限、アプリ版 | 設定を回避せず管理者へ連絡。基本演習へ切替 |
| 参加者には開始依頼しか表示されない | その人がホストか、参加者権限か | ホストへ依頼。開始のためだけに参加者へ権限を追加しない |
| Web Appで手順が一致しない | 段階的提供、ブラウザ、組織設定 | 事前検証済みデスクトップか保存済み文字起こしを使う基本演習へ切替 |
| 日本語の認識が不安定 | 発話言語、マイク、雑音、同時発話 | 一人ずつ明瞭に話し、重要事項を復唱。人の補助メモを残す |
| 話者が違う | 表示名、同室マイク、同時発話 | 推測で直さず、許可された記録か本人へ確認 |
| 数字・日付・否定が矛盾 | 別時刻の復唱、補助メモ、発言者 | 確認できるまで「要確認」 |
| 電話参加者へ説明できていない | 音声案内と必要な応答の実施 | 開始・継続せず、組織手順に従う |
| 外部参加者が保存できる | 閲覧・端末保存権限 | 直ちに管理者・ホストが確認。漏えいの疑いは正式窓口へ報告 |
| 誤って実データを取得した | 共有範囲、保存先、複製 | 追加のコピーやAI入力を止め、事故対応窓口へ報告 |
| AI要約だけが残り、根拠を確認できない | 文字起こし、補助メモ、参加者確認の可否 | 要約を事実として採用せず、「要確認」または再確認 |

## 14. Zoom実機を使わない基本演習

1. [テレビ会議の議事録作成演習](../exercises/video_meeting_minutes_exercises.md)を開きます。
2. [収録済みの自動文字起こし（未確認）](../sample-data/video_meeting_transcript.md)を読みます。
3. 数字、期限、否定、話者、決定と提案に印を付けます。
4. [人が確認した照合メモ](../sample-data/video_meeting_verification_notes.md)と照合し、誤りを訂正します。
5. 決定事項、タスク、未決事項、要確認事項、根拠時刻を表へ整理します。
6. 個人学習では本人が条件を確認した対話AI、組織利用では組織指定の承認済み対話AIへ、架空文字起こしだけを入力します。
7. AI案と文字起こしを人が照合し、Word用議事録とExcel用タスク一覧を完成させます。

保存済みAI出力は、誤り分析やトラブルの切り分けにだけ使用します。保存済みAI出力の点検だけでは、指示、生成、修正というAIの実操作を経験できないため、この基本演習の代替や完了条件にはしません。

この方法でも、「取得する」「誤りを直す」「構造化する」「人が承認する」という実務の流れを学べます。Zoom画面の暗記が学習目的ではありません。
