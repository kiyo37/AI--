# Microsoft Copilot利用環境準備ガイド

## 1. このガイドの目的

Microsoft Copilotを教材の比較演習で安全に使えるよう、ブラウザ、アカウント、ライセンス、MFA、データ保護、架空データでの動作確認を整理します。

> MicrosoftのCopilot製品名、URL、ライセンス、画面、提供機能は変わります。本書の確認日は**2026年8月2日**です。研修実施前に最新のMicrosoft公式情報、組織の契約、管理者設定を確認してください。

## 2. 先に製品とアカウントを区別する

「Copilot」という名前だけでは、データ条件や利用機能を判断できません。

| 利用場面 | 主なアカウント | 確認すること |
|---|---|---|
| Microsoft Copilotの個人利用 | 個人Microsoftアカウント | 個人向けの利用条件、履歴、プライバシー、接続機能 |
| Microsoft 365 Copilot Chatの組織利用 | Microsoft Entraの仕事・学校用アカウント | 組織の対象契約、管理設定、Web検索、保持、監査 |
| Microsoft 365 Copilotの組織利用 | 管理者がライセンスを割り当てた仕事・学校用アカウント | 対象ライセンス、Microsoft Graphへのアクセス権、各アプリでの利用可否 |

**Microsoft Graph**は、Microsoft 365内のメール、ファイル、予定などへ、利用者の権限に基づいてアクセスするための仕組みです。Copilotが参照できる範囲は、元のMicrosoft 365権限設計に影響されます。

## 3. インストールは必要か

ブラウザ利用なら、原則として追加インストールは不要です。

| 方法 | 入口 | インストール | 用途 |
|---|---|---|---|
| 組織向けブラウザ | <https://m365.cloud.microsoft/> | 不要 | 本教材で推奨。仕事・学校用アカウントで利用 |
| 個人向けブラウザ | <https://copilot.microsoft.com/> | 不要 | 個人学習。業務データは入力しない |
| Windows・モバイルアプリ | 公式ストア | 任意 | 組織の端末管理と配布ルールを確認して導入 |
| Word、Excel等のアプリ内 | Microsoft 365アプリ | 契約・更新・設定による | 対象ライセンスと管理者設定を確認 |

ブラウザ版だけで演習目的を満たせる場合、アプリを追加しません。非公式アプリ、検索広告、第三者のCopilot風サービスを使わないでください。

## 4. 登録・利用前の承認

### 4.1 企業研修・業務利用

- 受講者へ個人Microsoftアカウントの新規登録を強制しません。
- 管理者が発行した仕事・学校用アカウントと、割り当て済みの利用権を使います。
- 情報システム、セキュリティ、法務・個人情報等が定めた入力範囲を確認します。
- Web検索、ファイルアップロード、接続アプリ、エージェントなどは、利用可否とデータ経路を管理者へ確認します。
- 共有サイトやOneDrive・SharePointの権限が広すぎないかを、本番利用前に点検します。

### 4.2 個人学習

- 本人が個人向けの利用条件、費用、年齢・地域条件、プライバシー情報を確認します。
- 勤務先・顧客・学校のアカウントを、許可なく個人学習へ使いません。
- 教材の架空データだけを入力し、Outlook、OneDrive等への接続は演習に必要な場合だけ確認して有効化します。

## 5. 企業アカウントの準備

### 5.1 管理者が行う確認

1. 対象ユーザーと利用目的を決めます。
2. 対象のMicrosoft 365契約と、必要なCopilotライセンスを公式文書で確認します。
3. 必要な場合はMicrosoft 365管理センターで利用者またはグループへライセンスを割り当てます。
4. Copilotの管理設定、Web検索、接続機能、共有、保持、監査、アプリ権限を確認します。
5. SharePoint、OneDrive、Teams等の既存アクセス権を見直します。
6. 少人数の架空データ演習から始め、入力禁止、停止、相談、ログ確認の手順を周知します。

ライセンス要件や反映時間を本書で固定せず、Microsoftの最新のライセンス文書と管理センター表示を正とします。

### 5.2 受講者が行う確認

1. 管理者から指定されたブラウザで <https://m365.cloud.microsoft/> を開きます。
2. 指定された仕事・学校用アカウントでサインインします。
3. 画面上の氏名・組織を確認し、個人アカウントへ切り替わっていないことを確かめます。
4. Copilot Chatが表示されるか確認します。表示されない場合は、個人アカウントへ切り替えず管理者へ連絡します。
5. 組織の利用ルール、入力禁止情報、保存・共有、相談先を確認してから架空データを入力します。

## 6. 個人アカウントの準備

1. ブラウザで <https://copilot.microsoft.com/> を開きます。
2. 保存や個人向け機能の利用にサインインが必要な場合、本人が管理するMicrosoftアカウントを使います。
3. Microsoftアカウントのセキュリティ画面で2段階認証と回復情報を確認します。
4. 履歴、プライバシー、接続サービス、共有の設定を公式案内で確認します。
5. 架空データで動作を確かめます。

個人向けCopilotと、仕事・学校用アカウントで使うMicrosoft 365 Copilot／Copilot Chatのデータ保護条件を同一視しません。

## 7. MFAの設定

**MFA（多要素認証）**は、パスワード以外の要素も使って本人を確認する仕組みです。

### 7.1 企業アカウント

- Microsoft 365管理者がMFAを有効にし、利用者はサインイン時の案内に従って組織承認済みの方法を登録します。
- 使用できる認証アプリ、パスキー、セキュリティキー等は組織方針を優先します。
- 登録端末を紛失・交換した場合は、自己流で回避せず管理者へ連絡します。

### 7.2 個人アカウント

- Microsoftアカウントのセキュリティ設定から2段階認証を確認します。
- 回復手段を複数準備し、回復コードや認証情報を安全に保管します。
- パスワード、承認通知、認証コードを共有しません。

## 8. データ設定と権限の確認

Microsoft 365 CopilotとCopilot Chatの組織利用には、契約上の**Enterprise Data Protection（企業データ保護）**が適用されるとMicrosoftは説明しています。ただし、具体的な統制はプランと設定で異なり、Web検索クエリや外部エージェントには別の取扱条件が関係する場合があります。

| 確認領域 | 確認する質問 |
|---|---|
| 現在のアカウント | 個人用か、対象組織の仕事・学校用か |
| 参照権限 | Copilot以前から共有範囲が広すぎるファイルはないか |
| Web検索 | 有効か。検索クエリの取扱いを管理者が確認したか |
| ファイル | 保存先、保持、共有、削除、アクセス権は何か |
| ログ・監査 | 誰が確認でき、どの規程で保持するか |
| エージェント・接続 | 第三者の規約、権限、実行可能な操作を確認したか |
| 人間レビュー | 回答、引用、宛先、外部送信、実行操作を誰が承認するか |

データ保護機能があることは、全情報を無条件に入力できることや、AI回答が正しいことを意味しません。

## 9. 架空データでの動作確認

新しいチャットへ次だけを入力します。

```text
架空の青葉サービス社では、7月15日に社内AI研修を開催します。
申込締切は7月10日です。時刻、会場、URLは未決です。

この情報だけを使い、案内文の草案を作ってください。
未決事項を推測せず「要確認」と表示してください。
```

人が次を確認します。

- 開催日と締切が一致する
- 時刻、会場、URLを創作していない
- 仕事・学校用と個人用のアカウントを取り違えていない
- ファイル接続、メール送信、予定登録などを自動実行していない
- 出力を外部共有していない

演習後、利用したアカウント種別、製品表示名、確認日、人間の修正箇所を記録します。

## 10. 利用できない場合の代替

| 状況 | 対応 |
|---|---|
| ライセンス未割当て・機能未表示 | 管理者へ確認し、個人版へ切り替えず紙上演習または講師配布出力を使う |
| 組織が利用を許可していない | 登録・回避操作をせず、ChatGPT等の承認済みツールまたは紙上演習へ変更 |
| MFAを完了できない | 管理者またはMicrosoft公式サポートへ相談。認証情報を借りない |
| 研修中の障害 | 事前保存した架空出力を使い、人間レビューと比較を継続 |
| 個人アカウントを作りたくない | 登録不要の紙上演習、講師画面共有、架空出力比較を選ぶ |

講師がデモする場合も、受講者へ認証情報を共有しません。

## 11. 準備完了チェック

- [ ] 利用するCopilotの種類とアカウント種別を記録した
- [ ] 企業利用では管理者の承認と必要なライセンス割当てを確認した
- [ ] ブラウザの公式URLからアクセスした
- [ ] MFAと回復方法を設定した
- [ ] 既存の共有権限、Web検索、ファイル、ログ、接続機能を確認した
- [ ] 架空データで動作確認し、人が出力を照合した
- [ ] 利用不可・障害時の代替方法を用意した
