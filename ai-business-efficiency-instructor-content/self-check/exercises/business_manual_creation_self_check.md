> **[学習マップ](../../START_HERE.md) ｜ 自己点検 ｜ 演習 4 / 8・成果物作成**
> [← 演習本文：引継ぎメモから業務マニュアル](../../exercises/business_manual_creation_exercises.md) ・ [自己点検一覧](../README.md) ・ [次の演習：プロンプト受入テスト →](../../exercises/prompt_acceptance_testing_exercises.md)

このファイルは、[業務マニュアル作成演習](../../exercises/business_manual_creation_exercises.md)の自己点検資料です。自力課題の前には完成版を開かず、確認質問、確認カードとの照合、テスト版の紙上実行が終わった後の振り返りに使います。

すべて教材用の架空データです。実在する手順、台帳、申請、製品画面へ置き換えて、未承認のAIへ入力しないでください。

## 1. この演習で確認すること

この演習は採点しません。質問の数や文章の美しさではなく、自分が次の行動を実演できたかを確認します。

- 未整理メモの矛盾を、AIや自分の推測で解決しない
- 手順作成前に、業務責任者へ確認する質問を作る
- 確認済みの資料を、未確認メモより優先する
- 操作と期待結果を対にして書く
- 正常、空欄、重複、権限不足で、台帳変更の可否を分ける
- 入力にない製品名、画面名、メニュー名、ボタン名、セル位置を削除する
- 作成時とは役割を切り替えた紙上実行から、文書の不足を発見する
- 草案、テスト版、完成版を分け、改訂理由を残す

この自己点検は、自分で対話AIへ質問候補とマニュアル草案を生成させ、確認カードとの照合と紙上テストを終えた後に行います。保存済み問題例だけを手で直しても演習完了にはなりません。

## 2. 確認質問の例

表現や順序は同じでなくても構いません。重要なのは、各質問が手順上の判断へつながり、回答を誘導していないことです。

| No. | 確認質問の例 | 主なメモID | 確認しない影響 | 主な確認先 |
|---:|---|---|---|---|
| 1 | この業務の目的と対象範囲、対象外は何か | M01 | 返却や承認まで誤って扱う | 業務責任者 |
| 2 | 台帳を更新できる役割と、申請を承認する役割は誰か | M01、M10、M18 | 権限外の更新・承認 | 業務責任者、台帳管理担当 |
| 3 | 更新に使ってよい申請状態は何か。承認待ち・差戻し・取消はどうするか | M18 | 未承認申請の登録 | 業務責任者 |
| 4 | 開始前に必要な申請項目は何か | M02、M03、M04 | 欠損した行の登録 | 申請確認窓口 |
| 5 | 数量の許容条件と、日付の前後関係は何か | M12 | 不正数量、逆転日付の登録 | 申請確認窓口 |
| 6 | 備品名を確認する正しい最新版の資料は何か | M06 | 古い名称、記憶による誤入力 | 台帳管理担当 |
| 7 | 新規行へ記録する列と状態の値は何か | M02、M05 | 列不足、状態の誤り | 業務責任者、台帳管理担当 |
| 8 | 申請番号は完全一致か部分一致か。検索結果0件・1件・複数件でどうするか | M11 | 別申請との混同、二重登録 | 台帳管理担当 |
| 9 | 同一内容の重複と、内容が異なる重複をどう処理するか | M07、M08 | 二重登録、既存記録の上書き | 台帳管理担当 |
| 10 | 空欄や不正値がある場合、変更、記録、相談、再開をどうするか | M03、M04、M12、M14 | 推測入力、処理放置 | 申請確認窓口 |
| 11 | 編集権限がない場合の禁止事項、相談先、引継ぎ方法は何か | M09、M10、M14 | 個人コピー、認証情報共有 | 台帳管理担当 |
| 12 | 各操作の直後に何を確認すれば次へ進めるか | M13、M19 | 入力・保存の失敗を見落とす | 台帳管理担当 |
| 13 | 通常、重複、例外それぞれの完了状態は何か | M13、M14 | 未完了を完了扱い | 業務責任者 |
| 14 | 事故や意図しない変更の疑いがある場合、何を残し誰へ連絡するか | M14、M20 | 証拠消失、対応遅延 | 台帳管理担当、事故連絡窓口 |
| 15 | 手順書の文書情報、版、確認者、改訂履歴をどう管理するか | M17 | 古い版、責任者不明 | 業務責任者、文書管理担当 |

### 不十分な質問の例

| 質問 | 問題 | 問い直しの方向 |
|---|---|---|
| 空欄は登録禁止ですよね | 答えを誘導している | 必須項目、台帳変更の可否、相談先を分けて聞く |
| いつものシステムを使いますか | 製品、対象、権限が特定できない | 正しい台帳、最新版の確認方法、必要権限を聞く |
| エラーなら誰に聞けばよいですか | エラーの種類と伝える内容が不明 | 空欄、重複、権限、事故の場面別に聞く |
| どうやって登録しますか | 操作だけで、期待結果と停止条件がない | 操作、期待結果、異常時の戻り先を聞く |

質問を思い付かなかった場合は、答えを開く前に、`このメモだけで、初めての人が変更しても戻せますか`、`同じ番号があったとき、何が同じなら同一内容ですか`と自分へ問い、判断場面を具体化します。

## 3. 確認カードから得る確定要件

| 項目 | 確認済み内容 | 根拠カード |
|---|---|---|
| 目的 | 承認済みの研修備品貸出申請を指定台帳へ1件ずつ正確に記録 | A |
| 対象外 | 返却、取消、在庫変更、申請承認 | A |
| 実行者 | 指定台帳の編集権限を持つ台帳更新担当 | A、G |
| 正しい申請 | 研修運営責任者による`承認済み`の申請票 | A、B、C |
| 必須7項目 | 申請番号、申請部署、備品コード、数量、貸出予定日、返却予定日、承認状態 | C |
| 値の条件 | 数量は1以上の整数。返却予定日は貸出予定日と同日以降 | C |
| 備品名 | 指定された最新版の備品マスターで、コードと完全一致する名称 | B、C、D |
| 新規行 | 8項目を記録し、状態は`貸出予定` | D |
| 検索 | 申請番号を完全一致で確認 | F |
| 同一重複 | 新規追加も既存変更もせず、`同一内容の重複確認・更新なし`と記録 | F |
| 内容相違の重複 | 追加・上書きをせず、相違を記録して台帳管理担当へ相談 | F |
| 同じ番号が複数行 | 内容にかかわらず変更せず、件数を記録して台帳管理担当へ相談 | F |
| 空欄・不正値 | 変更せず、問題を記録して申請確認窓口へ相談 | E |
| 権限不足 | 変更・個人コピー・認証情報共有・自己権限変更をせず、台帳管理担当へ相談 | G |
| 通常完了 | 保存後、申請番号が1行だけで8項目が根拠と一致 | D、H |
| 例外の完了 | 重複同一は更新なし記録で完了。その他の例外は相談結果まで未完了 | H |
| 文書の版 | 草案v0.1→テスト版v1.0→完成版v1.1 | I |

`一般的な台帳ならこうする`という知識は根拠にしません。確認カードにないセル位置、ファイル名、画面ラベル、保存場所を書いた場合は、`その名前はどのカードにあるか`と自問します。

## 4. 保存済みAI草案との任意比較

自分で生成したAI草案を確認カードへ照合した後に、[保存済みAI草案（問題例）](../../sample-outputs/manual_ai_output_problem.md)と比較します。問題例には、少なくとも次の問題があります。

| 問題例の記載・状態 | 種類 | 主な影響 | 修正の方向 |
|---|---|---|---|
| `管理システムへ登録し備品を予約` | 対象範囲の作り足し | 台帳更新と予約処理を混同 | 確認済みの目的・対象外へ戻す |
| `Aoba-Asset Cloud` | 製品名の作り足し | 存在しない環境を案内 | `指定台帳`とだけ書く |
| `左メニューの貸出管理` | 画面・メニュー名の作り足し | 初めて読む人が見つけられない | 入力にない画面名を削除 |
| `新規登録`、`保存して確定`ボタン | ボタン名の作り足し | 誤操作、手順停止 | 行動と期待結果で記述 |
| 開始前の承認・必須値確認がない | 不足 | 未承認・欠損申請の登録 | 開始前チェックへ追加 |
| 備品名を過去行や記憶から入力 | 根拠の誤り | 古い・誤った名称 | 最新版備品マスターを使う |
| 空欄なら3日後を補う | 推測・作り足し | 返却予定日の改ざん | 変更せず申請確認窓口へ相談 |
| 状態を`予約`とする | ルールの誤り | 状態不一致 | `貸出予定`へ修正 |
| 重複を上書きする | 危険な変更 | 正しい既存記録を破壊 | 同一・相違を分け、どちらも変更しない |
| 個人PCへダウンロード | 権限・保存違反 | 情報拡散、版の分裂 | 禁止し台帳管理担当へ相談 |
| 同僚のアカウントを借りる | 認証情報・監査違反 | なりすまし、追跡不能 | 禁止し正式な権限・引継ぎを使う |
| エラー時に何度か保存 | 曖昧・危険 | 二重処理、状態悪化 | 変更を止め、状況記録と相談先を特定 |
| `詳しい担当者` | 相談先が曖昧 | 放置、誤連絡 | 場面別に申請確認窓口／台帳管理担当を指定 |
| 入力できれば完了 | 完了条件の不足 | 未保存・重複・誤入力を見落とす | 保存後の1行・8項目照合を行う |
| 操作ごとの期待結果がない | 再現性不足 | 失敗したまま次へ進む | 操作と期待結果を対にする |
| 対象外、禁止事項、停止条件がない | 安全設計不足 | 権限外処理を続行 | 独立した見出しを追加 |
| 作成者・確認者・改訂履歴がない | 文書管理不足 | 版と責任が不明 | 文書情報と履歴を追加 |

問題数を当てることが目的ではありません。同じ誤りが目的、手順、完了条件へ重複していれば、すべての箇所を修正します。

完全な架空内容の草案`v0.1`は、変更理由を追えるよう会社指定の限定保存先へ置きます。ただし、組織が研修草案を保持しない方針なら本文を保存せず、レビュー記録へ`v0.1非保持・組織ルール`と理由だけを残します。自習では個人領域や外部共有先へ保存しません。

## 5. 確認例：研修備品貸出台帳更新手順書 完成版 v1.1

以下は、Wordへ貼り付けられる構成例です。実在業務の正式手順ではなく、この演習の確認カードにだけ基づく研修成果物です。

---

### 研修備品貸出台帳更新手順書

#### 文書情報

| 項目 | 内容 |
|---|---|
| 版 | 完成版 v1.1 |
| 作成日 | 2026-08-09 |
| 作成者 | マニュアル作成者役 |
| 確認者 | 研修運営責任者役、台帳管理担当役 |
| 対象者 | 指定台帳の編集権限を持つ台帳更新担当 |
| 対象 | 承認済みの研修備品新規貸出申請の台帳更新 |
| 対象外 | 返却、取消、在庫数変更、申請の承認 |
| 文書状態 | 紙上テスト済みの研修成果物。実在業務での利用承認ではない |

#### 1. 目的

承認済みの研修備品貸出申請を、指定された貸出台帳へ正確に1件ずつ記録します。空欄、重複、権限不足などを推測で処理せず、台帳を変更しない状態で指定先へ相談します。

#### 2. 用語と役割

| 用語・役割 | この手順での意味 |
|---|---|
| 承認済み申請票 | 研修運営責任者が承認した、台帳更新の根拠資料 |
| 最新版備品マスター | 台帳管理担当が指定した、備品コードと備品名の正しい参照先 |
| 台帳更新担当 | 指定台帳の編集権限を持ち、この手順を実行する人。申請の承認は行わない |
| 申請確認窓口 | 空欄、不正値、申請内容の確認を受ける役割 |
| 台帳管理担当 | 台帳、重複内容、権限について相談を受ける役割 |
| 例外記録欄 | 組織が指定した場所へ、処理できない理由と相談状況を残す欄 |

#### 3. 開始前チェック

| No. | 確認すること | 満たす状態 | 満たさない場合 |
|---:|---|---|---|
| 1 | 対象業務 | 新規貸出申請の台帳更新である | 返却、取消、在庫変更、申請承認はこの手順を使わず停止 |
| 2 | 申請状態 | `承認済み`である | 台帳を変更せず、申請確認窓口へ確認 |
| 3 | 必須7項目 | 申請番号、申請部署、備品コード、数量、貸出予定日、返却予定日、承認状態がすべてある | 台帳を変更せず、空欄項目を記録して申請確認窓口へ相談 |
| 4 | 数量 | 1以上の整数である | 台帳を変更せず、不正値を記録して申請確認窓口へ相談 |
| 5 | 日付 | 返却予定日が貸出予定日と同日または後である | 台帳を変更せず、日付の不整合を記録して申請確認窓口へ相談 |
| 6 | 備品コード | 指定された最新版備品マスターに存在する | 台帳を変更せず、コードを記録して申請確認窓口へ相談 |
| 7 | 参照資料 | 申請票、備品マスター、貸出台帳が指定された最新版である | 台帳を変更せず、台帳管理担当へ確認 |
| 8 | 権限 | 台帳更新担当が指定台帳を編集できる | 個人コピー等を作らず、状況を記録して台帳管理担当へ相談 |

No.1から8をすべて満たすまで、新しい行を作りません。

#### 4. 入力項目と正しい参照先

| 台帳の項目 | 入力する値 | 正しい参照先 |
|---|---|---|
| 申請番号 | 申請票の申請番号 | 承認済み申請票 |
| 申請部署 | 申請票の申請部署 | 承認済み申請票 |
| 備品コード | 申請票の備品コード | 承認済み申請票 |
| 備品名 | 備品コードと完全一致する名称 | 指定された最新版備品マスター |
| 数量 | 申請票の数量 | 承認済み申請票 |
| 貸出予定日 | 申請票の貸出予定日 | 承認済み申請票 |
| 返却予定日 | 申請票の返却予定日 | 承認済み申請票 |
| 状態 | `貸出予定` | この手順の確認済みルール |

#### 5. 通常手順

| No. | 行う操作 | 期待結果 | 異常時の戻り先 |
|---:|---|---|---|
| 1 | 承認済み申請票、最新版備品マスター、指定台帳を開く | 3つの正しい参照先を区別して確認できる | 最新版か不明なら変更せず、台帳管理担当へ相談 |
| 2 | 開始前チェックNo.1から8を上から確認する | すべて満たす、または変更前に例外分岐へ進める | 空欄・不正値は「6.1」、権限不足は「6.4」へ進む |
| 3 | 申請番号を省略せず、指定台帳内で完全一致により照合する | 一致する既存行が0件、1件、または2件以上のどれかと判断できる | 1件なら8項目を比較して「6.2」または「6.3」へ進む。2件以上なら「6.3」へ進む |
| 4 | 備品コードを最新版備品マスターと完全一致で照合し、対応する備品名を確認する | コードに対応する備品名を1つ確認できる | 該当なし・複数候補なら変更せず「6.1」へ進む |
| 5 | 申請番号の既存行が0件である場合だけ、指定台帳に新しい行を1行用意する | 空の新規行が1行だけで、既存行を変更していない | 既存行を変更した疑いがあれば入力を止め、台帳管理担当へ相談 |
| 6 | 「4. 入力項目と正しい参照先」に従い、8項目を新規行へ転記する | 新規行の8項目がすべて埋まり、状態が`貸出予定`である | 空欄や不一致があれば保存せず、申請票と備品マスターへ戻る |
| 7 | 新規行の8項目を、各参照先と一つずつ照合する | 8項目すべてが根拠と一致し、推測入力がない | 不一致なら保存せず、該当値を直して再照合。根拠が一致しなければ停止・相談 |
| 8 | 組織が指定した通常の方法で台帳を保存する | 保存処理が終わり、保存失敗の表示や状態がない | 保存状態が不明、失敗、競合の疑いがあれば繰り返し操作せず台帳管理担当へ相談 |
| 9 | 保存後の台帳で申請番号を完全一致により再確認し、8項目を根拠と照合する | 対象番号が1行だけ存在し、8項目がすべて一致する | 0件、複数件、不一致なら完了にせず台帳管理担当へ相談 |
| 10 | 組織が指定した完了記録へ、通常登録が完了したことを記録する | 台帳の確認結果と処理状態を後から確認できる | 記録場所が不明なら完了にせず、台帳管理担当へ確認 |

この教材には画面ラベルがありません。上表の`開く`、`完全一致で照合する`、`保存する`は行動の説明であり、特定ボタンの名称ではありません。

#### 6. 条件別の分岐

##### 6.1 空欄・不正値・備品コード不明

| 条件 | 台帳変更 | 記録 | 相談先 | 再開条件 |
|---|---|---|---|---|
| 必須項目が空欄 | しない | 申請番号と空欄項目 | 申請確認窓口 | 修正済みの承認済み申請票を受領し、開始前チェックから再実施 |
| 数量が1以上の整数でない | しない | 申請番号と数量の問題 | 申請確認窓口 | 同上 |
| 返却予定日が貸出予定日より前 | しない | 申請番号と日付の不整合 | 申請確認窓口 | 同上 |
| 備品コードが最新版マスターにない、または一意に決まらない | しない | 申請番号と備品コード | 申請確認窓口 | 有効なコードを含む修正済み承認済み申請票を受領後、最初から再確認 |

空欄、数量、日付、備品名を台帳更新担当が推測して補いません。

##### 6.2 既存行1件・同一内容の重複

同じ申請番号の既存行が1行あり、8項目すべてが今回の根拠資料と一致する場合は、新しい行を追加せず、既存行も変更しません。例外記録欄へ`同一内容の重複確認・更新なし`と記録します。この記録を確認できれば、台帳変更なしでこの確認処理は完了です。

##### 6.3 内容が異なる重複・同じ番号が複数行

同じ申請番号の既存行が1行あり、8項目のうち1つでも今回の根拠資料と異なる場合は、新規追加、上書き、削除を行いません。相違した項目を例外記録欄へ記録して台帳管理担当へ相談します。

同じ申請番号の既存行が2行以上ある場合は、内容が同じでも新規追加、上書き、削除を行いません。件数を例外記録欄へ記録して台帳管理担当へ相談します。どちらの場合も、相談結果と正式な指示を確認するまで処理は未完了です。

##### 6.4 権限不足

指定台帳が閲覧専用、編集拒否、または権限不明の場合は変更しません。申請番号と発生状況を例外記録欄へ記録して台帳管理担当へ相談します。正式な編集権限が付与されるか、組織指定の方法で権限を持つ担当者へ引き継がれるまで処理は未完了です。

#### 7. 禁止事項

- 承認待ち、差戻し、取消の申請を登録しない
- 空欄、数量、日付、備品名、状態を推測で補わない
- 記憶や過去行を、最新版備品マスターの代わりにしない
- 重複した既存行を自己判断で上書き・削除しない
- 個人フォルダーへの台帳コピー、別台帳の作成、後からの非公式な統合を行わない
- 他人の認証情報を借りない、権限設定を自己変更しない
- 入力にない製品名、画面名、メニュー名、ボタン名、セル位置を手順へ追加しない
- 完了確認前に、処理済みとして連絡しない
- 意図しない変更や情報漏えいの疑いがあるとき、自己判断で履歴や証拠を削除しない

#### 8. 停止・相談条件

| 停止条件 | 台帳変更 | 記録すること | 相談先 |
|---|---|---|---|
| 承認状態、必須項目、数量、日付、備品コードの問題 | しない | 申請番号と問題項目 | 申請確認窓口 |
| 同じ申請番号1行で内容が異なる、または同じ番号が2行以上ある | しない | 申請番号と相違項目、または既存行の件数 | 台帳管理担当 |
| 指定台帳・最新版・保存先が不明 | しない | 不明な資料と確認状況 | 台帳管理担当 |
| 閲覧のみ、編集拒否、権限不明 | しない | 申請番号と発生状況 | 台帳管理担当 |
| 保存失敗、競合、意図しない変更の疑い | 追加操作を止める | 発生状況。自己判断で証拠を消さない | 台帳管理担当。情報漏えいの疑いは組織の事故連絡窓口にも連絡 |

#### 9. 完了確認

##### 通常登録

- [ ] 対象の申請番号が保存後の台帳に完全一致で1行だけある
- [ ] 申請番号、申請部署、備品コード、備品名、数量、貸出予定日、返却予定日、状態の8項目が根拠と一致する
- [ ] 状態は`貸出予定`である
- [ ] 既存行を変更していない
- [ ] 指定された完了記録を残した

##### 同一内容の重複

- [ ] 新規行を追加していない
- [ ] 既存行を変更していない
- [ ] `同一内容の重複確認・更新なし`を例外記録欄へ残した

##### その他の例外

- [ ] 台帳を変更していない
- [ ] 問題と相談先を例外記録欄へ残した
- [ ] 相談結果が出るまで処理未完了としている

## 6. 紙上テストの実行例

### T01：正常

| 確認点 | 確認例判断 |
|---|---|
| 承認・必須項目・数量・日付・コード | すべて開始条件を満たす |
| 既存行 | `TR-260901`の完全一致なし |
| 権限 | 編集可能 |
| 台帳変更 | 新規行を1行だけ追加する想定 |
| 追加予定行 | `TR-260901／研修企画部／EQ-101／HDMI変換アダプター／1／2026-09-07／2026-09-08／貸出予定` |
| 完了確認 | 保存後に申請番号1行と8項目一致を確認する想定 |

### T02：返却予定日が空欄

| 確認点 | 確認例判断 |
|---|---|
| 問題 | 必須項目の返却予定日が空欄 |
| 台帳変更 | しない。3日後などを推測しない |
| 記録 | `TR-260902、返却予定日が空欄` |
| 相談先 | 申請確認窓口 |
| 状態 | 修正済みの承認済み申請票が示されるまで未完了 |

### T03：同一内容の重複

| 確認点 | 確認例判断 |
|---|---|
| 検索 | `TR-260903`の完全一致が1行ある |
| 内容比較 | 8項目がすべて今回の根拠と一致 |
| 台帳変更 | 新規追加も既存変更もしない |
| 記録 | `同一内容の重複確認・更新なし` |
| 状態 | 記録を確認できれば、この確認処理は完了 |

### T04：権限不足

| 確認点 | 確認例判断 |
|---|---|
| 権限 | 閲覧のみで編集不可 |
| 台帳変更 | しない |
| 禁止 | 個人コピー、別台帳、他人の認証情報、自己権限変更 |
| 記録 | `TR-260904、閲覧のみで編集不可` |
| 相談先 | 台帳管理担当 |
| 状態 | 正式な権限付与または指定方法での引継ぎまで未完了 |

### 紙上テストで見るべき使いやすさ

正しい答えへ到達しただけで終えません。次も確認します。

- 開始前チェックを読めば、新規行を作る前に例外を発見できるか
- `完全一致`、`8項目`、`1行だけ`の意味が具体的か
- 空欄を見つけた後、どこへ戻り、誰へ何を伝えるか分かるか
- 同一内容の重複と内容相違の重複を分けられるか
- 権限不足時に、安全でない回避策を選ばず止まれるか
- 通常登録の完了と、相談中の未完了を区別できるか

## 7. よくある誤りと自分への確認質問

| よくある誤り | 自分への確認質問 |
|---|---|
| AIの質問一覧をそのまま採用 | 「この質問は、どのメモの不確かさを解消しますか」 |
| 確認カードを見る前に正解手順を書く | 「そのルールは、誰がどの資料で確認しましたか」 |
| 空欄を`要確認`と書きつつ台帳へ仮登録 | 「確認できない間、台帳は変更されますか」 |
| 備品名を申請票から転記 | 「備品名の正しい参照先はどれですか」 |
| 重複ならすべて上書き | 「内容が同じ場合と異なる場合で、守るべき記録は同じですか」 |
| 権限不足を別ファイル作成で回避 | 「正しい台帳が2つになったら、どちらが最新版ですか」 |
| `登録ボタンを押す`と書く | 「そのボタン名は、入力資料のどこにありますか」 |
| `適切に確認する`だけを書く | 「何と何がどうなれば、次へ進めますか」 |
| 正常例だけで紙上テスト | 「空欄、重複、権限不足なら、同じ手順で止まれますか」 |
| 作成者がテスト中に説明 | 「その説明がなくても進める文にするには、何を追加しますか」 |
| v1.0を上書きしてv1.1だけ残す | 「どの指摘で何を直したか、後から追えますか」 |
| 完成版なので実務利用できると判断 | 「研修成果物を正式手順へ承認する権限は誰にありますか」 |

確認例だけを読むのではなく、根拠カードと自分のレビュー記録へ戻ります。

## 8. 許容できる別解

次は、意味と安全性が同じなら別解として認められます。

- `開始前チェック`を、チェックボックス形式または判断表にする
- 通常手順を表ではなく、番号付きリストと各`期待結果`の組で書く
- 分岐をフローチャートで補助する。ただし本文の条件と矛盾させない
- `台帳管理担当`を文中で`管理担当`と略す。ただし最初に定義する
- Wordを使わず、同じ構造のMarkdownで完成させる。印刷物は紙上テストの指摘記録にだけ使う
- 改訂箇所が確認例と異なる。実際のテスト指摘、変更理由、再確認が記録されていることが条件

次は別解として認めません。

- 架空の製品、画面、ボタン、セル位置を追加する
- 一般知識やAIの推測で、確認カードにないルールを確定する
- 空欄を仮値で登録する
- 重複行を自己判断で変更・削除する
- 個人用コピーや他人の認証情報で権限不足を回避する
- 紙上テストを作成者の口頭説明で完了させる
- 改訂前の版や変更理由を残さない
- 研修成果物を正式承認済みと表記する

## 9. 利用環境と一人学習の分岐

| 制約 | 代替方法 | 同じように確認できる能力 |
|---|---|---|
| 指定された対話AI製品なし | 別の承認済み対話AIへ切り替える | AIで質問候補と草案を生成し、人が検証する |
| 承認済み対話AIを利用できない | 環境を準備するまで演習を停止する | AI実操作がないため未完了 |
| Wordなし | 1つのMarkdown文書に同じ見出しと表を作る | 構成、期待結果、分岐、版管理 |
| PCなし | 対話AIを操作できるPCを準備するまで演習を停止する | AI実操作がないため未完了 |
| ペアなし | テスト版を閉じ、後で別役割として4ケースを再実行 | 手順書だけで判断できるかの確認 |

保存済み問題例は、自分のAI草案の照合後に見落としを探す比較教材です。紙上テストは人が手順書の使いやすさを確認する工程であり、AI実操作の代替ではありません。

## 10. 振り返り例

| 質問 | 記入例 |
|---|---|
| AIが速めた作業 | 20個のメモを観点別に分類し、質問候補と見出し案を作る作業 |
| 人が行った判断 | どの資料を正とするか、空欄時に変更しないこと、相談先、完了状態 |
| 最も危険な作り足し | 入力にないボタン名よりも、空欄を3日後で補う業務ルールの作り足し |
| 紙上テストで分かったこと | 操作だけでなく、各段階の期待結果と異常時の戻り先が必要 |
| 実務で最初に確認すること | 正しい手順責任者、最新版資料、AI入力可否、権限、文書承認方法 |
| 停止条件 | 根拠不明、空欄、矛盾、権限不足、意図しない変更の疑い |

## 11. 自己点検用まとめ

この演習の中心は、AIで読みやすい文章を作ることではありません。`未整理メモ→確認質問→人間確認済み要件→草案→根拠照合→役割を変えた紙上実行→版更新→責任者承認`という流れを、自分で実行することです。

完成版が確認例と同じ文面である必要はありません。確認済み要件から外れず、初心者が正常・空欄・重複・権限不足を安全に判断でき、迷ったときに変更せず相談できれば目的を満たします。

実務へ転用する場合、AIへ入力できる情報、正式な根拠資料、文書承認、アクセス権、保存・共有・保持・削除は組織ごとに確認します。個人情報、契約、法令、労務、安全などが関係する業務では、必要に応じて専門家へ確認してください。AI出力は必ず人が元資料と照合し、権限を持つ責任者が承認します。
