## 1. 自己点検方法

各演習は点数を付けず、元教材の完成条件と次の自己点検ポイントで確認します。

| 観点 | 完成した状態 | 直ちに修正する状態 |
|---|---|---|
| 入力安全 | 架空・必要最小限の情報を使い、承認済み環境を確認している | 実在の顧客情報や認証情報を入力する |
| 指示設計 | 目的、読者、制約、出力形式、確認方法が明確 | 「いい感じに書いて」だけで生成する |
| 事実忠実性 | 入力にない内容を断定せず、不明点を明示している | 日時、担当、原因、補償などを創作する |
| 実務品質 | 読者が状況と次の行動を理解できる | 結論や依頼事項が分からない |
| 人間確認 | 主張を元資料と照合し、確認者・確認日・承認点を示す | AI出力を無確認で送信・公開する |

完成文だけでなく、プロンプト、AIチャット上の初回草案、照合記録、修正履歴も確認します。初回草案を保存するためだけの別ファイルは求めません。

## 2. 演習1：会議メモから議事録とタスク一覧を作成

### 2.1 この演習で確認すること

点数は付けません。次の行動を一人で順番に行い、なぜ必要か説明できるかを確認します。

[クイックスタート](../../setup/participant_quickstart.md)で同じケースの完成成果物を保存済みなら、再実施は不要です。2.7の完成条件だけを確認し、演習2へ進みます。演習1は、クイックスタートを未実施の場合や、このファイルから学習を始める場合に使います。

1. 完成プロンプトをコピーして送信する。
2. AI画面上の初回草案を元メモと照合する。
3. 問題があれば、同じチャットで具体的に修正を依頼する。
4. タスクを期限の早い順にするなど、指定された1点だけを改善する。
5. 再出力も元メモの全項目と照合する。
6. 完成したWord用議事録とExcel用タスク一覧を保存する。

初回草案を別のメモ帳へ転記したかどうかは確認対象にしません。AIの出力を業務成果物へ変換し、事実を保ったまま完成させることが目的です。

入力は、決定・タスク・未決の順に整っていない会議中の走り書きです。AIを使う価値は、文章の言い換えだけでなく、この走り書きを分類して実行可能な形へ変える点にもあります。ただし、分類が正しいかを決めるのは元資料と照合する人です。

### 2.2 完成議事録の例

**架空AI研修運営改善会議 議事録**

**会議情報**

| 項目 | 内容 |
|---|---|
| 会議名 | 架空AI研修運営改善会議 |
| 開催日 | 2026-07-08 |
| 参加役割 | 研修責任者、研修運営担当、情報システム担当、情報セキュリティ担当 |

**決定事項**

1. 次回の初心者研修では、教材の完全な架空データだけを使用する。
2. 終了時チェックリストへのリンクを学習案内へ追加する。決定。
3. 会議終了時チェックリストを共有フォルダーへ置く。決定。

**未決事項**

| 項目 | 現在の状態 | 担当 | 期限 |
|---|---|---|---|
| 研修の録画 | 録画可否は未決。法務確認が必要 | 未決 | 未決 |
| 来月のフォローアップ会 | 実施可否・日程とも未決 | 未決 | 未決 |
| 次回会議 | 日付・時刻・会場は未決 | 未決 | 未決 |

### 2.3 Excel用タブ区切りタスク一覧の例

次のコードブロックは、各項目の間をタブ文字で区切った例です。ExcelのA1セルへ貼り付けると、通常は3列に分かれます。

```text
タスク	担当	期限
入力禁止情報一覧をレビューする	情報セキュリティ担当	2026-07-10
業務用アカウントのログインテストを行う	情報システム担当	2026-07-11
学習案内を改訂する	研修運営担当	2026-07-12
```

自習では、タスクが3件より増えていないかを確認します。特に「法務確認を行う」をタスクとして追加し、担当を研修責任者、期限を任意の日付にしてしまう出力に注意してください。元メモでは、法務確認が必要であることだけが分かり、確認担当と期限は未決です。

### 2.4 元メモ照合表の完成例

文章が確認例と完全に同じである必要はありません。次の事実と状態が保たれていれば、言い換えを許容します。

| 確認対象 | 元メモ | 完成例での表現 | 判定 |
|---|---|---|---|
| 会議名 | 架空AI研修運営改善会議 | 同じ | 一致 |
| 開催日 | 2026-07-08 | 同じ | 一致 |
| 参加役割 | 指定の4役割 | 4役割すべて記載 | 一致 |
| 架空データ使用 | 決定 | 決定事項1 | 一致 |
| 学習案内へのチェックリストリンク追加 | 決定 | 決定事項2 | 一致 |
| チェックリストの共有フォルダー配置 | 決定 | 決定事項3 | 一致 |
| 学習案内改訂 | 研修運営担当、2026-07-12 | タスク一覧3行目 | 一致 |
| ログインテスト | 情報システム担当、2026-07-11 | タスク一覧2行目 | 一致 |
| 入力禁止情報一覧レビュー | 情報セキュリティ担当、2026-07-10 | タスク一覧1行目 | 一致 |
| 録画 | 録画可否は未決。法務確認が必要。担当・期限は未決 | 未決事項に同じ状態を記載 | 一致 |
| 来月のフォローアップ会 | 実施可否・日程とも未決 | 未決事項に記載 | 一致 |
| 次回会議 | 日付・時刻・会場は未決 | 未決事項に同じ状態を記載 | 一致 |
| 個人名 | 入力なし | 追加なし | 一致 |

### 2.5 同じチャットでの修正例

たとえばAIが「研修責任者が2026-07-09までに法務へ確認する」と補った場合は、次のように具体的に返します。

```text
元メモとの照合で、録画に関する担当と期限が作られていることを確認しました。
元メモで分かるのは「法務確認が必要」という点だけで、確認担当と期限は未決です。

録画の担当と期限をどちらも「未決」へ修正してください。
Word貼り付け用議事録とExcel貼り付け用タスク一覧を両方とも再出力し、ほかの決定・担当・期限を変更しないでください。
```

修正後は録画欄だけでなく、3件の決定、3件のタスク、ほかの未決事項も再確認します。AIは一箇所の修正時に、別の表現や項目を変えることがあるためです。

### 2.6 1点改善の例

標準の改善は、Excel用タスク一覧を期限の早い順へ並べることです。

```text
内容、担当、期限は変えず、Excel貼り付け用タスク一覧だけを期限の早い順に並べ替えてください。
Word貼り付け用議事録も含め、最終版の全文を再出力してください。
元の会議メモにない情報は追加しないでください。
```

許容できる変化は、3件の行が`2026-07-10`、`2026-07-11`、`2026-07-12`の順になることです。許容できない変化は、タスクの内容・担当・期限が変わる、タスクが増える、未決事項が決定扱いになることです。改善後も2.4の照合表をすべて確認します。

自分で別テーマを指定した場合は、読み手を会議に参加していない部門長へ変える、100字以内の要約を追加する、議事録の並び順を変える、といった1点改善でも構いません。複数条件を一度に変えた場合は、変更を一つに絞って再実行します。

### 2.7 Word・Excelの完成条件

組織指定のデスクトップ版またはWeb版を使用します。Web版のために個人登録したり、未承認アプリや拡張機能をインストールしたりしません。利用できない場合は2.8の別解へ切り替えます。

| 成果物 | 完成条件 | 完成ではない例 |
|---|---|---|
| Word用議事録 | 会議情報、3件の決定、3件の未決があり、見出しで区別できる | AIチャットの画面だけを残す、未決事項を決定扱いする |
| Excel用タスク一覧 | `タスク・担当・期限`の3列に、確定した3件だけが入る | 1列に詰まったまま、録画確認を架空の担当・期限付きで追加する |
| 事実確認 | 改善後の最終出力を元メモの全項目と照合している | 初回だけ確認し、再出力を無確認で保存する |
| 保存 | 自分または組織が決めた保存先とファイル名で保存している | 個人クラウド、公開場所、共有リンクへ保存する |

書式の美しさより、決定状態と担当・期限が正しいことを先に確認します。外部送信や実システムへの登録は、この演習の範囲外です。

### 2.8 Officeを利用できない場合の別解

Markdownでは、2.2の議事録を見出しと表で作り、タスク一覧を次の表にします。

| タスク | 担当 | 期限 |
|---|---|---|
| 入力禁止情報一覧をレビューする | 情報セキュリティ担当 | 2026-07-10 |
| 業務用アカウントのログインテストを行う | 情報システム担当 | 2026-07-11 |
| 学習案内を改訂する | 研修運営担当 | 2026-07-12 |

紙上では、[保存済みの議事録・タスク一覧（問題例）](../../sample-outputs/beginner_minutes_saved_output.md)を開き、次の順に自分で記入できれば完成です。確認例の議事録とタスク一覧は2.2、2.3および次のMarkdown表を比較材料として使います。

1. 誤りまたは不足へ線を引く。
2. 元メモの該当箇所へ番号を付ける。
3. 正しい議事録と3列のタスク一覧を書き直す。
4. タスクを期限の早い順にするなど、指定された1点を改善する。
5. 改善後も全事実へ確認印を付ける。

### 2.9 よくある誤りと自分への確認質問

| 誤り | 問題 | 自分への確認質問 |
|---|---|---|
| 録画を実施すると記載 | 法務確認が必要な未決事項を決定扱い | 「実施を決めた記述は元メモのどこですか」 |
| 法務確認の担当・期限を追加 | 未知の担当・期限を創作 | 「その担当と日付の根拠はどこですか」 |
| フォローアップ会の日程を提案 | 未決事項をもっともらしく補完 | 「今回の成果物は提案書ですか、議事録ですか」 |
| 次回会議日を期限から推測 | タスク期限と会議日を混同 | 「同じ日付だと判断できる根拠はありますか」 |
| 改善後は照合しない | 再出力で生じた誤りを見逃す | 「最後に保存した版を何と照合しましたか」 |
| 初回草案の保存に時間を使う | 実務成果物の完成が進まない | 「最終的に誰が何に使う成果物ですか」 |

## 3. 演習2：メール返信作成

### 3.1 プロンプト例

```text
あなたは法人向け研修の運営担当者です。
次の架空情報だけを使い、打合せ日時変更への返信草案を作成してください。

【目的】7月9日10:00〜11:00でよいか相手に確認する
【読者】青葉商事の研修担当者
【事実】
- 相手の希望：7月9日午前または7月10日午後
- 自社の空き：7月9日10:00〜11:00のみ
- オンライン会議を予定
- 会議URLは日時確定後に送る
【禁止】
- 契約、費用、研修日程を確約しない
- 入力にない年、タイムゾーン、担当者名を推測しない
【出力】
1. 件名
2. 200〜300字の本文
3. 送信前チェック項目

不明事項は補わず「要確認」としてください。最後に、入力外の情報を
追加していないか自己点検してください。
```

### 3.2 確認例

**件名：打合せ日時変更のご確認（7月9日10:00）**

青葉商事 研修ご担当者様
平素よりお世話になっております。打合せ日時の変更についてご連絡いただき、ありがとうございます。ご提示いただいた候補のうち、7月9日10:00〜11:00であれば調整可能です。オンラインでの実施を予定しております。恐れ入りますが、こちらの日時でよろしいか、ご都合をご確認のうえご返信いただけますでしょうか。会議URLは、日時の確定後に改めてお送りします。日程変更に伴うご調整をいただき、重ねて御礼申し上げます。どうぞよろしくお願いいたします。

### 3.3 送信前照合例

| 確認対象 | 草案 | 元資料 | 判定・対応 |
|---|---|---|---|
| 候補日時 | 7月9日10:00〜11:00 | 一致 | 確認済み |
| 実施方法 | オンライン予定 | 一致 | 「予定」と表現 |
| 会議URL | 確定後に送付 | 一致 | URLを創作していない |
| 年 | 記載なし | 不明 | 送信者が確認して必要なら追記 |
| タイムゾーン | 記載なし | 不明 | 相手と異なる可能性があれば確認 |
| 契約・費用・研修日程 | 記載なし | 確約禁止 | 違反なし |

### 3.4 自己点検ポイント

- 件名だけで用件と候補日時が分かる。
- 「確定しました」ではなく、相手へ確認する表現になっている。
- URL、年、タイムゾーンを推測していない。
- 送信前に宛先、社内予定、送付担当を人が確認する設計になっている。

### 3.5 許容できる別解

- 件名を「打合せ候補日時のご相談」とする。
- 本文の順番を「お礼→候補提示→確認依頼→URL案内」とする。
- タイムゾーンが社内手続で確認済みなら、確認記録を残したうえで明記する。

### 3.6 よくある誤りと自分への確認質問

| 誤り | 問題 | 自分への確認質問 |
|---|---|---|
| 「7月9日で確定しました」 | 相手の合意前に確定扱い | 「誰が、いつ合意しましたか」 |
| 会議URLを仮作成 | 入力にない情報の創作 | 「このURLの根拠はどこですか」 |
| 「研修も予定どおり実施」 | 禁止された確約 | 「今回のメールの目的に必要ですか」 |
| 年やJSTを無条件で追加 | 不明情報の推測 | 「送信前に何を人が確認しますか」 |

### 3.7 自己点検の解説

文章の丁寧さより、「候補」と「確定」を区別できたかを先に確認します。AIが自然な文章を作れても、日程調整という業務状態を正しく扱えるとは限らないことを説明してください。

## 4. 演習3：クレーム返信作成

### 4.1 プロンプト例

```text
あなたは架空の研修運営窓口です。次の確認済み事実だけを使い、
クレームへの一次返信草案を作成してください。

順序：受け止め→確認済み事実→現在の対応→次回連絡→窓口
必須：音声が聞こえない時間があったことへの配慮
禁止：顧客の過失の示唆、原因の断定、補償の約束、未確認事項の創作
事実：運営側でも一部時間帯の音声不具合を確認。原因は調査中。
資料と代替説明文を翌営業日17時までに案内予定。補償は未決。
窓口は「研修運営窓口」。

本文の後に、責任認定・原因断定・補償確約がないかを点検する表を付けてください。
```

### 4.2 確認例

**件名：オンライン研修の音声不具合に関するご案内**

このたびは、ご受講中に音声が聞こえない時間があり、ご不便をおかけしました。運営側でも一部時間帯の音声不具合を確認しており、現在、原因を調査しております。資料と該当部分の代替説明文は、翌営業日17時までに研修運営窓口からご案内する予定です。調査結果および追加対応については、確認後に改めてご連絡いたします。ご不明点は研修運営窓口までお知らせください。

### 4.3 確認表

| 論点 | 判定 | 理由 |
|---|---|---|
| 顧客への配慮 | 適切 | 不便が生じた事実を受け止めている |
| 原因 | 適切 | 「調査中」とし、原因を断定していない |
| 次回連絡 | 適切 | 翌営業日17時までの案内内容を限定している |
| 補償 | 適切 | 未決事項を約束していない |
| 責任認定 | 要組織確認 | お詫び表現はあるが法的責任を断定していない |

### 4.4 自己点検ポイント

- 共感と事実確認を分けている。
- 「運営側の不具合の原因は○○」などと推測していない。
- 翌営業日17時までに案内する対象が「資料と代替説明文」だと明確である。
- 補償、返金、再受講を勝手に約束していない。
- 組織の責任者が最終承認することを示している。

### 4.5 許容できる別解

「ご迷惑」または「ご不便」という表現の違いは、社内テンプレートに合い、過剰な責任認定にならなければ許容します。次回連絡を独立した箇条書きにしても構いません。

### 4.6 よくある誤り

- 「サーバー障害が原因でした」と断定する。
- 「受講料を返金します」と未決の補償を約束する。
- 「お客様の通信環境をご確認ください」と顧客側の原因を示唆する。
- 謝罪だけで、次にいつ何を連絡するかを書かない。

### 4.7 自己点検の解説

「お詫び」と「法的責任の認定」は同じではありません。ただし、適切な表現は事案や組織方針で変わるため、外部送信前に責任者、法務、顧客対応部門などへ確認する前提を伝えてください。

## 5. 演習4：箇条書きから報告書作成

### 5.1 計算確認

| 指標 | 式 | 結果 | 注意 |
|---|---|---:|---|
| 出席率 | 38 ÷ 40 × 100 | 95.0% | 全受講予定者40名が分母 |
| 実技演習の完成率 | 32 ÷ 37 × 100 | 約86.5% | 提出者37名が分母 |
| アンケート回答率 | 35 ÷ 40 × 100 | 87.5% | 参考値。設問で必須ではない |

### 5.2 確認例報告書

#### 要約

6月の架空AI研修では40名中38名が出席し、実技演習は37名が提出して32名が完成条件を満たしました。受講直後の反応は概ね良好ですが、業務での定着や成果はまだ測定していません。次回はガイド付き練習と安全確認を追加し、実務での実践状況を確認することを提案します。

#### 確認済み事実

| 項目 | 結果 |
|---|---|
| 出席 | 38/40名、出席率95.0% |
| 実技演習 | 37名提出、32名が完成条件を満たし、完成率約86.5% |
| 満足度 | 35名回答、平均4.2/5 |
| 自由記述 | 実務例が役立つ18件、ガイド付き練習が不足12件、用語が難しい5件 |
| 安全 | 実情報入力0件、入力前に自分で停止したヒヤリハット1件 |

#### 解釈候補

- 実務例は継続する価値がある可能性がある。
- ガイド付き練習の追加と、用語集の事前配布を検討する材料がある。
- 満足度は受講直後の反応であり、業務効率化や定着の証明ではない。
- 未回答者5名の意見は、このデータから推測できない。

#### リスク

ヒヤリハット1件は事故ではありませんが、入力前確認が十分定着していない可能性を示します。件数だけで安全と判断せず、停止できた理由と再発防止策を確認します。

#### 次回提案

1. ガイド付き練習と相互レビューの工程を追加する。
2. 用語集を事前配布する。
3. 入力可否判断を再演習する。
4. 30日後に実践率、確認手順の実施率、重大誤りを追跡する。

#### 要確認

ガイド付き練習を追加する場合の実施方法、補助担当者の要否、30日後調査の責任者・対象・方法。

### 5.3 自己点検ポイント

- 数値を変えず、分母と計算式を示している。
- 事実、解釈、提案を明確に分けている。
- 未回答者の意見や業務効果を推測していない。
- ヒヤリハットを事故件数へ混同していない。

### 5.4 許容できる別解

割合を小数第1位ではなく整数へ丸めても、式と丸め方が明記されていれば許容します。提案内容も、データと結び付いており、実施条件と評価方法があれば別案を認めます。

### 5.5 よくある誤り

- 実技演習の完成率を32/40または32/38で計算する。
- 満足度4.2から「業務効率が向上した」と結論づける。
- 自由記述件数の合計を回答者数と同一視する。
- ヒヤリハットを隠す、または重大事故と断定する。

### 5.6 自己点検の解説

AIは文章を整える一方で、分母や因果関係を取り違えることがあります。報告書中の数値、比較、因果表現へ自分で印を付け、すべてに根拠があるか確認します。

## 6. 演習5：上司向け要約作成

### 6.1 確認例

次回研修は、ガイド付き練習と安全確認を追加し、実務での実践状況を追跡する変更を提案します。根拠は、40名中38名の出席、実技演習を提出した37名中32名が完成条件を満たしたこと、演習不足の指摘12件です。満足度は回答35名で平均4.2/5ですが、業務定着は未測定で、入力前停止のヒヤリハットも1件ありました。この変更案の承認をお願いします。

### 6.2 構造確認

| 要素 | 該当内容 |
|---|---|
| 結論候補 | 次回は演習と安全確認を増やす |
| 根拠 | 出席、実技演習の完成状況、満足度、自由記述 |
| リスク | 業務定着は未測定、ヒヤリハット1件 |
| 承認事項 | ガイド付き練習の追加、安全確認、30日後追跡 |

### 6.3 自己点検ポイント

- 150〜220字の指定範囲に収めている。
- 重要な数字の分母を省略していない。
- 上司に何を承認してほしいかが明確である。
- 未測定の業務効果を断定していない。

### 6.4 許容できる別解

提案を「演習手順の見直し」や「事前学習追加」に変えても、データとのつながり、実施条件、承認事項が明確なら許容します。

### 6.5 よくある誤り

- 数字を削りすぎて判断根拠がなくなる。
- 報告書全体を短くしただけで、承認事項がない。
- 「研修は成功」「全員が習得」と断定する。
- 文字数を満たすために未確認の効果を追加する。

### 6.6 自己点検の解説

要約は「短い文章」ではなく「意思決定に必要な情報を選んだ文章」です。読み手、判断、期限を先に決めてから情報を削るよう指導してください。

次の初回草案は、修正練習用に意図的な誤りを含めています。自分が実際に得た初回草案が別内容でも、同じ観点で照合します。

### 7.3 AIと人間の役割分担例

| 演習 | AIへ任せる候補 | 人が必ず行うこと | AIへ任せない判断 |
|---:|---|---|---|
| 1 | 議事録の構成候補とタスクの表形式化 | 全項目を元メモと照合し、改善後も再確認 | 入力にない決定・担当・期限の決定 |
| 2 | 件名・本文・チェック項目の草案 | 日時、宛先、予定、URL、確約表現を確認し送信承認 | 日程の最終確定、契約・費用の確約 |
| 3 | 一次返信の構成・文案 | 確認済み事実、表現、次回連絡を照合し責任者が承認 | 原因、法的責任、補償の決定 |
| 4 | 構成、計算候補、文章草案 | 式、分母、数値、因果表現、リスクを確認 | 業務効果や研修を続けるかの最終判断 |

演習1では、完成したWord用議事録とExcel用タスク一覧を保存します。照合で見つけた問題、同じチャットで行った修正、1点改善、改善後の再照合は、自分または組織が決めたワークシートへ簡潔に記録します。初回草案を保存するためだけの別ファイルは不要です。演習2〜5も、自分で指定した成果物と確認記録を保存します。

## 9. 自業務転用と終了処理の確認例

自業務転用表は、次のように実データを含めず記入できていれば完成です。

| 項目 | 記入例 |
|---|---|
| 候補業務 | 定例会議メモの整理 |
| AIに任せる部分 | 決定・未決・タスクの候補抽出 |
| 人が照合する項目 | 決定の有無、担当、期限、元メモの該当文 |
| 誤りの影響 | 未承認事項が実行される可能性 |
| 相談・承認先 | 上司、情報システム、情報セキュリティ担当 |
| 最初の試行 | 承認後、完全な架空メモ3件で試す |
| 停止条件 | 入力外の決定を作る、外部共有が発生する |

自習では終了時に、外部送信・公開・共有リンクがないこと、完成成果物と照合記録が指定場所にあること、改善後の出力も再照合したこと、共有端末のサインアウトと一時ファイル処理を組織ルールに従って行ったことを確認します。自業務転用表は利用許可ではなく、担当部門への相談材料です。
