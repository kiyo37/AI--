# 04 プロンプトエンジニアリング：成果物例と自己点検

[元教材「04 プロンプトエンジニアリング」へ戻る](../../04_prompt_engineering.md)

## 自己点検の進め方

1. このページを読む前に、追加指示、改善後の成果物、再照合記録を保存します。
2. 最初は「段階ヒント」だけを読み、自分で1回見直します。
3. 次に「一致必須」と成果物例を比較し、選んだ1条件以外が変わっていないか確かめます。
4. 「危険な状態」に当てはまる箇所があれば、その箇所を優先して修正します。
5. 最後に改善点を1つだけ選び、成果物を再保存します。

- 本書の出力例は一例です。文章表現が異なっても、元資料の事実と状態が保たれていれば別解として成立します。
- 良いプロンプトでも正確性は保証されません。条件を一つ変えた後にも、元資料との全件照合が必要です。
- この教材では完全な架空データだけを使い、成果物を外部送信・公開しません。
- 法律、医療、金融、契約、権利などはAIだけで判断せず、権限を持つ担当者または専門家へ確認します。
- ツールの機能、上限、保存、データ利用条件は変わるため、実施時点の最新の公式情報を確認します。

## 演習：完成プロンプトを1点改善する

### 開始状態の確認

[クイックスタート](../../setup/participant_quickstart.md)を完了していることが前提です。クイックスタートではすでに、順不同の走り書きの分類、元資料照合、期限順への並べ替え、Word・Excelへの仕上げを行っています。この章で同じ生成・分類を繰り返しません。

| 自分の状態 | 開始方法 |
|---|---|
| AI会話と確認済み成果物がある | その会話と成果物を基準にする |
| 確認済み成果物はあるがAI会話がない | クイックスタートの完成プロンプトを1回だけ新しい会話へ送り、元資料と照合してから使う |
| 対話AIを利用できない | 演習を停止し、承認・利用条件を確認した対話AIを準備してから戻る。確認済み成果物の閲覧だけでは完了にしない |
| クイックスタートが未完了 | 先にクイックスタートを完了させる |

既存チャットがある場合は、完成プロンプトを再送しません。既存チャットがない場合も、同じ指示を何度も送って望む出力を選びません。

### 段階ヒント1：完成プロンプトを読む

クイックスタートの完成プロンプトを小さな仕様書として説明できれば、次へ進めます。

| 要素 | このケースでの役割 |
|---|---|
| 役割 | 社内会議の記録を整理するが、決定や割り当ては行わない |
| 目的 | Word用議事録とExcel用タスク一覧を作る |
| 読者 | 会議参加者と研修運営の関係者 |
| 入力 | 区切り線内の完全架空の走り書きだけに限定する |
| 制約 | 未知の決定・担当・期限などを補わず、法務確認が必要という状態を保つ |
| 出力形式 | 議事録と、タスク・担当・期限の3列をタブで区切った一覧 |

### 段階ヒント2：基準成果物を確認する

照合の正本は[初回演習用の架空会議メモ](../../sample-data/beginner_meeting_notes.md)です。AI会話や完成成果物を正本にはしません。

| 確認項目 | 元資料と一致すべき状態 |
|---|---|
| 会議情報 | 架空AI研修運営改善会議／2026-07-08 |
| 参加者 | 氏名ではなく、4種類の役割だけ。実際の人数は不明 |
| 決定事項 | 明記された3件だけ |
| タスク | タスク名・担当・期限の3組が一致する |
| 録画 | 可否、確認担当、期限は未決。法務確認が必要 |
| フォローアップ会 | 実施可否と日程が未決 |
| 次回会議 | 日付、時刻、会場が未決 |
| 入力外の補完 | 未知の決定、担当、期限、日時、人物がない |
| Excel用形式 | 見出し1行とタスク3行、3列、タブ区切り |

### 1点改善の成果物例

おすすめは「要約」だけを追加する方法です。AI会話を利用できる場合は、基準出力を作った同じ会話へ次の指示を1回送ります。

```text
Word貼り付け用議事録の先頭に「3行要約」を追加し、決定事項3件だけを1件1行で要約してください。
それ以外の事実とExcel貼り付け用タスク一覧は変更しないでください。
```

改善後の先頭には、例えば次の内容が追加されます。

```text
3行要約
- 次回初心者研修では、教材の完全な架空データだけを使用する。
- 終了時チェックリストへのリンクを学習案内へ追加する。
- 会議終了時チェックリストを共有フォルダーへ置く。
```

表現が異なっても、3件とも元資料で決定と明記された内容だけなら成立します。未決事項やタスクを「決定」として要約してはいけません。

「読み手」を選ぶ場合の指示例は次のとおりです。

```text
Word貼り付け用議事録は、会議へ参加していない引継ぎ担当者にも分かる表現にしてください。
略語は使わず、それ以外の事実とExcel貼り付け用タスク一覧は変更しないでください。
```

読み手を変えても、新しい背景説明、会議目的、参加者、決定理由を作ってはいけません。分からない背景は説明せず、元資料にある表現の範囲で読みやすくします。

クイックスタートで実施済みの「期限の早い順へ並べ替える」指示だけを再度行うことは、この章の改善には数えません。

### AI操作で作る改善版の成果物例

元の確認済み成果物を比較用に残し、選んだ変更を追加指示として対話AIへ1回送ります。

- 要約を選んだ場合：決定事項3件を、議事録の先頭へ1件1行で示すようAIへ依頼する。
- 読み手を選んだ場合：略語や省略表現だけを分かりやすくし、事実を追加しないようAIへ依頼する。
- 変更後：AI出力を元資料と全件照合し、変更していない箇所まで確認する。

元の確認済み成果物は比較用に残します。成果物はMarkdownまたは紙へ記録しても構いませんが、追加指示の送信とAI出力の確認は省略しません。

### 改善後の再照合

| 確認対象 | 期待結果 | 改善が必要な例 |
|---|---|---|
| 選んだ1条件 | 読み手または要約の一つだけが変わった | 読み手と要約を同時に変えた |
| 決定事項 | 3件の内容と状態が元資料と一致する | 未決事項を要約へ混ぜた |
| タスク | 3件の名称・担当・期限が変わっていない | 担当や期限を言い換える過程で変更した |
| 未決事項 | 録画、フォローアップ会、次回会議が未決のまま | 担当、期限、日時、会場を作った |
| Excel用タスク一覧 | 内容と3列構成が基準出力から変わっていない | 読み手変更と無関係な列を追加した |
| 外部利用 | 送信・共有・公開していない | 完成確認前に共有リンクを作った |

### 成果物と完成条件

| 成果物 | 完成した状態 |
|---|---|
| 1点を改善する追加指示 | 読み手または要約のどちらか一つだけを指定している |
| 改善後のWord用議事録 | 選んだ変更が反映され、会議情報、決定3件、未決3件が元資料と一致する |
| Excel用タスク一覧 | タスク3件の名称、担当、期限、3列構成が保たれている |
| Officeを使えない場合 | Markdownまたは紙上で同じ変更と照合結果を示している |

保存するのは人が確認した改善版です。初回出力を別のメモ帳へ保存する作業は完成条件に含めません。外部共有・送信・公開も行いません。

### 一致必須・危険な状態・改善例

| 一致必須 | 自分で確かめる点 | 危険な状態・改善例 |
|---|---|---|
| 完成プロンプトの要素を説明できる | 各行がどの誤りや使いにくさを防ぐか説明したか | ロール指定だけを重要視している |
| 基準出力を再生成しすぎない | 既存会話を使い、ない場合だけ1回再現したか | 同じプロンプトを何度も送って回答を選ぶ |
| 1点だけ改善する | 指定した1点と実際の変化を対応付けたか | 複数条件を同時に変え、効果を説明できない |
| 未知の値を補わない | 未決事項へ担当・期限・日時・会場を作っていないか | 自然に見える推測を採用している |
| 改善後も再照合する | 決定・タスク・未決を全件確認したか | 基準出力だけを確認し、改善版は無確認である |

### 自己点検

元資料、基準成果物、改善版を横に並べて見比べます。文章の好みではなく、選んだ1条件だけが変わったか、決定・担当・期限・未決状態が保たれているかを優先します。正式な議事録として利用できるかはAIに決めさせず、実務では会議責任者が確認します。この教材の練習中は外部送信しません。

### 振り返り例

> 3行要約を追加すると決定をつかみやすくなった。一方、形式変更は事実変更の指示ではないため、要約だけでなく議事録とタスク一覧も元資料へ戻って再確認した。同じ会議分類を最初からやり直さず、確認済み成果物を比較基準にできた。

### 成立する別解

- 要約の表現が異なっても、決定3件だけを元資料の意味を変えずに示していれば成立します。
- 読み手を選び、元資料にない背景を加えず文章だけを平易にした場合も成立します。
- Wordを使わずMarkdownまたは紙へ結果を記録しても、対話AIで作った基準版と改善版を比較し、全件照合できれば成立します。
- 保存済み成果物を人の手だけで変更する方法は、AIへの追加指示を評価できないため本章の完了にはなりません。

### 危険な状態と修正

- 既存チャットがあるのに、クイックスタートの完成プロンプトを再送する。
- 同じプロンプトを複数回送り、好みの回答だけを採用する。
- クイックスタートと同じ期限順への並べ替えだけを、もう一度実施する。
- 読み手と要約を同時に変え、どの指示が影響したか分からなくなる。
- 要約へ未決事項を決定として混ぜる。
- 読み手に合わせるため、元資料にない会議目的や背景を作る。
- 改善後の議事録だけを見て、タスク一覧を再確認しない。
- 完成成果物をメール、共有リンク、公開リポジトリへ送る。

### 再挑戦のポイント

この章では分類操作をやり直しません。「確認済みの基準を再利用する」「別の1条件だけ変える」「変えていない部分も元資料と再照合する」のうち、抜けた工程を1つ選んでやり直します。既存チャットがない場合の1回の再送は、より良い回答を引き当てるためではなく、追加指示を試す基準を再現するためです。

- [ ] 成果物例をそのまま写さず、自分の差分理由を記録した
- [ ] 危険な状態に当たる箇所を先に修正した
- [ ] 追加指示または再照合記録を1点改善して再保存した
