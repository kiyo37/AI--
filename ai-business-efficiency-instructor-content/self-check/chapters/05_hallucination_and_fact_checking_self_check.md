# 05 ハルシネーションとファクトチェック 自己点検ガイド

- 本編：[05 ハルシネーションとファクトチェック](../../05_hallucination_and_fact_checking.md)
- 環境準備：[Perplexity演習環境セットアップ](../../setup/perplexity_setup.md)
- 対応練習：未検証の回答候補を主張へ分け、一次情報で検証する
- 公式情報の確認日：学習した日に自分で記録

## 先に行うこと

このページを最初から読み写さないでください。先に自分の`05_ファクトチェック記録.md`を保存し、次の順で使います。

1. 成果物を自分で作り、確認できない箇所は`不明`と書く。
2. 下の「段階ヒント」をヒント1から順に開く。
3. まだ直せない箇所だけ成果物例と比較する。
4. 差分を1点だけ修正し、元資料との照合をもう一度行う。

## 段階ヒント

<details>
<summary>ヒント1：どこへ戻るか</summary>

回答文ではなく、主張ごとに「誰・何／数値／日付／条件／因果関係」へ分けてください。検索結果の抜粋ではなく、発行元の原文へ戻ります。

</details>

<details>
<summary>ヒント2：最低限残す記録</summary>

`主張ID、判定、出典ID、発行主体、文書名・版、該当箇所、適用条件、確認日、不明点`が必要です。

</details>

<details>
<summary>ヒント3：Perplexityを使えない場合</summary>

承認済み対話AIで未検証文を主張へ分解し、本人または組織が利用を認めた別の検索サービスから公式原文を探します。検索結果の要約ではなく、発行元の原文を人が開いて照合します。承認済み対話AIまたは公式原文を利用できない場合は、環境を準備できるまで演習を停止します。

</details>

## 成果物例を見る前の注意

- 対話AIは未検証文を主張へ分解する補助、Perplexity等の検索サービスは出典候補を探す補助として使います。どちらも事実の最終確定者ではありません。
- Perplexityの回答文や検索結果の抜粋だけで判定せず、引用先の公式ページを人間が開き、該当箇所を読みます。
- 製品仕様と公式ページは更新されます。本書に固定の正解値を置かず、学習日に最新の公式原文を再確認します。
- 組織利用では承認済みの環境だけを使います。承認済み対話AIまたは公式原文を利用できない場合は、収録済み資料だけで完了にせず、環境を準備できるまで演習を停止します。
- 法律、医療、金融、個人の権利義務等の個別判断を本演習で確定しません。最新の一次情報を確認し、担当部署または有資格の専門家へ引き継ぎます。
- AI出力は人間が確認してから業務利用します。

## 利用環境の記入例

| 項目 | 記入例 |
|---|---|
| 対話AI | 本人が条件を確認したアカウント、または組織の承認済みアカウント。公開情報と教材の誤答候補だけを入力 |
| Perplexity | 承認済みアカウントと組織管理ブラウザを使用 |
| 公式原文 | `perplexity.ai` の公式ヘルプをブラウザで開く |
| 記録項目 | 主張、判定、公式URL・正規ドメイン、発行主体、文書名・版、公開・更新・適用日、訂正・撤回、相反する一次情報、確認日、該当見出し、条件、不明点 |
| 共有 | 検証記録を外部公開せず、組織利用では指定された保存・共有ルールに従う |
| Perplexity利用不可時 | 承認済み対話AIと別の利用可能な検索サービスを使い、公式原文を人が確認。対話AIまたは公式原文を利用できなければ停止 |

### 準備段階の記入例

```text
検証対象：Perplexity Webアプリの対応ブラウザに関する未検証文
基準日：学習日（YYYY-MM-DDで記録）
対話AIの役割：主張分解と確認項目の整理
Perplexityの役割：公式出典候補の探索
人間の役割：公式原文を開き、該当性・日付・条件を確認して判定
停止条件：公式原文が見つからない、対象・時点が違う、規約上利用できない
```

## 見本ケースの成果物例

### 3.1 検証対象

```text
PerplexityのWebアプリにはブラウザ上の制限が一切なく、すべての主要ブラウザで同じ機能を利用できます。
この内容は現在も有効な最新版であり、例外や対象プランの違いはありません。
```

これは根拠を示さず断定した未検証の候補です。正誤を教材へ固定せず、学習日に公式原文で確かめます。

### 3.2 対話AIによる主張分解の例

対話AIには事実確認をさせず、検証単位を作らせます。

| ID | 検証する主張 | 確認対象 | 望ましい一次情報 |
|---|---|---|---|
| C-01 | ブラウザ上の制限が一切ない | 対応条件・制限 | Perplexity公式ヘルプ |
| C-02 | すべての主要ブラウザで利用できる | 対応ブラウザと「すべて」の範囲 | Perplexity公式ヘルプ |
| C-03 | どのブラウザでも同じ機能を使える | ブラウザ・プラン・地域等による機能差 | Perplexity公式ヘルプ、公式リリース情報 |
| C-04 | 候補文は現在有効な最新版である | 文書の版、更新・適用日、訂正・撤回 | Perplexity公式ヘルプ、公式更新情報 |
| C-05 | 例外や対象プランの違いはない | 注意書き、例外、対象プラン・地域 | Perplexity公式ヘルプ |

望ましい対話AI出力は、正しさを断定せず、「一切」「すべて」「同じ」「最新版」「例外なし」という限定語と、対象・版・日付を別々にしたものです。

### 3.3 Perplexityによる出典候補探索の例

検索文例：

```text
Perplexity Webアプリの対応ブラウザを、Perplexity公式ヘルプだけから探してください。
公式ページ名、URL、更新日を示し、確認できない情報は推測しないでください。
```

出典候補として[Perplexityウェブアプリ対応ブラウザ](https://www.perplexity.ai/help-center/ja/articles/11502647-perplexity%E3%82%A6%E3%82%A7%E3%83%96%E3%82%A2%E3%83%97%E3%83%AA%E5%AF%BE%E5%BF%9C%E3%83%96%E3%83%A9%E3%82%A6%E3%82%B6)が示されたら、検索画面の要約で止めず、リンクを開きます。

### 3.4 公式原文との照合例

製品仕様は変わるため、具体的なブラウザ名・バージョンを固定しません。学習日に公式ページを確認し、次の表を同じIDで結んで完成させます。

| 主張ID | 判定例 | 出典ID |
|---|---|---|
| C-01 | 当日確認済み／誤り／不明 | S-01 |

| 主張ID | 公式原文から確認した要旨 | 適用条件・不明点 | 次の行動 |
|---|---|---|---|
| C-01 | 原文にある制限と注意書きを自分の言葉で記録 | 対象ブラウザ・プラン・地域等 | 断定を修正／不明のまま保留 |

| 出典ID | 公式URL・正規ドメイン | 発行主体 | 文書名・版 |
|---|---|---|---|
| S-01 | 当日確認 | Perplexity | 当日確認 |

| 出典ID | 公開・更新・適用日 | 訂正・撤回 | 相反する一次情報 | 確認日 |
|---|---|---|---|---|
| S-01 | 当日確認 | なし／あり／不明 | なし／あり／未調査 | YYYY-MM-DD |

相反する一次情報が見つかった場合は、新旧の版、文書の上下関係、対象範囲を確認します。解消できなければ「不明」とし、公式窓口または担当者へ確認します。

### 3.5 安全な修正文の例

```text
YYYY-MM-DDに、Perplexityが発行する公式ヘルプ（正規ドメイン：当日記録、文書名・版：当日記録）を確認しました。
確認できた条件は【原文の要旨】です。確認できなかった点は【不明点】です。
訂正・撤回と相反する一次情報は【確認結果】でした。
製品仕様は変わるため、利用時に公式ページと組織のブラウザ方針を再確認してください。
```

修正文では、確認日、公式発行元、対象、条件、変更可能性を示します。検索結果の文章を長く転載せず、要旨とURLを記録します。

## 自分で行う練習の成果物例

実務テーマを変えても、主張表と出典確認表をIDで結びます。記入欄は3.4と同じ形式を使います。

### 作業記録例

| 工程 | 実施内容 | 残した記録 |
|---|---|---|
| 質問を限定 | 対象製品、基準日、用途を明記 | 質問文 |
| 対話AI | 未検証文を最小の主張へ分解 | 主張IDと確認項目 |
| Perplexity | 公式ドメインの出典候補を探索 | 検索文、候補URL |
| 公式サイト | 正規ドメインからリンク先を開き、該当箇所を人が確認 | 発行主体、文書名・版、日付、見出し、要旨、訂正・撤回 |
| 相反確認 | 同じ論点を扱う別の一次情報を確認 | 一致・相反、版・適用範囲、未解消事項 |
| 判定 | 主張ごとに確認済み・誤り・不明を記録 | 判定理由と不足情報 |
| 修正 | 確認できた内容だけで回答を書き直す | 修正文と確認者 |

公式情報が見つからない場合は「まとめ記事で補う」のではなく、「不明と記録し、回答から外すか公式窓口へ確認する」とします。

## 自己レビューの記録例

| レビュー指摘 | 修正例 | 理由 |
|---|---|---|
| Perplexityの要約だけを根拠にした | 公式ページを開き、該当見出しと確認日を追加 | 出典表示もAI処理を含むため |
| URLが公式なので全主張を確認済みにした | 主張ごとに本文との一致を再確認 | URLの実在と主張の該当は別だから |
| 更新日だけを見た | 対象仕様の基準日と適用条件を追加 | ページ更新日と内容の適用時点は別だから |
| 検索上位の似たドメインを公式と判断した | 公式トップページからたどり、正規ドメインと発行主体を記録 | 表示名や見た目だけでは公式性を確認できないため |
| 訂正・撤回と相反資料を確認していない | 文書の版と更新情報、相反する一次情報を追加確認 | 古い原文や一方の発表だけでは誤判定する可能性があるため |
| 「おそらく」を確認済みにした | 不明へ変更し、確認先を記載 | 推測で空欄を埋めないため |
| 同じ質問を対話AIへ再入力した | 一次情報との照合へ変更。組織利用で別確認が必要なら正式な確認者へ回す | 同じ誤りを繰り返す可能性があるため |

## 振り返りの記入例

- 信じそうになった表現：「一切ない」「すべて」「同じ」「最新版」「例外なし」のような断定。
- Perplexityだけでは分からなかったこと：検索要約が公式ページの注意書きを省いている可能性。
- 原文を開いて変わった判断：対象、制限、例外、版、適用日の扱い。
- 今後残す情報：質問、基準日、公式URL・正規ドメイン、発行主体、文書名・版、公開・更新・適用日、訂正・撤回、相反資料、確認日、該当見出し、確認者。

## 一致必須の内容と改善例

| 一致必須の観点 | 完成した状態 | 改善例 |
|---|---|---|
| 主張分解 | 数値、日付、限定語、条件を別々にする | 一文を丸ごと判定している場合は一事実ずつ分ける |
| ツールの役割 | 対話AIは分解、検索サービスは探索、人は原文照合 | AIに最終判定させた場合は役割表へ戻る |
| 出典確認 | 公式リンクの該当箇所を読む | 検索抜粋だけなら原文の見出しと要旨を記録する |
| 日付 | 発行・更新日と内容の基準日を区別する | 「最新」とだけ書いた場合は具体日を追加する |
| 出典の身元 | 正規ドメイン、発行主体、文書名・版を記録する | 表示名だけなら公式トップページからたどり直す |
| 変更・相反 | 訂正・撤回、相反する一次情報、確認日を記録する | 一つの原文だけなら更新情報と別の一次情報を探す |
| 不明の扱い | 推測せず不明を残す | 断定へ直した場合は根拠の有無を再確認する |
| 高リスク領域 | 一般論の整理にとどめ専門家へ引き継ぐ | 個別助言を作った場合は利用を止め、担当者へ渡す |

## 成立する別解・追加の誤り分析例

### 成立する別解

- 本人または組織が利用条件を確認した対話AIで、未検証文を主張へ分ける。
- Perplexityを使わず、利用条件を確認した通常の検索エンジンで公式ドメインを指定して探す。
- 公式原文しかない場合は、検索AIを介さず直接照合する。
- 判定名が異なっても、根拠と不明点が明確ならよい。「部分確認」等を追加してもよい。

### 保存済みAI出力を追加分析する例

1. 本章の対話AI操作と公式原文の照合を先に完了します。
2. [収録済みの問題出力](../../sample-outputs/video_meeting_ai_minutes_problem.md)を開きます。
3. 主張ごとに切り分け、検証台帳へ転記します。
4. [文字起こし](../../sample-data/video_meeting_transcript.md)と[照合用メモ](../../sample-data/video_meeting_verification_notes.md)から根拠へ線を引きます。
5. 「確認済み・誤り・不明」を付け、断定を避けた修正文を紙またはMarkdownへ書きます。
6. 問題出力を閉じ、原文と台帳だけを使って自分で再照合します。

この保存済み出力は誤りを見つける追加材料です。これだけを紙上で照合しても、対話AIで主張を分解する実操作の代わりにはならず、本章の完了条件を満たしません。

## 危険な状態

- 検索結果の抜粋やAIの再回答だけで`確認済み`にしている
- URLが実在するだけで、本文との一致、版、適用範囲を確認していない
- 確認できない内容を推測で補っている
- 法律、医療、金融などの個別判断を自己点検だけで確定している

一つでも当てはまる場合は成果物を利用せず、該当する主張を`不明`へ戻します。

## 再挑戦

1. 成果物例との最大の差を1点だけ選びます。
2. 対応する原文へ戻り、修正理由と根拠を記録します。
3. 修正した主張だけでなく、変更していない主張も再照合します。
4. 完成後も、製品仕様に関する内容は利用時点の公式ページを再確認します。
