# 03 業務プロセス分析：成果物例と自己点検

- 元教材：[03 業務プロセス分析](../../03_business_process_analysis.md)
- 使用様式：[業務分析シート](../../templates/business_analysis_sheet.md)
- 対応演習：対話AIと業務分析シートで月次問い合わせ報告を分解する

## 1. 自己点検の進め方

1. このページを読む前に、業務分析シートを保存します。
2. 最初は「段階ヒント」だけを読み、自分で1回見直します。
3. 次に「一致必須」と成果物例を比較し、AI案を採用・修正・却下した理由を確認します。
4. 「危険な状態」に当てはまる箇所は、外部送信や高影響判断へ進まない設計へ修正します。
5. 最後に改善点を1つだけ選び、成果物を再保存します。

- 本書は唯一の完成形ではありません。業務目的、社内規程、利用環境、担当者の権限により適切な分解は変わります。
- 対話AIの案を写すのではなく、現場の事実と照合し、採用・修正・却下の理由を残すことが重要です。
- 問い合わせ、氏名、数値は教材用の架空例です。実在者の情報を加工して演習へ転用しません。
- 実業務へ適用する場合は、最新の製品公式情報、自社規程、契約を確認します。個人情報、契約、雇用、与信等が関係するときは担当部署または専門家へ確認します。
- 組織利用では管理者発行の業務用アカウントだけを使い、承認済み環境でも教材に記載された完全な架空データだけを使います。未承認の場合は演習を停止し、正式窓口へ確認します。

## 2. 開始前の一致必須と記入例

| 項目 | 記入例 |
|---|---|
| 学習方法 | 本人が条件を確認した対話AI、または組織が用意した承認済み対話AIを使用 |
| 入力データ | 実在者を元にしていない架空の業務条件だけ |
| 使用様式 | 業務分析シートの複製 |
| 保存先 | 組織が指定した限定共有フォルダー。個人学習では自分だけが閲覧できる学習用フォルダー |
| 共有範囲 | 学習者本人。組織利用では必要な確認担当者だけ |
| 画面共有 | 通知、別案件のタブ、ファイル名を非表示 |
| 利用不可時 | 演習を停止し、承認・利用条件を確認した対話AIを準備してから再開 |

### 開始前の成果物例

```text
承認済み環境：確認済み
入力するもの：架空業務の説明、架空件数、分類基準の例
入力しないもの：実在の問い合わせ本文、顧客名、担当者名、未公開資料
AIの役割：分解漏れと確認質問の候補を出す
人の役割：現行業務の確定、分類、承認、停止判断
AI実操作：架空業務を入力し、分解候補の採用・修正・却下を記録
```

## 3. 段階ヒントと成果物例

対象は「架空の問い合わせメールを受け取り、担当部署へ振り分ける」です。

まず、各動作の入出力と未確認事項を整理します。

| 動作ID | 動作 | 入力 | 出力 | 要確認 |
|---|---|---|---|---|
| P-01 | 受信対象を確認 | 共有受信箱、対象期間 | 対象一覧 | 締切後の追加受信 |
| P-02 | 必須情報を点検 | 架空メール本文 | 欠落一覧 | 添付の扱い |
| P-03 | 内容を分類 | 本文、分類基準 | 分類候補 | 新しい問い合わせ種別 |
| P-04 | 担当部署を決定 | 確定分類、担当表 | 振分先 | 兼務部署の優先順位 |
| P-05 | 記録して引継ぐ | 振分結果 | 履歴、担当通知 | 期限・緊急度 |

次に、同じ動作IDを使って役割を分けます。

| 動作ID | 通常の自動化 | AI補助 | 人間判断 |
|---|---|---|---|
| P-01 | 期間条件で抽出 | なし | 対象外窓口を決める |
| P-02 | 件名・受付番号の有無 | 不足候補の抽出 | 本当に不足か確定 |
| P-03 | 明確なキーワード規則 | 意味に基づく候補 | 複数分類・例外を確定 |
| P-04 | 承認済み対応表 | なし | 例外時の担当を決定 |
| P-05 | 定型記録・通知 | 通知文案 | 宛先と内容を確認 |

### 対話AI案に対する人間の修正例

| 対話AI案 | 人間の判断 | 理由 |
|---|---|---|
| AIが担当部署を確定し、自動送信する | 修正 | 例外と誤送信の影響があるため、AIは候補までとする |
| 感情分析で緊急度を決める | 却下 | 緊急度は契約・安全・期限等の業務基準で決める |
| 欠落項目を一覧化する | 採用 | 元文を人が確認でき、最終判断を残せる |
| 顧客へ即時に回答する | 却下 | 対外回答は内容・権限・宛先の承認が必要 |

## 4. 実務演習：月次問い合わせ報告の成果物例

### 4.1 業務の境界

| 項目 | 記入例 |
|---|---|
| 業務目的 | 問い合わせ傾向を把握し、改善候補を責任者へ提示する |
| 開始 | 対象月の受付が締まり、対象データが利用可能になる |
| 完了 | 責任者が件数、上位テーマ、根拠、改善案を確認して承認する |
| 主な入力 | 架空問い合わせ、承認済み分類基準、報告様式 |
| 主な出力 | 確認記録付き月次報告書 |
| 主な例外 | 欠損、重複、複数テーマ、分類不能、重大案件、合計不一致 |

### 4.2 データ取扱い確認

| 確認項目 | 記入例 |
|---|---|
| 個人情報・第三者情報 | 学習用に一から作った架空問い合わせのみ。実在情報なし |
| データ所有者 | 架空資料の管理者。本番利用では実データの所有部署を別途確認 |
| 利用・AI処理の権限 | 本教材の架空ケースを自己学習または組織が承認した学習で使う範囲だけ |
| 法令・契約・守秘義務 | 実在情報を使わない。利用するAIの契約・設定が不明なら演習を停止して確認 |
| 保存・削除 | 個人学習は非公開の学習用フォルダー、組織利用は指定先へ保存し、それぞれの正式手順で終了確認 |
| 処理地域・再委託 | 個人学習は本人、組織利用は正式担当者が利用サービスの契約資料で確認。不明なら入力しない |
| 出力・ログの所有者・閲覧者 | 個人学習では本人だけ。組織利用では組織が管理し、本人と必要な確認担当者に限定 |
| PoC終了時 | 共有権限を撤回し、入力・出力・ログ・一時ファイルの削除を確認 |

### 4.3 動作分解と役割分担

下表の所要時間は架空業務の処理指標であり、学習者を評価する数値ではありません。

| # | 動作 | 主な入力 | 主な出力 | 所要時間例 |
|---:|---|---|---|---:|
| 1 | 対象範囲を確定 | 報告条件 | 対象・除外条件 | 5分 |
| 2 | データを抽出 | 架空問い合わせ300件 | 対象一覧 | 5分 |
| 3 | 形式と件数を検査 | 対象一覧 | エラー一覧 | 10分 |
| 4 | 入力禁止情報を点検 | 検査済み一覧 | 停止・相談一覧 | 10分 |
| 5 | 重複・対象外候補を出す | 検査済み一覧 | 除外候補 | 10分 |
| 6 | 分類基準の版を確定 | 分類表 | 承認済み基準 | 5分 |
| 7 | 分類候補を作る | 架空本文、基準 | 候補、根拠、不明点 | 10分 |
| 8 | 例外を確定 | 候補、元本文 | 確定分類、保留 | 20分 |
| 9 | 件数を集計 | 確定分類 | 集計表 | 5分 |
| 10 | 根拠例候補を抽出 | 集計、架空本文 | 根拠候補 | 10分 |
| 11 | 報告草案を作る | 集計、根拠、様式 | 草案 | 10分 |
| 12 | 数値と表現を照合 | 草案、元集計 | 修正版 | 20分 |
| 13 | 指定形式へ整える | 修正版、様式 | 報告書案 | 10分 |
| 14 | 承認または差戻し | 報告書案、記録 | 承認済み報告書 | 15分 |

例外と役割は、同じ番号で次の表へ記録します。

| # | 主な例外 | 担当の考え方 |
|---:|---|---|
| 1 | 締め日変更 | 人が判断 |
| 2 | 抽出失敗 | 通常の自動化 |
| 3 | 文字化け | 通常の自動化 |
| 4 | 情報分類不明 | 自動検知候補＋人が判断 |
| 5 | 類似する別案件 | 通常の自動化＋人が判断 |
| 6 | 新分類が必要 | 人が判断 |
| 7 | 複数テーマ | AI補助 |
| 8 | 判断材料不足 | 人が判断 |
| 9 | 合計不一致 | 通常の自動化 |
| 10 | 代表性が低い | AI補助＋人が判断 |
| 11 | 原因の断定 | AI補助 |
| 12 | 数値・因果不一致 | 人が判断 |
| 13 | 表示崩れ | 通常の自動化＋AI補助 |
| 14 | 根拠不足 | 権限者が判断 |

### 4.4 Before / Afterの記入例

| 指標 | Before例 | Afterの目標例 | 測り方 |
|---|---:|---:|---|
| 総作業時間 | 240分 | 160分以下 | 抽出から承認までを実測 |
| 人の確認時間 | 80分 | 60分以下 | 照合、修正、差戻しを含む |
| 分類一致率 | 82% | 90%以上 | 人が事前確定した架空例と比較 |
| 集計の重大誤り | 月1件 | 0件 | 合計・上位テーマの不一致を記録 |
| 根拠のない原因断定 | 月2件 | 0件 | 元資料で支えられない表現を記録 |
| 情報混入 | 0件 | 0件 | 発生時は処理を停止 |

目標値は架空ケース用です。実務では現状値、許容リスク、監視可能性を基に業務責任者が決めます。時間短縮を達成しても、重大誤りや情報混入が増えれば採用しません。

### 4.5 PoC案

| 項目 | 記入例 |
|---|---|
| 仮説 | 人間確認を残しながら総作業時間を減らし、重大誤りを増やさない |
| 対象 | 一から作った架空問い合わせ50件 |
| テスト構成 | 通常例30件、境界例10件、欠落・矛盾・異常入力等の例外例10件 |
| 比較 | 同じデータを現行手順とAI補助手順で処理 |
| AIの範囲 | 分類候補、根拠候補、報告草案 |
| 人の範囲 | 対象確定、例外分類、数値照合、原因判断、最終承認 |
| 成功条件 | 事前に決めた品質・安全条件を満たし、確認を含む総作業が改善する |
| 停止条件 | 情報混入、重大誤分類、根拠のない断定、承認前送信、意図しない自動実行 |
| 復旧 | 処理停止、事実記録、責任者報告、原因確認、必要なら従来手順へ戻す |
| 段階展開 | 非公開試行で評価後、責任者承認を得て限定利用。対象拡大は再評価後 |
| 継続監視 | 分類一致、修正時間、苦情、重大誤り、情報事故、費用を月次確認 |
| PoC終了時 | 連携・アクセス権を撤回し、指定した入力・出力・ログ・一時ファイルを消去して確認記録を残す |

この50件で重大誤りが0件でも、安全が証明されたとは判断しません。この標本では問題が観測されなかった可能性を残し、別の境界例・例外例、限定利用後の実績、苦情・事故を継続して確認します。

## 5. 自己点検：修正記録例

| 指摘 | 修正 | 判断理由 |
|---|---|---|
| 分類不能を通常問い合わせへ入れている | 「保留」へ分離 | 材料不足を無理に確定しないため |
| AIが改善案で原因を断定している | 「可能性」「追加確認が必要」へ変更 | 集計だけでは因果関係を示せないため |
| 送信工程の承認者がない | 業務責任者の承認ゲートを追加 | 対外影響と責任を明確にするため |
| Afterが生成速度だけ | 確認・修正・差戻しを含む総作業へ変更 | 部分最適を避けるため |

## 6. 振り返り：記入例

- 対話AIが有用だった点：例外、入力・出力、確認質問の候補を短時間で広げられた。
- 人間が直した点：分類基準の正式版、承認者、原因断定、外部送信の扱い。
- 通常の自動化へ任せる点：形式検査、承認済み規則による集計、定型整形。
- 次に試す最小範囲：架空データで分類候補だけを作り、外部送信や確定処理は行わない。
- 着手前の相談先：業務責任者、情報セキュリティ、個人情報担当。

### 自分の業務への転用成果物例

実際のメール、顧客名、案件名、社内数値等は書かず、非機密の業務メタデータだけで作る例です。

| 項目 | 記入例 |
|---|---|
| 業務の一般名 | 定例報告の下書き |
| 困りごと | 情報の並べ方が担当者ごとに異なり、確認で手戻りが出る |
| 最初に簡素化 | 報告項目と見出しを共通テンプレート化する |
| AI補助候補 | 完全な架空入力から、テンプレートに沿う文章草案を作る |
| 人の役割 | 元資料照合、数値・原因・重要度の判断、承認、共有。高影響判断は担当部門・専門家が行う |
| 情報の扱い | 実際の内容は記載・入力せず、区分と相談先だけを記録する |
| 架空テスト | 通常、項目欠落、数値矛盾の3種類を一から作る |
| 成功・停止 | 確認を含む総時間を測定。未確認数値や情報混入があれば停止 |
| 次の行動 | この案を業務責任者と情報管理担当へ渡し、実データPoCは学習外の正式審査にする |

## 7. 一致必須・危険な状態・改善例

| 一致必須 | 自分で確かめる点 | 危険な状態・改善例 |
|---|---|---|
| 業務の境界 | 開始と完了を状態で説明する | 「報告書作成」だけなら、開始資料と承認済み状態を追加する |
| 動作の粒度 | 誰が何を見て何を変えるか分かる | 「確認する」を、数値照合、例外判定、承認へ分ける |
| 役割分担 | 通常処理、AI補助、人の判断に理由がある | ツール名から決めた場合は、再現性・誤りの影響・検出可能性へ戻る |
| 効果 | 時間、品質、安全、費用を扱う | 生成速度だけなら確認・修正・差戻しを追加する |
| 安全設計 | 停止、報告、復旧の担当がある | 成功条件だけなら停止条件と従来手順への戻し方を追加する |
| AI案の扱い | 採否と理由が記録される | AI案を写しただけなら現場担当者との照合欄を追加する |

## 8. 成立する別解・記録方法

### 成立する別解

- AIを分類に使わず、報告書の構成と文章草案だけへ限定する。
- 集計を表計算関数、データベース、通常のワークフローで行う。
- 動作数が例と異なっても、判断、例外、承認が埋もれず理由を説明できる。
- 処理件数、期限遵守、担当者間のばらつきなど、業務目的に合う別の指標を使う。

### AI操作前後を紙や付箋で記録する例

1. 付箋へ一枚一動作を書き、開始から完了まで並べます。
2. 青を通常の自動化、黄をAI補助、赤を人間判断として印を付けます。
3. 架空業務を対話AIへ入力し、AIが示した分解候補を付箋と比較します。
4. AI候補ごとに「採用・修正・却下」と理由を書きます。
5. 業務分析シートへ転記し、例外、承認、停止、復旧を追記します。
6. 自己点検後の差分を別色で残します。

紙、付箋、Markdownは比較と記録の媒体です。対話AIを利用できない場合は、この記録だけで演習完了にしません。

## 9. 再挑戦のポイント

「AIを使った箇所の多さ」ではなく、適切な境界とレビューができたかを確認します。曖昧な動作を1つ選び、`誰が／何を見て／何を変え／どこへ渡すか`へ分けてからシートを1点修正します。実務導入の判断は一人で行わず、業務責任者と、必要に応じて情報セキュリティ、個人情報、法務等の担当部署・専門家へつなぎます。

- [ ] 成果物例をそのまま写さず、AI案の採否理由を記録した
- [ ] 危険な状態に当たる箇所を先に修正した
- [ ] 動作の粒度、停止条件、効果指標のいずれか1点を改善して再保存した
