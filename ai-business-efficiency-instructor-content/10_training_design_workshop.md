# 10 AI業務効率化研修 設計ワークショップ

> 用語に迷ったときは、[用語集](glossary.md)も参照してください。

## 1. この章の目的

受講者の実務行動が変わるAI業務効率化研修を設計します。知識の網羅ではなく、対象業務、安全な判断、演習、観察、研修後の定着を一貫させます。

### 本章の主要用語

| 用語 | 初心者向けの意味 |
|---|---|
| ハンズオン | 受講者が実際に手を動かし、作成・確認・修正・停止を練習する演習 |
| モジュール | 学習目的に応じて選び、組み合わせられる研修の単元 |
| アクセシビリティ | 障害、年齢、利用端末などにかかわらず、参加・理解しやすくする配慮。「アクセシブル」は、その配慮がなされた状態を指す |
| KPI（Key Performance Indicator／重要業績評価指標） | 目標への進み具合を測る重要な指標 |
| PoC（Proof of Concept／概念実証） | 本格導入前に、対象を限定して効果・安全性・運用上の課題を確かめる小規模な試行 |
| Before / After | 改善前の手順・負担と、改善後の手順・負担を並べて変化を確認する考え方 |
| 観察記録 | 点数で順位を付けるのではなく、できた行動、迷った場面、次に改善する行動を書き残すもの |

## 2. 学習ゴール

- 研修ニーズから行動ベースの学習目標を作れる
- 基礎・実践・役割別のモジュールを組み合わせて研修を設計できる
- 安全で実務に近いハンズオンの完成条件と観察ポイントを設計できる
- 読みやすくアクセシブルなスライド・表・ワークを設計できる
- 受講者アンケートと実務KPIを使い分けられる
- 研修後の定着支援を業務の節目に合わせて設計できる
- 模擬登壇と質疑対応の観察・改善方法を説明できる

## 3. 本編解説

### 3.1 研修設計の基本手順

| 手順 | 問い | 成果物 |
|---:|---|---|
| 1. 依頼確認 | なぜ今、誰の何を変えるのか | 依頼背景、対象、制約 |
| 2. 現状分析 | 現在の業務、スキル、事故、ツールは | 受講者像、業務マップ |
| 3. 目標設定 | 研修後に何を実演・判断できるか | 行動目標、完成条件 |
| 4. 内容選定 | 目標に必要な最小内容は | モジュール構成、扱う範囲 |
| 5. 演習設計 | どの判断を手で練習するか | 架空データ、手順、観察ポイント |
| 6. 実施条件 | アカウント、端末、規程、支援は | 事前案内、代替手順 |
| 7. 振り返り | 学習・行動・業務成果をどう確かめるか | 観察記録、KPI、追跡計画 |
| 8. 改善 | 何を次回直すか | 改訂履歴、改善担当 |

悪い目標：「ChatGPTを理解する」。良い目標：「架空の会議メモから議事録草案を作り、入力にない決定を特定・修正できる」。

### 3.2 研修要件ヒアリング

- 対象者の職種、人数、経験、利用できるツール
- 改善したい業務と現状の時間・品質・事故
- データ分類、承認済みツール、入力禁止情報、相談先
- 絶対にAIへ任せない判断と、責任者
- 端末、ネットワーク、アカウント、アクセシビリティ
- 研修後に上司が支援できる時間と制度

要件が未確定なら、実データ・実システムを使う演習は行いません。

### 3.3 基礎モジュール

対象は生成AIを初めて業務で検討する人です。研修時間へ先に内容を詰め込まず、受講者が必要な行動を選んで組み合わせます。

| 単元 | 学ぶ行動 | 方法 | 完成条件 |
|---|---|---|---|
| 利用前判断 | 入力してよい情報と止める情報を分ける | 架空ケース分類 | 判断理由と相談先を説明できる |
| 仕組みと限界 | 得意・不得意、ハルシネーション、人間確認を説明する | 誤答例の比較 | AI出力を確定情報として扱わない |
| プロンプト | 目的、前提、制約、出力形式を指定する | 草案の修正 | 要件不足を見つけて改善できる |
| 出力レビュー | 元情報、根拠、禁止事項と照合する | チェック表 | 修正・破棄・相談の判断を記録できる |
| 業務分解 | AI、人、自動化の担当を切り分ける | 業務カード | 人が判断する工程と責任者を示せる |

すべてを実施する必要はありません。研修目的に直結する単元を選び、残りは事前資料または次の学習機会へ回します。

### 3.4 実践モジュール

対象は、担当業務の改善案を作る人です。基礎モジュールで扱った安全判断を前提に、実務に近い架空ケースへ進みます。

| 単元 | 学ぶ行動 | 成果物 | 人間レビュー |
|---|---|---|---|
| 業務分析 | Beforeの工程、負担、ミスを整理する | 業務マップ | 現場担当者が実態と照合する |
| 役割分担 | AI・固定ルール・人の判断を分ける | Afterマップ | 責任者と承認箇所を確認する |
| 安全な試行 | 対象を限定したPoCを設計する | 対象、完成条件、停止条件 | 管理部門と現場が実施可否を判断する |
| RAG・自動化 | 根拠検索や承認付き連携を構想する | データ・権限・ログの図 | 権限外アクセスと外部送信を確認する |
| 改善提案 | 効果だけでなく費用・リスク・運用を示す | 提案書草案 | 前提と未確認事項を明記する |

実践モジュールは、受講者が持ち込んだ実データをAIへ入力する場ではありません。組織が別途承認した場合を除き、完全な架空データを使用します。

### 3.5 管理職モジュール

管理職には操作量より、意思決定と責任を重視します。

| 研修単元（モジュール） | 主な問い |
|---|---|
| 機会 | どの業務成果を狙い、何を測るか |
| リスク | 入力、誤答、権利、偏り、自動実行の影響は |
| 責任 | 利用者、承認者、情シス、法務、経営の役割は |
| 投資 | PoC、教育、運用、監査を含む総費用は |
| 定着 | 現場に安全な時間・相談先・評価制度があるか |

演習は、3つの提案を「承認・条件付き・差戻し」に分類し、条件とKPIを決めるケース会議が適しています。

### 3.6 教育担当モジュール

- 行動目標と演習・振り返りの対応付け
- 初心者がつまずく用語の言い換え
- 架空データと失敗例の作成
- AIで作った教材の正確性、難易度、著作権、偏りのレビュー
- 模擬講義、相互フィードバック、改訂管理

成果物は、講師台本、スライド構成、演習、完成例、観察ポイント、FAQです。

### 3.7 情報システム部門（情シス）モジュール

この節では、次の情報システム分野の用語を使います。

- **アーキテクチャ**：モデル、データ、検索、外部連携などをどう組み合わせるかを示す、システム全体の構成。**データフロー**は、その中で情報がどこからどこへ流れるかを表します。
- **アイデンティティ管理**：利用者が誰で、どの組織・役割・権限を持つかを確認・管理すること。**SSO（Single Sign-On／シングルサインオン）**は、1回の共通認証で複数サービスへログインできるようにする仕組みです。
- **データ越境**：データを国外へ送信・保存・処理すること。適用法令、契約、保存地域は、法務・個人情報保護・セキュリティなどの担当者や専門家へ確認します。
- **サービス提供者（ベンダー）評価**：提供会社の安全対策、契約条件、障害対応、再委託先などが自社要件を満たすか確認すること。

| 領域 | 扱う内容 |
|---|---|
| アーキテクチャ | モデル、RAG、連携、データフロー |
| アイデンティティ管理 | SSO、最小権限、退職・異動対応 |
| データ | 分類、保存、削除、データ越境、バックアップ |
| セキュリティ | プロンプト注入、秘密情報、コネクタ（外部サービスとの接続部品）、サービス提供者評価 |
| 運用 | ログ、監視、費用上限、障害、手動復旧 |
| 変更管理 | モデル・プロンプト・文書・フローの版管理 |
| 評価 | 正確性、未回答、権限違反、レッドチーム |

**レッドチーム**は、攻撃者や誤用者の視点で弱点を試す活動です。実施範囲と権限を事前合意します。

### 3.8 ハンズオン設計

良いハンズオンは、操作だけでなく判断を含みます。

| 要素 | 設計内容 |
|---|---|
| 目的 | 実務行動を一つに絞る |
| データ | 完全な架空データ、権利確認済み素材 |
| 手順 | 入力前確認→生成→検証→修正→承認 |
| 完成例 | 必要な要素を示すが、唯一解にしない |
| 失敗例 | 誤情報、過剰入力、曖昧な決定など |
| 観察 | 結果だけでなく判断理由と検証記録を見る |
| 代替 | アカウント障害時の紙上・録画・ペア実施 |
| 安全 | 実メール送信・実データ入力・自動実行を禁止 |

**演習の難易度**は、模倣→一部変更→新しいケースへ転用→他者へ説明、の順に上げます。

入力可否が「禁止」または「不明」ならAIへの入力を中止し、一から作った承認済みの架空データへ差し替えられない場合は紙上演習へ切り替えます。出力を安全に修正・再検証できない場合も利用を止め、停止理由を記録します。

### 3.9 教材・表・ワークの見やすさ

投影資料と記入用ワークは目的が異なります。情報量を同じにしません。

| 教材 | 推奨 | 避けること |
|---|---|---|
| 投影スライド | 1枚1メッセージ、結論を見出しへ | 文章の読み上げ、横長の大表 |
| 比較表 | 投影は3〜5列、重要セルを言葉でも説明 | 小さい文字、色だけの区別 |
| 記入ワーク | 記入例、空欄、提出物、完成条件を明示 | 9列以上を狭い画面で入力させる |
| 講師メモ | 誤解、問いかけ、代替手順、停止条件 | スライド本文へ全て詰め込む |
| 完成例 | 演習後に表示し、判断理由を説明 | 唯一の正解として先に配る |

- 横に長い業務分析表は、A3横向きまたは表計算版で配布する
- 文字サイズ、行間、余白、コントラストを確保する
- 正誤やリスクを赤・緑だけで区別せず、記号と文字を併用する
- 画像には代替説明、動画には字幕、口頭指示には書面を用意する
- マウス操作が難しい場合のキーボード・紙上代替を用意する
- 表の前後に「この表から何を判断するか」を一文で示す

アクセシビリティ上の必要な配慮は、本人と研修担当者へ事前確認します。個人の事情を無断で共有しません。

### 3.10 受講者アンケート例

研修直後の満足度だけでは業務効果は分かりません。

**自己効力感**とは、「自分ならその行動を実行できる」と本人が感じる度合いです。実際に必要な技能を持っているかとは別に確認します。

| 設問 | 形式 | 目的 |
|---|---|---|
| 学習目標と内容が一致していた | 一致した／一部不明／一致しなかった＋理由 | 設計の妥当性（目的に合っているか） |
| 入力禁止情報を説明できる | 自分でできる／支援があればできる／まだ難しい＋理由 | 自信と実演結果の差を見る |
| 業務をAI・人・自動化に分けられる | 自分でできる／支援があればできる／まだ難しい | 自己効力感 |
| 最も役立った演習と理由 | 自由記述 | 継続・改善判断 |
| 不明点・不安・相談したい用途 | 自由記述 | フォロー題材 |
| 次に試す架空／低リスク業務 | 自由記述 | 行動計画 |
| 研修で扱うべきでなかった内容 | 自由記述 | 安全・負荷の把握 |

### 3.11 研修効果の4段階

| 段階 | 測るもの | 例 |
|---|---|---|
| 反応 | 役立ち感、難易度 | アンケート |
| 学習 | 知識・技能 | 振り返り、実演の観察記録 |
| 行動 | 実務での実践 | 初回実践後の利用記録、上司確認 |
| 成果 | 業務指標 | 総時間、差戻し、重大誤り、利用停止件数 |

### 3.12 研修後の定着支援

| 節目 | 施策 | 確認すること |
|---|---|---|
| 研修直後 | 承認済み用途と相談窓口を確認する | 次に試す業務と停止条件が明確か |
| 初回実践前 | 上司・管理部門と入力データ、ツール、承認者を確認する | 実施許可と代替手順があるか |
| 初回実践後 | プロンプト、出力、修正、判断理由を振り返る | 見落としと改善点を記録できたか |
| 継続利用中 | オフィスアワー（決めた時間帯の質問・相談会）と安全な事例共有を行う | 相談、差戻し、ヒヤリハットを把握できるか |
| 定期見直し | KPI、権限、利用ルール、教材を見直す | 継続・変更・停止を判断できるか |

上司が利用時間、承認、相談を支援しないと、研修だけで定着させるのは困難です。

### 3.13 登壇・質疑・デモ失敗の練習

設計した教材は、必ず模擬登壇で検証します。説明の流暢さだけでなく、受講者への問いかけ、安全な停止、未回答質問の扱い、代替進行を観察します。具体的な方法は [11 登壇・改善実践](11_instructor_delivery_practicum.md) を使います。

## 4. 実務での使いどころ

- 顧客への研修提案、見積り、要件定義（目的、対象、必要機能、安全条件、制約、完成条件を実施前に明確にすること）
- 対象者別の教材・デモ・演習選定
- 模擬登壇と講師への観察フィードバック
- 研修後のPoC、相談会、事例共有の設計

## 5. 講師メモ

- 冒頭で「今日できるようになる行動」と「扱わない範囲」を明示します。
- デモが失敗しても学習になるよう、スクリーンショット、出力例、紙上演習を用意します。
- 回答速度の速い受講者だけを基準にせず、ペア、読み上げ、休憩、文字サイズなどに配慮します。
- アンケート満足度を成果と呼ばず、初回実践後と継続利用中の行動・業務指標まで合意します。

## 6. 演習

### 総合演習：研修モジュールとスライド草案を作る

架空の「青葉サービス社・営業事務部門」を対象とします。課題はメール草案と会議後タスク整理のばらつきです。ChatGPTで研修構成を検討し、Canva AIまたはGammaのどちらか一方でスライド草案を作ります。両方へ登録する必要はありません。

#### 1. 利用環境の準備確認

| 状況 | 進め方 |
|---|---|
| 個人学習 | 本人が規約・料金・データ設定を確認したChatGPTと、Canva AIまたはGammaの一方を使う。完全な架空情報だけを入力する |
| 企業研修 | 組織が承認・発行したアカウントだけを使う。登録、外部共有、公開、ブランド素材利用は管理者の指示に従う |
| 一部だけ利用可能 | ChatGPTで構成を作り、スライドはMarkdownまたは付箋で作る。スライドツールだけ利用可能なら講師配布の構成案を使う |
| 未承認・利用不可 | どのサービスにも登録せず、配布カードと[スライド構成テンプレート](templates/training_slide_outline.md)で紙上作成する |

利用前に[共通準備](setup/common_preparation.md)と[Canva AI・Gammaの準備](setup/canva_gamma_setup.md)を確認します。実在企業の情報、実在受講者の個人情報、未許諾の画像・ロゴは使いません。

#### 2. ガイド付き練習

ChatGPTを使える場合は、次のように依頼します。使えない場合は同じ項目を紙上で埋めます。

```text
あなたは企業研修の設計補助者です。次の完全な架空ケースについて、
「基礎」「実践」「対象者別」のモジュール候補を作ってください。

対象：架空の青葉サービス社の営業事務担当
課題：メール草案と会議後タスク整理のばらつき
必須：入力前の安全確認、AI出力の人間レビュー、紙上代替
出力：行動目標／演習／完成条件／観察ポイント／実務定着策

不足情報があれば、構成を確定する前に質問してください。
```

AI案はそのまま採用せず、依頼目的、受講者像、社内ルールと照合して修正します。

#### 3. 実務演習

1. 基礎、実践、管理職、教育担当、情シスから必要なモジュールを選びます。
2. 各モジュールに行動目標、架空データ演習、完成条件、観察ポイント、紙上代替を設定します。
3. ChatGPTで講師説明とスライド見出しの草案を作り、人が内容を編集します。
4. Canva AIまたはGammaの一方へ、承認済みの草案だけを渡してスライド草案を作ります。利用できなければMarkdownまたは付箋で作ります。
5. 研修後の初回実践前・実践後・定期見直しで行う支援を決めます。

#### 4. 人間レビュー

- 学習目標、説明、演習、完成条件が同じ行動へつながっているか
- AIが作った説明に事実誤認、断定、対象者に難しい用語がないか
- 入力禁止情報、人間確認、停止、相談先を扱っているか
- 画像・文章・ロゴの利用権と出典を確認したか。法的な個別判断は専門家へ確認するか
- 文字量、表、コントラスト、代替説明、参加方法に配慮したか
- 外部共有・公開が無効で、完成後も責任者が承認する流れか

#### 5. 振り返り

- AI案から削除・修正した内容と、その理由は何か。
- 固定時間ではなくモジュール式にしたことで、どの対象者へ調整しやすくなったか。
- ChatGPT、選んだスライドツール、人間の担当をどのように分けたか。
- 実務定着を妨げそうな条件と、研修外で必要な支援は何か。

**提出物**：モジュール構成、スライド草案、講師メモ、ハンズオン、完成条件、観察記録、紙上代替、定着支援案。

## 7. 実務チェックリストと振り返り

この節は採点しません。研修設計者として必要な行動がそろっているか確認します。

- [ ] 依頼背景と対象業務から、観察できる行動目標を作れる
- [ ] 基礎・実践・役割別モジュールから必要な内容だけを選べる
- [ ] 架空データ、失敗例、人間レビュー、紙上代替を含むハンズオンを作れる
- [ ] 完成条件と観察ポイントを、点数や順位を付けずに示せる
- [ ] ChatGPTとCanva AIまたはGammaの役割を、人間の編集・承認と分けられる
- [ ] アカウント未承認時に登録を求めず、紙上作成へ切り替えられる
- [ ] アンケート、実演、業務KPIを目的別に使い分けられる
- [ ] 初回実践前後と定期見直しの支援を設計できる

**振り返り**：研修後に受講者ができるようになる行動を一つ挙げ、その行動をどの演習で観察し、誰が実務で支援するか説明してください。説明が難しい専門用語は、一言の意味と業務例を講師メモへ追記してください。

## 8. まとめ

研修は、対象者の実務課題から行動目標を作り、必要なモジュールを選び、架空データで安全に判断を練習する設計です。AIが作った構成やスライドは人が確認・修正します。直後の満足度で終わらせず、管理職と連携して初回実践と継続利用の行動・業務成果を追います。
