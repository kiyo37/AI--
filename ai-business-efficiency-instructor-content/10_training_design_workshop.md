# 10 AI業務効率化研修 設計ワークショップ

> 用語に迷ったときは、[用語集](glossary.md)も参照してください。

## 1. この章の目的

受講者の実務行動が変わるAI業務効率化研修を設計します。知識の網羅ではなく、対象業務、安全な判断、演習、評価、研修後の定着を一貫させます。

### 本章の主要用語

| 用語 | 初心者向けの意味 |
|---|---|
| ハンズオン | 受講者が実際に手を動かし、作成・確認・修正・停止を練習する演習 |
| アクセシビリティ | 障害、年齢、利用端末などにかかわらず、参加・理解しやすくする配慮。「アクセシブル」は、その配慮がなされた状態を指す |
| KPI（Key Performance Indicator／重要業績評価指標） | 目標への進み具合を測る重要な指標 |
| ルーブリック | 成果物や実演を、観察できる段階別の基準で採点する表 |

## 2. 学習ゴール

- 研修ニーズから行動ベースの学習目標を作れる
- 3時間・1日・役割別の研修構成を作れる
- 安全で実務に近いハンズオンと採点基準を設計できる
- 読みやすくアクセシブルなスライド・表・ワークを設計できる
- 受講者アンケートと実務KPIを使い分けられる
- 30・60・90日の定着支援を設計できる
- 模擬登壇と質疑対応の評価方法を説明できる

## 3. 本編解説

### 3.1 研修設計の基本手順

| 手順 | 問い | 成果物 |
|---:|---|---|
| 1. 依頼確認 | なぜ今、誰の何を変えるのか | 依頼背景、対象、制約 |
| 2. 現状分析 | 現在の業務、スキル、事故、ツールは | 受講者像、業務マップ |
| 3. 目標設定 | 研修後に何を実演・判断できるか | 行動目標、合格基準 |
| 4. 内容選定 | 目標に必要な最小内容は | 章立て、時間配分 |
| 5. 演習設計 | どの判断を手で練習するか | 架空データ、手順、採点表 |
| 6. 実施条件 | アカウント、端末、規程、支援は | 事前案内、代替手順 |
| 7. 評価 | 学習・行動・業務成果をどう測るか | テスト、KPI、追跡計画 |
| 8. 改善 | 何を次回直すか | 改訂履歴、改善担当 |

悪い目標：「ChatGPTを理解する」。良い目標：「架空の会議メモから議事録草案を作り、入力にない決定を特定・修正できる」。

### 3.2 研修要件ヒアリング

- 対象者の職種、人数、経験、利用できるツール
- 改善したい業務と現状の時間・品質・事故
- データ分類、承認済みツール、入力禁止情報、相談先
- 絶対にAIへ任せない判断と、責任者
- 端末、ネットワーク、アカウント、アクセシビリティ
- 研修後に上司が支援できる時間と制度

要件が未確定なら、実データ・実システムを使う演習は行いません。

### 3.3 3時間研修の構成例

対象：生成AI初心者の全社員。休憩10分を含む180分です。

| 時間 | 内容 | 方法 | 成果物 |
|---:|---|---|---|
| 0〜10分 | 目的、ルール、事前チェック | 説明・投票 | 利用可否の認識 |
| 10〜35分 | 生成AIの仕組み・得意不得意 | ミニ講義・誤答デモ | 用語メモ |
| 35〜60分 | セキュリティ、個人情報、正確性 | ケース分類 | 入力判断表 |
| 60〜85分 | プロンプトの基本 | 比較デモ | 基本テンプレート |
| 85〜95分 | 休憩 |  |  |
| 95〜130分 | メールまたは議事録ハンズオン | 個人→ペア | 草案・検証表 |
| 130〜155分 | 業務分解 | グループ | AI／人の役割表 |
| 155〜170分 | 発表・相互レビュー | 発表 | 改善点 |
| 170〜180分 | 確認テスト・次の行動 | テスト | 7日以内の実践計画 |

短時間ではRAGやエージェントを詳説せず、概念と相談先に留めます。

### 3.4 1日研修の構成例

対象：部門の業務改善担当。次の例は実働6時間15分＋昼休憩・小休憩です。6時間に収める場合は、対象業務を事前課題で分解し、午後の業務分解を15分短縮します。

| 時間帯 | 内容 | 演習 |
|---|---|---|
| 09:30〜10:00 | 目的、現状、利用ルール | 自己評価 |
| 10:00〜10:45 | 基礎、ツール選定 | 業務別候補比較 |
| 10:45〜11:30 | プロンプト設計 | 草案→採点→改善 |
| 11:30〜12:00 | セキュリティ・ハルシネーション | リスク判断 |
| 13:00〜14:15 | 業務分解 | Beforeマップ |
| 14:15〜15:00 | AI・人・自動化の切り分け | Afterマップ |
| 15:15〜16:00 | RAG・自動化・エージェント概論 | 承認付き構想 |
| 16:00〜16:45 | 改善提案とPoC | KPI・停止条件 |
| 16:45〜17:00 | 発表、テスト、次の行動 | 30日計画 |

### 3.5 管理職向け研修

管理職には操作量より、意思決定と責任を重視します。

| 研修単元（モジュール） | 主な問い |
|---|---|
| 機会 | どの業務成果を狙い、何を測るか |
| リスク | 入力、誤答、権利、偏り、自動実行の影響は |
| 責任 | 利用者、承認者、情シス、法務、経営の役割は |
| 投資 | PoC、教育、運用、監査を含む総費用は |
| 定着 | 現場に安全な時間・相談先・評価制度があるか |

演習は、3つの提案を「承認・条件付き・差戻し」に分類し、条件とKPIを決めるケース会議が適しています。

### 3.6 教育担当者向け研修

- 行動目標と確認問題の対応付け
- 初心者がつまずく用語の言い換え
- 架空データと失敗例の作成
- AIで作った教材の正確性、難易度、著作権、偏りのレビュー
- 模擬講義、相互フィードバック、改訂管理

成果物は、講師台本、スライド構成、演習、解答、採点基準、FAQです。

### 3.7 情報システム部門向け研修

この節では、次の情報システム分野の用語を使います。

- **アーキテクチャ**：モデル、データ、検索、外部連携などをどう組み合わせるかを示す、システム全体の構成。**データフロー**は、その中で情報がどこからどこへ流れるかを表します。
- **アイデンティティ管理**：利用者が誰で、どの組織・役割・権限を持つかを確認・管理すること。**SSO（Single Sign-On／シングルサインオン）**は、1回の共通認証で複数サービスへログインできるようにする仕組みです。
- **データ越境**：データを国外へ送信・保存・処理すること。適用法令、契約、保存地域は、法務・個人情報保護・セキュリティなどの担当者や専門家へ確認します。
- **サービス提供者（ベンダー）評価**：提供会社の安全対策、契約条件、障害対応、再委託先などが自社要件を満たすか確認すること。

| 領域 | 扱う内容 |
|---|---|
| アーキテクチャ | モデル、RAG、連携、データフロー |
| アイデンティティ管理 | SSO、最小権限、退職・異動対応 |
| データ | 分類、保存、削除、データ越境、バックアップ |
| セキュリティ | プロンプト注入、秘密情報、コネクタ（外部サービスとの接続部品）、サービス提供者評価 |
| 運用 | ログ、監視、費用上限、障害、手動復旧 |
| 変更管理 | モデル・プロンプト・文書・フローの版管理 |
| 評価 | 正確性、未回答、権限違反、レッドチーム |

**レッドチーム**は、攻撃者や誤用者の視点で弱点を試す活動です。実施範囲と権限を事前合意します。

### 3.8 ハンズオン設計

良いハンズオンは、操作だけでなく判断を含みます。

| 要素 | 設計内容 |
|---|---|
| 目的 | 実務行動を一つに絞る |
| データ | 完全な架空データ、権利確認済み素材 |
| 手順 | 入力前確認→生成→検証→修正→承認 |
| 成功例 | 合格基準を示すが、唯一解にしない |
| 失敗例 | 誤情報、過剰入力、曖昧な決定など |
| 採点 | 結果だけでなく判断理由と検証記録 |
| 代替 | アカウント障害時の紙上・録画・ペア実施 |
| 安全 | 実メール送信・実データ入力・自動実行を禁止 |

**演習の難易度**は、模倣→一部変更→新しいケースへ転用→他者へ説明、の順に上げます。

入力可否が「禁止」または「不明」ならAIへの入力を中止し、一から作った承認済みの架空データへ差し替えられない場合は紙上演習へ切り替えます。出力を安全に修正・再検証できない場合も利用を止め、停止理由を記録します。

### 3.9 教材・表・ワークの見やすさ

投影資料と記入用ワークは目的が異なります。情報量を同じにしません。

| 教材 | 推奨 | 避けること |
|---|---|---|
| 投影スライド | 1枚1メッセージ、結論を見出しへ | 文章の読み上げ、横長の大表 |
| 比較表 | 投影は3〜5列、重要セルを言葉でも説明 | 小さい文字、色だけの区別 |
| 記入ワーク | 記入例、空欄、提出物、時間を明示 | 9列以上を狭い画面で入力させる |
| 講師メモ | 誤解、問いかけ、時間、停止条件 | スライド本文へ全て詰め込む |
| 解答例 | 演習後に表示し、判断理由を説明 | 唯一の正解として先に配る |

- 横に長い業務分析表は、A3横向きまたは表計算版で配布する
- 文字サイズ、行間、余白、コントラストを確保する
- 正誤やリスクを赤・緑だけで区別せず、記号と文字を併用する
- 画像には代替説明、動画には字幕、口頭指示には書面を用意する
- マウス操作が難しい場合のキーボード・紙上代替を用意する
- 表の前後に「この表から何を判断するか」を一文で示す

アクセシビリティ上の必要な配慮は、本人と研修担当者へ事前確認します。個人の事情を無断で共有しません。

### 3.10 受講者アンケート例

研修直後の満足度だけでは業務効果は分かりません。

**自己効力感**とは、「自分ならその行動を実行できる」と本人が感じる度合いです。実際に必要な技能を持っているかとは別に確認します。

| 設問 | 形式 | 目的 |
|---|---|---|
| 学習目標と内容が一致していた | 1〜5 | 設計の妥当性（目的に合っているか） |
| 入力禁止情報を説明できる | 1〜5＋小テスト | 自信と知識の差を見る |
| 業務をAI・人・自動化に分けられる | 1〜5 | 自己効力感 |
| 最も役立った演習と理由 | 自由記述 | 継続・改善判断 |
| 不明点・不安・相談したい用途 | 自由記述 | フォロー題材 |
| 7日以内に試す架空／低リスク業務 | 自由記述 | 行動計画 |
| 研修で扱うべきでなかった内容 | 自由記述 | 安全・負荷の把握 |

### 3.11 研修効果の4段階

| 段階 | 測るもの | 例 |
|---|---|---|
| 反応 | 役立ち感、難易度 | アンケート |
| 学習 | 知識・技能 | 確認問題、実技採点 |
| 行動 | 実務での実践 | 30日後の利用記録、上司確認 |
| 成果 | 業務指標 | 総時間、差戻し、重大誤り、利用停止件数 |

### 3.12 研修後の定着支援

| 時期 | 施策 | 指標 |
|---|---|---|
| 0〜7日 | 承認済み用途を1件試す、相談窓口案内 | 実践計画提出率 |
| 2〜4週 | オフィスアワー（決めた時間帯の質問・相談会）、プロンプト・事例レビュー | 相談件数、修正率 |
| 30日 | 部門内の安全な事例共有 | 実践率、総時間、品質 |
| 60日 | 失敗例と利用ルールの再確認 | ヒヤリハット（事故には至らなかったが、一歩間違えば事故になり得た事例）、差戻し |
| 90日 | KPI・権限・教材の見直し | 継続・変更・停止判断 |

上司が利用時間、承認、相談を支援しないと、研修だけで定着させるのは困難です。

### 3.13 登壇・質疑・デモ失敗の練習

設計した教材は、必ず模擬登壇で検証します。説明の流暢さだけでなく、受講者への問いかけ、安全な停止、未回答質問の扱い、時間、代替進行を評価します。具体的な方法は [11 登壇・評価実践](11_instructor_delivery_practicum.md) を使います。

## 4. 実務での使いどころ

- 顧客への研修提案、見積り、要件定義（目的、対象、必要機能、安全条件、制約、合格基準を実施前に明確にすること）
- 対象者別の教材・デモ・演習選定
- 模擬登壇と講師評価
- 研修後のPoC、相談会、事例共有の設計

## 5. 講師メモ

- 冒頭で「今日できるようになる行動」と「扱わない範囲」を明示します。
- デモが失敗しても学習になるよう、スクリーンショット、出力例、紙上演習を用意します。
- 回答速度の速い受講者だけを基準にせず、ペア、読み上げ、休憩、文字サイズなどに配慮します。
- アンケート満足度を成果と呼ばず、30〜90日後の行動・業務指標まで合意します。

## 6. 演習

### 総合演習：3時間研修を設計する（120分）

架空の「青葉サービス社・営業事務20名」を対象とします。課題はメール草案と会議後タスク整理のばらつきです。利用できるのは組織承認済み対話AI、実データは禁止とします。

1. 行動目標を3つ作ります。
2. 180分の構成を作り、講義は全体の40%以下にします。
3. 架空データのハンズオンを1つ作ります。
4. 入力判断、出力検証、業務分解を採点するルーブリックを作ります。
5. アカウント障害時の代替手順を作ります。
6. 直後・30日・90日の評価を決めます。
7. 10分の模擬講義を実施し、相互評価で改善します。
8. 投影スライド1枚と記入ワーク1枚を、文字量・表の列数・色以外の区別・代替説明の観点でレビューします。

テンプレートは [training_slide_outline.md](templates/training_slide_outline.md) を使用します。

## 7. 確認問題

1. 行動目標が「理解する」だけでは不十分な理由は何ですか。
2. 3時間研修で全機能を教えるべきでない理由は何ですか。
3. 良いハンズオンに失敗例を含める理由は何ですか。
4. 満足度だけで研修成果を判断できないのはなぜですか。
5. 研修後の定着に管理職が必要な理由は何ですか。
6. 投影用の表と記入用ワークを同じ情報量にしない理由は何ですか。

<details><summary>解答例</summary>

1. 観察・評価できず、実務で何を行えば修了か分からないためです。
2. 時間内に判断と実践を身につけるため、対象業務と安全性に必要な内容へ絞る必要があるためです。
3. 誤りを検出・修正・停止する力が実務で必要だからです。
4. 満足しても知識、行動、業務時間、品質が改善したとは限らないためです。
5. 実践時間、承認、相談、評価、業務変更の権限を支援できるためです。
6. 投影では短時間で要点を理解する必要があり、記入用では判断過程と記録欄が必要だからです。目的に応じて列数・文字量・配布形式を変えます。

</details>

## 8. まとめ

研修は、対象者の実務課題から行動目標を作り、架空データで安全に判断を練習し、明確な基準で評価する設計です。直後の満足度で終わらせず、管理職と連携して30・60・90日の行動と業務成果を追います。
