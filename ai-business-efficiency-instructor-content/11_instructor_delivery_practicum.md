# 11 AI業務効率化講師の登壇・評価実践

> 用語に迷ったときは、[用語集](glossary.md)も参照してください。

## 1. この章の目的

設計した教材を、安全かつ分かりやすく届ける登壇力を身につけます。説明、問いかけ、演習進行、質疑、反対意見、デモ失敗、時間管理を模擬講義で練習し、観察可能な基準で改善します。

**ルーブリック**とは、成果物や実演を、観察できる段階別の基準で採点する表です。本章では、講師の話し方の好みではなく、受講者の理解、安全な進行、質疑対応などの行動を評価します。

## 2. 学習ゴール

- 専門用語を「一言説明・例・注意点」で説明できる
- 受講者の発言を引き出し、誤解を安全に修正できる
- 答えられない質問を推測せず、確認先と回答期限を示せる
- デモや通信が失敗しても、紙上演習へ切り替えられる
- 20分の模擬講義をルーブリックで評価・改善できる

## 3. 本編解説

### 3.1 講師に必要な5つの実践能力

| 能力 | 観察できる行動 | よくある失敗 |
|---|---|---|
| 説明 | 定義、業務例、限界を短く話す | 用語を別の用語で説明する |
| 進行 | 目的、時間、手順、提出物を明示する | 説明が長く演習時間を削る |
| 問いかけ | 判断理由と根拠を受講者から引き出す | 正解をすぐ講師が言う |
| 安全管理 | 入力前確認、停止、相談を実演する | デモの便利さを優先する |
| 改善 | 観察記録から次回の行動を一つ変える | 満足度だけで成功とする |

### 3.2 初心者へ説明する5段階

1. **結論**：「生成AIは下書きの補助で、最終判断者ではありません」。
2. **一言定義**：30秒以内で用語を説明する。
3. **身近な例**：メール、会議、報告など受講者の業務へつなぐ。
4. **非例・限界**：「医療判断を任せる」のような不適切例を示す。
5. **確認質問**：「この例で人が確認するのは何ですか」と問い返す。

スライドを読み上げるのではなく、受講者が自分で判断を言葉にする時間を作ります。

### 3.3 ファシリテーションの基本

**ファシリテーション**は、参加者の発言や作業を促し、学習目標へ沿って場を進めることです。

| 場面 | 講師の問いかけ例 |
|---|---|
| 業務分解 | 「開始と完了は何ですか」「誰が承認しますか」 |
| リスク判断 | 「何が起きたら困りますか」「誤りをどう見つけますか」 |
| プロンプト改善 | 「どの要件が不足していますか」「採点基準は何ですか」 |
| 事実確認 | 「その主張を支える原文はどこですか」 |
| 振り返り | 「AIへ任せなかった部分と、その理由は何ですか」 |

沈黙があってもすぐ答えを言わず、個人思考→ペア相談→全体共有の順にすると参加しやすくなります。

### 3.4 反対意見・不安への対応

| 発言例 | 避ける応答 | 推奨する応答 |
|---|---|---|
| 「AIは危険だから全部禁止すべき」 | 危険ではないと否定 | 懸念を具体化し、禁止・条件付き・許可へ分ける |
| 「AIなら必ず時短できる」 | 成功例だけを示す | 確認時間を含むBefore / Afterで検証する |
| 「自分の仕事がなくなる」 | 大丈夫と断定 | 変わる作業、残る判断、必要な学習を業務単位で整理する |
| 「別のAIでは違う回答だった」 | 正解の製品を決める | 元資料と評価基準で比較する |
| 「会社のルールが分からない」 | 一般論で許可する | 入力を止め、正式な相談先を確認する |

講師は不安を評価・否定せず、「何が不明か」「誰が決めるか」「次に何を確認するか」へ変換します。

### 3.5 質疑応答の境界

質問へ即答することより、誤答しないことを優先します。

```text
現時点では断定できません。
確認が必要なのは、{法令・契約・製品仕様・社内規程・個別事情}です。
{公式情報／担当部門／専門家}へ確認し、{期限・方法}で回答します。
それまでは{入力・公開・実行}を止めてください。
```

| 質問 | 講師が答えられる範囲 | 引き継ぐ先 |
|---|---|---|
| 製品の操作 | 確認済み環境の一般手順 | 管理者・公式サポート |
| 自社の入力可否 | 判断枠組みと確認事項 | セキュリティ・個人情報担当 |
| 著作権・契約の個別判断 | 一般的論点 | 法務・知財・専門家 |
| 医療・金融・法律の助言 | AIを最終判断にしない原則 | 有資格の専門家 |
| 事故・誤入力 | 停止・記録・報告 | 社内の事故対応窓口 |

未回答は、質問、質問者、確認先、担当、回答期限、回答内容を一覧で管理します。

### 3.6 安全なライブデモ

| デモ前 | デモ中 | デモ後 |
|---|---|---|
| 架空データ、通知非表示、履歴・タブ確認 | 入力内容を読み上げ、送信前に一度止まる | 出力の誤りと確認箇所を示す |
| 承認済みアカウント・機能を確認 | 外部送信・実システム実行をしない | 会話・ファイルの保存条件を確認 |
| 成功例、失敗例、画像、紙上代替を準備 | 予想外の出力を正解扱いしない | デモ結果を教材の固定仕様にしない |

通信・アカウント障害時は、画面の復旧に時間を使い続けず、3分を目安に事前保存した出力例または紙上演習へ切り替えます。

### 3.7 時間管理

20分模擬講義の例です。

| 時間 | 内容 | 講師の行動 |
|---:|---|---|
| 0〜2分 | 目的・安全ルール | 終了時の行動を一つ示す |
| 2〜6分 | 一言解説 | 定義、例、限界を説明 |
| 6〜8分 | デモまたは比較 | 観察ポイントを先に示す |
| 8〜14分 | 個人・ペア演習 | 進捗確認し、答えを言いすぎない |
| 14〜17分 | 共有・解説 | 判断理由と根拠を扱う |
| 17〜19分 | 確認問題 | 全員が答えられる方法を使う |
| 19〜20分 | まとめ | 行動、停止条件、相談先を再提示 |

### 3.8 アクセシブルな進行

**アクセシビリティ**は、障害、年齢、利用端末などにかかわらず参加・理解しやすくする配慮です。

- 色だけで正誤を区別せず、文字・記号も使う
- 小さな文字や横に長すぎる表を避け、配布版を用意する
- 動画に字幕、画像に代替説明、口頭指示に書面を用意する
- キーボード操作や紙上参加など代替手段を用意する
- 読み書き・発言速度だけで理解度を判断しない
- 休憩、ペア選択、匿名質問など参加方法を複数にする

必要な配慮は本人・研修担当者へ事前確認し、個人の事情を全体へ無断共有しません。

### 3.9 模擬講義の評価ルーブリック

**責任分界**とは、AI、利用者、承認者、管理者などが、それぞれどこまで確認・判断・対応するかを区切ることです。

| 評価軸 | 1：不足 | 2：基礎 | 3：実務 | 4：講師レベル |
|---|---|---|---|---|
| 目標 | 内容だけ紹介 | 目標を提示 | 行動と合格基準を提示 | 目標・演習・評価が一貫 |
| 説明 | 用語の読み上げ | 定義を説明 | 例・非例・限界を説明 | 受講者の言葉で再説明させる |
| 問いかけ | 一方的 | 質問あり | 判断理由を引き出す | 沈黙・誤答を学習へ変える |
| 安全 | 注意のみ | 禁止事項を提示 | 停止・相談を実演 | 想定外出力・事故にも対応 |
| 演習 | 操作模倣 | 手順どおり | 検証・修正を含む | 実務転用と責任分界まで扱う |
| 質疑 | 推測で即答 | 不明と回答 | 確認先を示す | 期限・記録・暫定対応まで示す |
| 時間 | 大幅超過 | 終了 | 演習時間を確保 | 反応に応じ調整して目標達成 |
| 配慮 | 一つの参加方法 | 資料配布 | 複数の参加方法 | 個別配慮を安全に調整 |

合格目安は全項目3以上、安全と質疑は3未満を不可とします。

## 4. 実務での使いどころ

- 初登壇前の社内模擬講義
- 顧客向けデモの安全確認
- 講師同士の相互評価と標準化
- 研修事故・アンケート・未回答質問を使った改善会議

## 5. 講師メモ

- 流暢さより、説明の正確さ、受講者の判断、安全な停止を評価します。
- 模擬講義の録画は、参加者の同意、保存期間、閲覧範囲を決めます。
- 反対意見を「抵抗」と片付けず、未解決の業務・安全要件として扱います。
- 受講者の質問に個人情報・機密が含まれそうなら、発言を止めて**架空化**（実在する氏名、組織、数値などを、一から作った架空情報へ置き換えること）します。単に氏名を伏せるだけで安全と判断しません。
- 講師自身のAI出力も根拠確認し、訂正が必要な場合は記録して周知します。

## 6. 演習

### 演習：20分模擬講義と障害対応（90分）

1. `01〜10`から一つのテーマを選びます。
2. 行動目標を一つ、確認問題を一つ決めます。
3. 架空データを使う5分の演習を入れます。
4. 「通信障害」「AIが入力外の事実を生成」「法的な個別質問」のカードから一つを観察者が途中で提示します。
5. 講師は代替進行、誤答修正、専門家への引継ぎを行います。
6. [模擬登壇観察シート](templates/instructor_observation_sheet.md)で自己・観察者評価し、次回に変える行動を一つ決めます。

**役割**：講師、受講者、観察者。3人で交代します。

**提出物**：20分台本、スライドまたは配布資料、演習、未回答質問票、評価表、改善記録。

## 7. 確認問題

1. 講師が答えをすぐ言わず、判断理由を尋ねるのはなぜですか。
2. 法的な個別質問へ即答しない場合、何を伝えるべきですか。
3. デモ障害時に紙上演習を用意する理由は何ですか。
4. 反対意見を否定せず扱う手順を説明してください。
5. アクセシビリティ配慮を2つ挙げてください。

<details><summary>解答例</summary>

1. 受講者が実務で再現できる判断過程を練習し、誤解の原因を把握するためです。
2. 断定できないこと、確認すべき事項、確認先、回答方法・期限、それまでの停止条件を伝えます。
3. 製品や通信の成否に左右されず、行動目標と判断練習を完了するためです。
4. 懸念を具体化し、影響・根拠・決定者を確認し、禁止・条件付き・許可または追加確認へ整理します。
5. 色だけで区別しない、字幕や代替説明を用意する、書面指示を出す、参加方法を複数用意する、などです。

</details>

## 8. まとめ

講師の価値は、知識量だけでなく、受講者が安全に判断できる場を作ることにあります。短く説明し、根拠を問い、誤答を修正し、不明時は確認先へつなぎます。デモ失敗や反対意見も事前に練習し、模擬講義の観察記録から改善を続けます。
