# 学習用：プロンプト受入テスト記録

> [!TIP]
> 横長の表はGitHubでは横へスクロールします。`ID`または`問題ID`を共通キーに、まず`分類・不足`、次に`安全処理・影響`、最後に`判定・修正`のまとまりで記入してください。

このシートは、[プロンプト受入テスト演習](../exercises/prompt_acceptance_testing_exercises.md)で使います。[架空の一次判定規程](../sample-data/prompt_acceptance_policy.md)と[架空の問い合わせ8件](../sample-data/prompt_acceptance_cases.md)を横に開いてください。

> AIの文章が自然かではなく、規程の各条件へ合っているかを人が確認します。AIに「正しいですか」と尋ねた回答やAIの自己評価は、人間レビューの根拠にしません。

### 開始判定

- [ ] 入力するのは[収録された完全な架空データ8件](../sample-data/prompt_acceptance_cases.md)だけ
- [ ] 実在の問い合わせ、氏名、連絡先、社員番号、認証情報を追加しない
- [ ] 承認済みAI以外へ貼り付けない
- [ ] メール送信、チケット登録・更新、リンクを開く操作を行わない
- [ ] v1とv2で同じ8件、同じ順序、同じAI環境を使う
- [ ] 最終成果物の保存先が決まっている

1つでも確認できない場合は開始せず、利用環境の管理者または組織の正式窓口へ確認します。

## 4. 変更履歴

一度に複数の規則を変えると、どの変更が効いたか分からなくなります。1行につき1つだけ変更し、変更対象のケースで確認します。最終版v2ができたら、8件すべてを再実行します。

| 版 | 変更した1点 | 対象の問題ID・ケース | 変更直後の確認結果 | 予想外の悪化 | 維持／戻す |
|---|---|---|---|---|---|
| v1.1 |  |  |  |  |  |
| v1.2 |  |  |  |  |  |
| v1.3 |  |  |  |  |  |
| v1.4 |  |  |  |  |  |
| v1.5 |  |  |  |  |  |
| v1.6 |  |  |  |  |  |
| v1.7 |  |  |  |  |  |
| v1.8 |  |  |  |  |  |
| v1.9 | 認証情報時の停止ルール | 該当ケースなし | 設計済み・実行未確認 | 未確認 | 維持／保留 |
| v2.0 | 表現と順序だけを整理。新しい規則は追加しない | 全変更 | 全8件で再テストへ進む |  |  |

変更が6件未満なら、不要な版を削除して構いません。変更が多い場合は行を追加します。版番号の数をそろえることが目的ではありません。

## 9. 最終成果物と終了処理

### 保存する成果物

- [ ] 最終版プロンプトv2
- [ ] v1・v2の8件結果表
- [ ] 1点ずつの変更履歴
- [ ] 利用範囲
- [ ] 停止条件

推奨ファイル名は`プロンプト受入テスト_最終版.md`または演習で示した推奨名です。Excelを使った場合は、同じ内容を`プロンプト受入テスト結果.xlsx`へ保存できます。Excelを利用できない場合は、このMarkdownシートへ記入します。印刷物は人間レビューのメモにだけ使い、v1・v2のAI実行は省略しません。

### 終了確認

- [ ] 外部メール、外部チャット、実システムへ送信・書き込みしていない
- [ ] 教材外の実在情報を保存していない
- [ ] 自分で意図した範囲または組織指定外の共有リンクを作っていない
- [ ] 不要な一時コピーやチャット履歴を、個人学習ではサービスの公式手順、組織利用では組織の規程に従って処理した
- [ ] 共有PCを使った場合はファイルを閉じ、承認済みアカウントからサインアウトした
- [ ] 削除可否が不明な記録は自己判断で消さず、管理者へ確認した
