# 教材保守・公開チェックリスト

初回公開、大きな変更、安定版Releaseの前に使います。チェック欄の完了は、自動検査の成功だけではなく、必要な人の確認も終わったことを意味します。

## 1. 公開リポジトリの配置

- [ ] 教材フォルダーの**中身**を、単独の公開リポジトリの最上位に置いた
- [ ] GitHubのトップに`README.md`が表示される
- [ ] `README.md`から`START_HERE.md`へ進める
- [ ] ZIPダウンロード版でも相対リンクと必要ファイルがそろっている
- [ ] 親リポジトリの他のファイルや履歴を、教材リポジトリへ誤って含めていない

## 2. 公開範囲と秘密情報

- [ ] 自己学習に不要な運営専用資料、個別進捗記録、実在案件が含まれていない
- [ ] 実在する企業名、個人情報、社内URL、認証情報、未公開数値、実際のAI入出力がない
- [ ] 現在のファイルだけでなくGit履歴も秘密情報について確認した
- [ ] 生成過程の切れた出力、ツールログ、デバッグメッセージが教材へ混入していない
- [ ] `.gitignore`がリポジトリ内へ誤って作られた`learning-artifacts/`を除外している（標準の`ai-learning-work/`はリポジトリ外に作る）
- [ ] GitHubのSecret scanningとpush protectionの利用可否を確認した

## 3. 権利と利用条件（公開前の必須ゲート）

- [ ] すべての著作権者と公開権限を確認した
- [ ] 共同著作、勤務先、委託契約、第三者素材の関係を確認した
- [ ] `LICENSE`が自己学習、組織内の限定利用、改変、再配布、第三者向け研修の方針と一致している
- [ ] `NOTICE.md`へ第三者素材と商標の扱いを記録した
- [ ] 許諾権限を持つ担当者と、非公開で連絡できる許諾窓口を決めた
- [ ] `CONTRIBUTING.md`の寄稿許諾条件と受付方針を確認した
- [ ] 法務・知財担当者または専門家が最終確認した

**上記が完了するまで、安定版Release、第3項の個別許諾、外部Pull Requestの取込みを行わない。**

## 4. 公開コミュニティの安全性

- [ ] Issue Formの安全確認が必須になっている
- [ ] 空白Issueが無効になっている
- [ ] Issue Formが存在しないラベルを前提にしていない、または必要なラベルを作成した
- [ ] `SECURITY.md`の非公開報告方法をGitHub設定で利用できる
- [ ] `SUPPORT.md`と`CODE_OF_CONDUCT.md`が、現在の維持管理体制と連絡方法に一致している
- [ ] 個別事故、法律・医療・金融・人事判断を公開Issueへ誘導していない

## 5. 自習導線

- [ ] READMEは公開トップの概要と入口に絞られ、ファイル単位の学習順序を重複掲載していない
- [ ] START_HEREが、学習順序、演習、自己点検、完了水準の唯一の詳細ナビになっている
- [ ] 必修順が「導入→第01〜07章→実務演習→第10章」で一致している
- [ ] 第08・09章が任意発展であることと、全編完了の条件が明確である
- [ ] 各章に前提、個人学習・組織利用・AIなしの3経路、使用ファイル、成果物、停止条件がある
- [ ] 各章末に自己点検と前後ナビがある
- [ ] `LEARNING_PROGRESS.md`に全章と8演習を個別に記録できる
- [ ] `TROUBLESHOOTING.md`が現在のフォルダーと学習導線に一致している

## 6. 演習の整合

- [ ] 8演習のそれぞれに、架空元資料、AIなし経路、記入用シート、対応する自己点検がある
- [ ] 完成プロンプトのコピー範囲が明確である
- [ ] 元資料との全件照合がある
- [ ] AIによる作り足し、抜け、誤りを発見できる
- [ ] 一か所以上を修正して再確認する
- [ ] 完了条件と停止条件が矛盾していない
- [ ] Word・Excel・AIを利用できない代替経路がある
- [ ] 外部送信、公開、本番書込みを演習中に行わない

## 7. 安全性と最新情報

- [ ] 実データを基本演習へ持ち込む例外がない
- [ ] 高影響判断をAIだけで確定しない
- [ ] 外部送信、公開、書込み、削除、支払、権限変更は実行前に人が承認する
- [ ] 事故時に秘密値・個人情報を再転記させない
- [ ] 少数ケースの誤り0件を将来の安全保証にしていない
- [ ] 法律、著作権、個人情報、医療、金融等の専門家確認を維持した
- [ ] 製品情報を公式ページで再確認し、URL、発行主体、版、確認日を記録した
- [ ] 変動する画面名、料金、機能を固定知識として断定していない

## 8. Markdownとデータ

- [ ] Windows PowerShell 5.1で`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate_content.ps1`が成功した
- [ ] PowerShell 7で`pwsh -NoProfile -File ./scripts/validate_content.ps1`が成功した
- [ ] GitHub Actionsの検査が成功した
- [ ] ローカル相対リンクがすべて存在する
- [ ] 見出しレベルが飛んでいない
- [ ] Markdown表の列数が一致している
- [ ] コードフェンスとdetailsタグが閉じている
- [ ] Mermaid図がGitHubで表示でき、直後に文章の「図の要点」がある
- [ ] CSV・TSVの文字コード、列数、行数を確認した
- [ ] `git diff --check`が成功した

## 9. Release

- [ ] `CHANGELOG.md`を更新した
- [ ] 既知の制約と法務確認ゲートの状態を確認した
- [ ] 教材版を決めた
- [ ] タグとGitHub Releaseを作成した
- [ ] Release notesへ変更点、既知の制約、教材内容の横断確認日を書いた
- [ ] `main`と安定版の違いをREADMEに表示した
